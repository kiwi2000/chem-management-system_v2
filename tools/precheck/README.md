# 事前チェック（precheck）

顧客環境の法規制データを更新する前に、**顧客が何を変えているか**と**次の更新でどう扱うか**を一覧にする道具。
顧客環境には書き込まない。社内で流して、人が読む。

## いつ使うか

法規制の改正・LOLI の版・CHRIP の版を顧客環境へ入れる前。段取りは次のとおり。

1. 顧客の写しを取る（顧客環境に繋いで `export.ts`。画面の書き出しができたらそちら）
2. 当方の正規データの写しを取る（その顧客に前回渡した内容と同じもの）
3. 次に渡す配布物の写しを取る（あれば）
4. `compare.ts` で突き合わせ、報告（Markdown）と全件（TSV）を出す
5. 要相談のものを顧客と決め、顧客向けの配布パッケージを作る
6. 顧客環境では、取り込みの下見で差異が無いことを確かめて取り込む

## 使いかた

```bash
# 写しを取る（DATABASE_URL の先から読む。顧客環境はトンネル越しの一時ファイルを --env-file に）
node --env-file=.env node_modules/tsx/dist/cli.mjs --tsconfig apps/web/tsconfig.json \
  tools/precheck/export.ts --out .cache/precheck/base.json --label "当方 正規 2026-09-11"
```

```bash
# 突き合わせる（データベースには繋がない）
node node_modules/tsx/dist/cli.mjs --tsconfig apps/web/tsconfig.json tools/precheck/compare.ts \
  --customer .cache/precheck/customer.json --base .cache/precheck/base.json \
  --next .cache/precheck/next.json --out .cache/precheck/report.md --tsv .cache/precheck/report.tsv
```

`--next` は省いてよい。省くと「配布物との関係」は見ない。

## 報告の読みかた

| 影響           | 中身                                                                                                                   | 既定の扱い                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 表示だけ       | 名称・備考・並び順・法律上の番号・結び付きの出典文                                                                     | 残す                                                     |
| 判定が変わる   | 閾値・合算・金属換算・閾値の対象・判定に使うか・適用開始日／終了日・適用条件・兼ね合い・スコア・結び付きの追加／非該当 | 残す（確認）。配布物とぶつかれば要相談                   |
| 突き合わせの鍵 | 行の削除、別の分類への付け替え、コードの付け替えの疑い（同じ名前で別コード）                                           | 要相談。消した行を配布物が持っていれば「取り込むと戻る」 |

- 突き合わせの鍵は**コード**（法律 → 区分 → 分類 → 法文物質名、結び付きは バージョン×データソース×CAS）。内部の id は環境ごとに違うので使わない
- 「配布物とぶつかる」は、配布物が同じ行の同じ項目を顧客と違う値で持っていること。配布物に無ければそのまま残る

## 直すときの決まり

- **法規制の表に項目を足したり変えたりしたら、ここも一緒に直す。** `lib/snapshot.ts` の写しの形と `takeSnapshot`、`lib/compare.ts` の項目の一覧（表示だけ / 判定が変わる）と `FIELD_LABELS`。知らない項目は安全側（判定が変わる）として扱われるが、報告の項目名が英語のままになる
- 画面からの「書き出し」「取り込み」を作るときは、`Snapshot` の形をそのまま使い、取り込みの下見は `compare` を使い回す
- 検証は `npm run test:tools`
