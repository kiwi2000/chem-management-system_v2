化学物質管理システム
社内サーバーへの導入

御社の社内サーバー1台にインストールし、社内LANから使えるようにするまでの手順です。 作業はサーバーの管理者権限を持つ方が行います。所要時間はおよそ1時間です。 外部のサービスには一切接続しません。 0〜9 は Linux（推奨）の手順です。Windows Server に入れる場合は 10 に読み替えてください（アプリのプログラムは同じものです）。

対象 社内サーバー 1台 作業者 サーバー管理者 所要 約1時間 版 2026-09-01

0. 導入前の確認

ご用意いただくもの
もの要件
サーバー4コア / メモリ8GB / SSD 250GB 以上（推奨は8コア・16GB・NVMe 500GB）。物理でも仮想でも構いません
OSUbuntu Server 24.04 LTS、または RHEL系 9（AlmaLinux / Rocky Linux）

電源無停電電源装置（UPS）。停電でデータベースが壊れることを防ぎます
バックアップ先サーバーとは別の機器（社内NASなど）

chem-images-(ver).tar約 1.5 GB実行に使う Docker イメージ。サーバーがインターネットに繋がらない場合のみお渡しします

1. システムの構成

サーバー1台の中で、3つの入れ物（コンテナ）が役割を分けて動きます。 入れ物は Docker が管理し、社内LANに開いているのは入口のひとつだけです。

それぞれの役目
入れ物役目社内LANから
caddy 社内LANからの接続を受け、暗号化（HTTPS）して app へ渡します 見えます（443 / 80）
app 画面の表示と法規制の判定。データが要るときは db に聞きます 見えません
db 物質・製品・法規制・操作記録の保管。PostgreSQL 16 見えません

POINT

  • 外から届くのは caddy だけです。app と db はサーバーの中でしか繋がらず、社内LANからも直接は触れません
  • データは入れ物の外（db-data）に置いてあります。アプリを新しくして入れ物を作り直しても、中身は消えません
  • インターネットへの通信はありません。認証も自前で持っているため、外部のサービスを使いません

2. サーバーの準備

1

サーバーの用意OSのインストールまでは済ませておいてください

この手順書は、次の状態から始めます。 サーバー本体の調達とOSのインストールの方法は、この手順書では扱いません。

始めるときの状態
項目そろえておくこと
OS Ubuntu Server 24.04 LTS（最小構成で構いません）、または RHEL系 9。デスクトップ環境は要りません
ネットワーク 社内LANの固定IPアドレスが付いていること。DHCPで変わると、社員のパソコンから開けなくなります
接続 SSHで入れること。鍵での接続にし、パスワードでの接続は止めておくことをおすすめします
時刻 時刻が合っていること（timedatectl で確認）。操作記録の時刻とバックアップの時間に影響します

作業に使うユーザー

ユーザー役目
導入作業をする人
1つ。例 chemadmin		 sudo が使える一般ユーザーを1つ用意します。 このユーザーでログインして、以降の作業をすべて行います。 手順3で docker グループにも入れます
root 直接ログインしては使いません。必要なときだけ sudo を通します。 誤った操作でOSごと壊すことを防ぐためです
システムの中で使われるもの アプリとデータベースは Docker の中で動き、OSのユーザーは作りません。 システムを使う人（社員）のアカウントは、OSではなくアプリの中で管理します

ディレクトリの構成

導入したあと、サーバーの中はこうなります
場所中身消えると
/opt/chem/ アプリ一式。展開したファイルと起動用の設定が入ります お渡ししたファイルから戻せます
/opt/chem/.env.prod データベースのパスワードを書く設定ファイル。このファイルだけは外に出さないでください 戻せません。控えを別に保管してください
/opt/chem/scripts/ バックアップなどの補助スクリプト お渡ししたファイルから戻せます
/var/lib/docker/volumes/ データベースの中身（db-data）。Docker が管理します。直接さわらないでください バックアップから戻します
/var/backups/chem/ 毎日のバックアップ。14日より古いものは自動で消えます 社内NASの複製から戻します
/var/log/chem-backup.log バックアップが動いた記録 差し支えありません

IMPORTANT

守るべきものは2つだけです。 /opt/chem/.env.prod（設定）と、データベースの中身（毎日のバックアップ）。 この2つがあれば、サーバーが壊れても新しい機械で同じ状態に戻せます。

2

OSの更新Ubuntu Server 24.04 の例

# パッケージを最新にし、セキュリティ更新を自動で当てる設定にします
sudo apt update && sudo apt -y upgrade
sudo apt -y install unattended-upgrades

RHEL系の場合は sudo dnf -y update と sudo dnf -y install dnf-automatic です。

3

Docker の導入アプリとデータベースはこの上で動きます

# インターネットに繋がる場合
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# ここで一度ログインし直します（グループの変更を反映するため）

OFFLINE

インターネットに繋がらないサーバーでは、OSの提供元から docker-ce のパッケージを別途入手して導入してください。 Ubuntu なら docker.io パッケージ（OSの標準リポジトリ）でも動きます。 

# 入ったことの確認。バージョンが2つとも表示されればOK
docker --version
docker compose version
4

通信の入口の制限社内LANからだけ入れるようにします

# 社内LANが 192.168.10.0/24 の場合の例。自社の範囲に読み替えてください
sudo ufw allow from 192.168.10.0/24 to any port 443 proto tcp
sudo ufw allow from 192.168.10.0/24 to any port 80 proto tcp
sudo ufw allow 22/tcp
sudo ufw enable

CAUTION

インターネットに向けて 80 / 443 を開けないでください。 このシステムは社内LANの中だけで使う前提で作ってあります。 外部から使う必要がある場合は、VPN経由にしてください。

3. アプリの配置と起動

5

ファイルの展開

sudo mkdir -p /opt/chem && sudo chown $USER /opt/chem
tar xzf chem-system-(ver).tar.gz -C /opt/chem
cd /opt/chem
6

設定ファイルの作成データベースのパスワードを決めます

cp .env.prod.example .env.prod
openssl rand -base64 24        # 出てきた文字列を控えます
nano .env.prod                 # DB_PASSWORD= の右側に貼り付けます

IMPORTANT

DB_PASSWORD は必ず変更してください。 この値は最初の起動でデータベースに焼き付きます。あとから変えるには データベースを作り直すことになります。

7

起動初回は10〜20分かかります

# インターネットに繋がる場合（その場でイメージを組み立てます）
docker compose -f compose.prod.yml --env-file .env.prod up -d --build

OFFLINE

お渡しした Docker イメージのファイルから読み込みます。

docker load -i chem-images-(ver).tar
docker compose -f compose.prod.yml --env-file .env.prod up -d
# 3つとも running になっていれば起動しています
docker compose -f compose.prod.yml --env-file .env.prod ps

CHECK

db / app / caddy の3つが running と表示されること。

4. 最初の管理者の作成

8

最初の管理者の作成

docker compose -f compose.prod.yml --env-file .env.prod exec app \
  npx tsx scripts/set-password.ts admin@example.co.jp 'ここに強いパスワード' --create

メールアドレスは御社のものに読み替えてください。 この1人だけコマンドで作ります。2人目からは管理画面から追加できます。

CAUTION

コマンドに書いたパスワードは端末の履歴に残ります。実行後に history -c で消してください。 このパスワードは初回ログイン時に変更を求められます。

5. 社内パソコンからの接続

9

ブラウザからの接続

社内のパソコンから https://サーバーのIPアドレス/ を開きます。 ログイン画面が出れば、ここまでは成功です。

証明書の警告について

初回は「この接続ではプライバシーが保護されません」という警告が出ます。 社内専用のため、システムが自分で作った証明書を使っているためです。通信は暗号化されています。 警告を消すには、次の手順でサーバーの証明書を各パソコンに登録してください。 

# サーバーで実行して、証明書のファイルを取り出します
docker compose -f compose.prod.yml --env-file .env.prod exec caddy \
  cat /data/caddy/pki/authorities/local/root.crt > chem-root.crt

取り出した chem-root.crt を各パソコンに配り、 Windows では「信頼されたルート証明機関」に取り込みます。 台数が多い場合はグループポリシーで配布できます。

社内のドメイン名を使う場合

社内DNSに chem.社内ドメイン のような名前を登録しておくと、 IPアドレスではなく名前で開けます。設定ファイル deploy/Caddyfile の 先頭にあるコメントに、書き換え方を記載しています。

6. 毎日のバックアップの設定

10

自動バックアップの設定これは必ず設定してください

chmod +x /opt/chem/scripts/backup-db.sh
crontab -e

開いたファイルの最後に、次の1行を足して保存します（毎日 深夜3時）。

0 3 * * * /opt/chem/scripts/backup-db.sh >> /var/log/chem-backup.log 2>&1

/var/backups/chem/ に、圧縮したファイルが1日1つ増えます。 14日より古いものは自動で消えます。

IMPORTANT

サーバーとは別の機器へ複製してください。同じサーバーの中だけに置いていると、 サーバーが壊れたときにデータも一緒に失われます。 社内NASへ毎日コピーする設定を、あわせてお願いします。

CHECK

その場で1回動かして、ファイルができることを確かめます。

/opt/chem/scripts/backup-db.sh
ls -lh /var/backups/chem/

7. 導入完了の確認

次のすべてができていれば、導入は完了です。

  • docker compose ... ps で3つとも running になっている
  • 社内のパソコンから https://サーバーのIP/ でログインできる
  • バックアップのファイルが /var/backups/chem/ にできている
  • サーバーを再起動しても、自動でアプリが立ち上がる（sudo reboot で確認）

8. 導入後の運用

定期的にお願いすること
いつすることやりかた
毎日バックアップの確認 前日のファイルができているか。cronが動いていれば自動です
毎月ディスクの空きを見る df -h。使用率80%を超えたらご連絡ください
年1回操作記録の整理 管理画面の「操作記録」から古い分を削除します。自動では消えません

アプリの更新

cd /opt/chem
# 念のため、先にバックアップを取ります
./scripts/backup-db.sh
# 新しいファイルを展開してから
docker compose -f compose.prod.yml --env-file .env.prod up -d --build

データベースの構造が変わる場合も、起動時に自動で適用されます。 作業中は1〜3分ほどアプリが止まります。

バックアップからの復元

gunzip -c /var/backups/chem/chem_日付.sql.gz | \
  docker compose -f compose.prod.yml --env-file .env.prod exec -T db \
  psql -U chem chem

9. うまくいかないとき

症状見るところ
ブラウザで開けない サーバーで docker compose ... ps。3つとも running か。次にファイアウォール（sudo ufw status）で、そのパソコンのIPが許可されているか
「データベースに接続できません」と出る docker compose ... logs db。.env.prod の DB_PASSWORD を後から変えていないか
ログインできない 5回続けて間違えると一時的にロックされます。15分待つか、手順8のコマンドでパスワードを出し直してください
動きが遅い free -h でメモリの空き、df -h でディスクの空きを確認してください
アプリの記録を見たい docker compose -f compose.prod.yml --env-file .env.prod logs -f app

SUPPORT

解決しない場合は、実行したコマンドと、画面に出たメッセージをそのままお送りください。 docker compose -f compose.prod.yml --env-file .env.prod logs --tail 200 app の出力もあわせていただけると、原因を絞り込めます。

10. Windows Server への導入 Linux の代わりに

ここまでは Linux での手順です。Windows Server に入れる場合は、この節に読み替えてください。 アプリのプログラムは1行も変わりません。変わるのは、入れ物（Docker）の代わりに 3つを Windows のサービスとして常駐させるところです。

IMPORTANT

仮想化（Hyper-V・WSL2・Docker）は使いません。 Windows Server 2019 / 2022 / 2025 のいずれかで、管理者権限が要ります。 この構成は Linux 版ほどの運用実績がありません。 どちらでもよい場合は Linux 版をお勧めします。

Linux 版との対応
役目Linux 版Windows Server 版
データベース db コンテナ PostgreSQL 16 を直接インストール（サービスとして常駐）
アプリ app コンテナ Node.js で直接動かし、nssm でサービス登録
入口（HTTPS） caddy コンテナ Caddy の Windows 版をサービス登録
自動起動・再起動 Docker が受け持つ Windows のサービスが受け持つ
バックアップ backup-db.sh（cron） backup-db.ps1（タスクスケジューラ）
W1

必要なソフトの導入いずれも公式のインストーラーがあります

ソフト版入れ方
Node.js22 LTS（20以上）公式の MSI。PATH に通すにチェック
PostgreSQL16公式インストーラー。文字コードは UTF-8。ポートは 5432 のまま
Caddy2 系公式サイトの Windows 版（caddy.exe 1本）を C:\chem\caddy\ に置く
NSSM2.24 以降アプリと Caddy をサービスにするための道具。nssm.exe 1本

CAUTION

PostgreSQL のインストール時に決める postgres のパスワードは控えておいてください。 このあと業務用のユーザーを作るのに使います。

W2

データベースの作成

# PowerShell を管理者で開いて実行します
$bin = "C:\Program Files\PostgreSQL\16\bin"
$env:PGPASSWORD = "<インストール時に決めた postgres のパスワード>"

# 業務用のユーザーとデータベースを作ります
& "$bin\psql.exe" -h 127.0.0.1 -U postgres -c "CREATE USER chem WITH PASSWORD '<強いパスワード>';"
& "$bin\psql.exe" -h 127.0.0.1 -U postgres -c "CREATE DATABASE chem OWNER chem ENCODING 'UTF8';"

IMPORTANT

ホストは 127.0.0.1 と書いてください。 localhost と書くと IPv6 側に解決されて繋がらないことがあります。

W3

ファイルの配置と設定

# お渡ししたファイルを C:\chem に展開します
Expand-Archive -Path chem-system-(ver).zip -DestinationPath C:\chem
cd C:\chem

C:\chem\.env を作り、次の1行を書きます（このファイルは外に出さないでください）。 

DATABASE_URL="postgresql://chem:<W2で決めたパスワード>@127.0.0.1:5432/chem?schema=public"
W4

組み立て10〜20分かかります

cd C:\chem
npm ci
npx prisma generate
npm run build
npx prisma migrate deploy   # データベースの表を作ります

CHECK

npx prisma migrate deploy が All migrations have been successfully applied. で終わること。

W5

最初の管理者の作成

cd C:\chem
npx tsx scripts/set-password.ts admin@example.co.jp '<強いパスワード>' --create

Linux 版の手順8と同じです。この1人だけコマンドで作ります。 実行後、Clear-History で履歴を消してください。

W6

サービスへの登録電源を入れると自動で立ち上がるようにします

# アプリ本体
nssm install chem-app "C:\Program Files\nodejs\npm.cmd" "run start -w apps/web"
nssm set chem-app AppDirectory C:\chem
nssm set chem-app Start SERVICE_AUTO_START
nssm set chem-app AppEnvironmentExtra NODE_ENV=production

# 入口（HTTPS）
nssm install chem-caddy C:\chem\caddy\caddy.exe "run --config C:\chem\deploy\Caddyfile"
nssm set chem-caddy Start SERVICE_AUTO_START

nssm start chem-app
nssm start chem-caddy

CHECK

Get-Service chem-app, chem-caddy, postgresql-x64-16 |
  Select-Object Name, Status, StartType

3つとも Running / Automatic になっていること。

HTTPS は必須です

ログインの記録はHTTPS のときだけ保たれる作りになっています。 http:// のまま使うと、ログインしても画面を移るたびに切れます。 Caddy を必ず通してください（証明書の扱いは Linux 版の手順9と同じです）。

W7

通信の入口の制限

# 社内LANが 192.168.10.0/24 の場合の例
New-NetFirewallRule -DisplayName "chem HTTPS" -Direction Inbound -Protocol TCP `
  -LocalPort 443 -RemoteAddress 192.168.10.0/24 -Action Allow

# データベースは外に出しません（既定で閉じていますが、念のため確認）
Get-NetFirewallRule -Direction Inbound |
  Where-Object { $_.Enabled -eq 'True' } |
  Get-NetFirewallPortFilter | Where-Object { $_.LocalPort -eq 5432 }
W8

毎日のバックアップの設定

# 毎日3時。パスワードは .env から読むので、ここには書きません
schtasks /Create /TN "chem-backup" /SC DAILY /ST 03:00 /RU SYSTEM `
  /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\chem\scripts\backup-db.ps1"

CHECK

その場で1回動かして、ファイルができることを確かめます。

powershell -NoProfile -ExecutionPolicy Bypass -File C:\chem\scripts\backup-db.ps1
Get-ChildItem C:\backups\chem

IMPORTANT

サーバーとは別の機器へ複製してください。 backup-db.ps1 の末尾に、社内NASへコピーする例をコメントで書いてあります。

Windows Server ならではの注意

項目すること
Windows Update 再起動の時間帯を業務時間の外に設定してください。サービスは自動起動なので、再起動しても復帰します
ウイルス対策 C:\chem と PostgreSQL のデータ領域をリアルタイム検査の対象外にすることを検討してください。 データベースの書き込みが遅くなることがあります
文字コード データベースは UTF-8 で作ってください。既定のままだと日本語が化けます
アプリの記録 nssm set chem-app AppStdout C:\chem\logs\app.log のように出力先を決めておくと、 困ったときに追えます

更新のしかた

cd C:\chem
powershell -File scripts\backup-db.ps1   # 先にバックアップ
nssm stop chem-app
# 新しいファイルを展開してから
npm ci
npx prisma generate
npm run build
npx prisma migrate deploy
nssm start chem-app

組み立ての最中はアプリを止めてください。動かしたまま作り直すと、 作りかけのファイルを読んで動かなくなることがあります。
