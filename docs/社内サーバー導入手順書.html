社内サーバーへの導入

御社の社内サーバー1台にインストールし、社内LANから使えるようにするまでの手順です。 作業はサーバーの管理者権限を持つ方が行います。所要時間はおよそ1時間です。 外部のサービスには一切接続しません。 0〜9 は Linux（推奨）の手順です。Windows Server に入れる場合は 10 に読み替えてください（アプリのプログラムは同じものです）。

対象 社内サーバー 1台 作業者 サーバー管理者 所要 約1時間 版 2026-09-15

1. システムの構成

サーバー1台の中で、3つの入れ物（コンテナ）が役割を分けて動きます。 入れ物は Docker が管理し、社内LANに開いているのは入口のひとつだけです。

それぞれの役目
入れ物役目社内LANから
caddy 社内LANからの接続を受け、暗号化（HTTPS）して app へ渡します 見えます（443 / 80）
app 画面の表示と法規制の判定。データが要るときは db に聞きます 見えません
db 物質・製品・法規制・操作記録の保管。PostgreSQL 16 見えません

POINT

  • 外から届くのは caddy だけです。app と db はサーバーの中でしか繋がらず、社内LANからも直接は触れません
  • データは入れ物の外（db-data）に置いてあります。アプリを新しくして入れ物を作り直しても、中身は消えません
  • インターネットへの通信はありません。認証も自前で持っているため、外部のサービスを使いません

1

サーバーの用意OSのインストールまでは済ませておいてください

この手順書は、次の状態から始めます。 サーバー本体の調達とOSのインストールの方法は、この手順書では扱いません。

始めるときの状態
項目そろえておくこと

時刻 時刻が合っていること（timedatectl で確認）。操作記録の時刻とバックアップの時間に影響します

導入作業をする人

ディレクトリの構成

導入したあと、サーバーの中はこうなります
場所中身消えると
/opt/chem/ アプリ一式。展開したファイルと起動用の設定が入ります お渡ししたファイルから戻せます
/opt/chem/.env.prod データベースのパスワードを書く設定ファイル。このファイルだけは外に出さないでください 戻せません。控えを別に保管してください
/opt/chem/scripts/ バックアップなどの補助スクリプト お渡ししたファイルから戻せます
/var/lib/docker/volumes/ データベースの中身（db-data）。Docker が管理します。直接さわらないでください バックアップから戻します
/var/backups/chem/ 毎日のバックアップ。14日より古いものは自動で消えます 社内NASの複製から戻します
/var/log/chem-backup.log バックアップが動いた記録 差し支えありません

IMPORTANT

守るべきものは2つだけです。 /opt/chem/.env.prod（設定）と、データベースの中身（毎日のバックアップ）。 この2つがあれば、サーバーが壊れても新しい機械で同じ状態に戻せます。

2

OSの更新Ubuntu Server 24.04 の例

# パッケージを最新にし、セキュリティ更新を自動で当てる設定にします
sudo apt update && sudo apt -y upgrade
sudo apt -y install unattended-upgrades

RHEL系の場合は sudo dnf -y update と sudo dnf -y install dnf-automatic です。

3

Docker の導入アプリとデータベースはこの上で動きます

# インターネットに繋がる場合
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# ここで一度ログインし直します（グループの変更を反映するため）

OFFLINE

インターネットに繋がらないサーバーでは、OSの提供元から docker-ce のパッケージを別途入手して導入してください。 Ubuntu なら docker.io パッケージ（OSの標準リポジトリ）でも動きます。 

# 入ったことの確認。バージョンが2つとも表示されればOK
docker --version
docker compose version
4

通信の入口の制限社内LANからだけ入れるようにします

# 社内LANが 192.168.10.0/24 の場合の例。自社の範囲に読み替えてください
sudo ufw allow from 192.168.10.0/24 to any port 443 proto tcp
sudo ufw allow from 192.168.10.0/24 to any port 80 proto tcp
sudo ufw allow 22/tcp
sudo ufw enable

CAUTION

インターネットに向けて 80 / 443 を開けないでください。 このシステムは社内LANの中だけで使う前提で作ってあります。 外部から使う必要がある場合は、VPN経由にしてください。

アプリの側でも制限できます（任意）

手順6で作る .env.prod の ALLOWED_IPS に許可する範囲を書くと、 アプリ自身も決まった場所からの接続だけを受け付けます。空のままなら制限しません。 IP_FILTER_MODE は、まず monitor（記録するだけ）で様子を見て、 問題が無ければ enforce（許可外を断る）に切り替えます。 締め出されたときは ALLOWED_IPS を空に戻して起動し直します。

3. アプリの配置と起動

5

ファイルの展開

sudo mkdir -p /opt/chem && sudo chown $USER /opt/chem
tar xzf chem-system-(ver).tar.gz -C /opt/chem
cd /opt/chem
6

設定ファイルの作成データベースのパスワードを決めます

cp .env.prod.example .env.prod
openssl rand -base64 24        # 出てきた文字列を控えます
nano .env.prod                 # DB_PASSWORD= の右側に貼り付けます

IMPORTANT

DB_PASSWORD は必ず変更してください。 この値は最初の起動でデータベースに焼き付きます。あとから変えるには データベースを作り直すことになります。

7

起動初回は10〜20分かかります

# インターネットに繋がる場合（その場でイメージを組み立てます）
docker compose -f compose.prod.yml --env-file .env.prod up -d --build

OFFLINE

お渡しした Docker イメージのファイルから読み込みます。

docker load -i chem-images-(ver).tar
docker compose -f compose.prod.yml --env-file .env.prod up -d
# 3つとも running になっていれば起動しています
docker compose -f compose.prod.yml --env-file .env.prod ps

CHECK

db / app / caddy の3つが running と表示されること。

4. 最初の管理者の作成

8

最初の管理者の作成

docker compose -f compose.prod.yml --env-file .env.prod exec app \
  npx tsx scripts/set-password.ts admin@example.co.jp 'ここに強いパスワード' --create

メールアドレスは御社のものに読み替えてください。 この1人だけコマンドで作ります。2人目からは管理画面から追加できます。

CAUTION

コマンドに書いたパスワードは端末の履歴に残ります。実行後に history -c で消してください。 このパスワードはログイン後に、画面右上のメニューの「パスワードを変更する」から 本人が変えられます（変更を求める仕組みは働きません）。

5. 社内パソコンからの接続

9

ブラウザからの接続

社内のパソコンから https://サーバーのIPアドレス/ を開きます。 ログイン画面が出れば、ここまでは成功です。

証明書の警告について

初回は「この接続ではプライバシーが保護されません」という警告が出ます。 社内専用のため、システムが自分で作った証明書を使っているためです。通信は暗号化されています。 警告を消すには、次の手順でサーバーの証明書を各パソコンに登録してください。 

# サーバーで実行して、証明書のファイルを取り出します
docker compose -f compose.prod.yml --env-file .env.prod exec caddy \
  cat /data/caddy/pki/authorities/local/root.crt > chem-root.crt

取り出した chem-root.crt を各パソコンに配り、 Windows では「信頼されたルート証明機関」に取り込みます。 台数が多い場合はグループポリシーで配布できます。

社内のドメイン名を使う場合

社内DNSに chem.社内ドメイン のような名前を登録しておくと、 IPアドレスではなく名前で開けます。設定ファイル deploy/Caddyfile の 先頭にあるコメントに、書き換え方を記載しています。 パスキー（指紋や顔などでのログイン）を使う予定があるなら、名前で開く必要があります。 パスキーの仕組み上、IPアドレスでは登録できません。

6. 毎日のバックアップの設定

10

自動バックアップの設定これは必ず設定してください

chmod +x /opt/chem/scripts/backup-db.sh
crontab -e

開いたファイルの最後に、次の1行を足して保存します（毎日 深夜3時）。

0 3 * * * /opt/chem/scripts/backup-db.sh >> /var/log/chem-backup.log 2>&1

/var/backups/chem/ に、圧縮したファイルが1日1つ増えます。 14日より古いものは自動で消えます。

IMPORTANT

サーバーとは別の機器へ複製してください。同じサーバーの中だけに置いていると、 サーバーが壊れたときにデータも一緒に失われます。 社内NASへ毎日コピーする設定を、あわせてお願いします。

CHECK

その場で1回動かして、ファイルができることを確かめます。

/opt/chem/scripts/backup-db.sh
ls -lh /var/backups/chem/

7. 導入完了の確認

次のすべてができていれば、導入は完了です。

  • docker compose ... ps で3つとも running になっている
  • 社内のパソコンから https://サーバーのIP/ でログインできる
  • バックアップのファイルが /var/backups/chem/ にできている
  • サーバーを再起動しても、自動でアプリが立ち上がる（sudo reboot で確認）

法規制のデータ（法律・規制区分・法文物質名・CAS番号の結び付き）は、この手順では入りません。 物質や製品のデータも空の状態です。法規制のデータは導入のときにこちらが投入します。 投入が済むまで、判定は動きません。

いつすることやりかた

アプリの更新

cd /opt/chem
# 念のため、先にバックアップを取ります
./scripts/backup-db.sh
# 新しいファイルを展開してから

データベースの構造が変わる場合も、起動時に自動で適用されます。 作業中は1〜3分ほどアプリが止まります。

バックアップからの復元

復元は、データベースの中身をバックアップを取った時点の内容に置き換えます。 それ以降に入れたものは消えます。先にアプリを止めてから行ってください。 

cd /opt/chem
docker compose -f compose.prod.yml --env-file .env.prod stop app
gunzip -c /var/backups/chem/chem_日付.sql.gz | \
  docker compose -f compose.prod.yml --env-file .env.prod exec -T db \
  psql -U chem chem
docker compose -f compose.prod.yml --env-file .env.prod start app

9. うまくいかないとき

症状見るところ
ブラウザで開けない サーバーで docker compose ... ps。3つとも running か。次にファイアウォール（sudo ufw status）で、そのパソコンのIPが許可されているか
「データベースに接続できません」と出る docker compose ... logs db。.env.prod の DB_PASSWORD を後から変えていないか
ログインできない 5回続けて間違えると一時的にロックされます。15分待つか、手順8のコマンドでパスワードを出し直してください
動きが遅い free -h でメモリの空き、df -h でディスクの空きを確認してください
アプリの記録を見たい docker compose -f compose.prod.yml --env-file .env.prod logs -f app

SUPPORT

解決しない場合は、実行したコマンドと、画面に出たメッセージをそのままお送りください。 docker compose -f compose.prod.yml --env-file .env.prod logs --tail 200 app の出力もあわせていただけると、原因を絞り込めます。

10. Windows Server への導入 Linux の代わりに

ここまでは Linux での手順です。Windows Server に入れる場合は、この節に読み替えてください。 アプリのプログラムは1行も変わりません。変わるのは、入れ物（Docker）の代わりに 3つを Windows のサービスとして常駐させるところです。 Windows Server 用はインストールセット（組み立て済みのアプリと、必要なソフトの インストーラーを1つにまとめたもの）でお渡しします。サーバーがインターネットに繋がっていなくても導入できます。

IMPORTANT

仮想化（Hyper-V・WSL2・Docker）は使いません。 Windows Server 2019 / 2022 / 2025 のいずれかで、管理者権限が要ります。 この構成は Linux 版ほどの運用実績がありません。 どちらでもよい場合は Linux 版をお勧めします。

W1

セットの展開C:\chem-install に置きます

お渡しした zip をサーバーにコピーし、管理者の PowerShell で展開します。 ファイルが多いので、Windows に入っている tar で展開します（Expand-Archive は 10 分近くかかります）。 

tar -xf C:\chem-install-set-(ver)-win64.zip -C C:\
Rename-Item C:\chem-install-set-(ver)-win64 C:\chem-install

CHECK

C:\chem-install の下に README.txt・手順書.html・app・installers・scripts があること。

W2

導入の実行10〜15分かかります

管理者の PowerShell で次を実行します。社内LANのアドレス範囲と、 最初の管理者（画面にログインする方）のメールアドレスを自分のものに変えてください。 

powershell -ExecutionPolicy Bypass -File C:\chem-install\scripts\install.ps1 `
  -LanCidr 192.168.10.0/24 -AdminEmail admin@example.co.jp

途中で3つのパスワードを聞かれます。打った文字は画面に出ず、どこにも記録されません。

聞かれるもの何のパスワードか控え
postgresデータベースの管理ユーザー。復元などの保守で使います必ず控える
chemアプリがデータベースに繋ぐためのもの。C:\chem\.env に書き込まれます控える（.env にも残ります）
最初の管理者画面にログインするためのもの。ログイン後に画面から変えられます本人に渡す

CAUTION

パスワードは 12文字以上で、@ / ' を含めないでください （設定ファイルの読み取りが崩れます）。

スクリプトは次の順に進みます。画面には W1〜W8 の見出しで出ます。

見出しすること
W1 前提ソフトNode.js 22・PostgreSQL 16（ポート 5432、pgAdmin は入れません）・Caddy・NSSM を入れます。入っているものは飛ばします
W2 データベース業務用のユーザー chem とデータベース chem を UTF-8 で作ります
W3 アプリの配置app\ を C:\chem に写し、C:\chem\.env を作ります
W4 データベースの表表を作ります（prisma migrate deploy）
W5 最初の管理者指定したメールアドレスで、全権限の利用者を1人作ります
W6 サービスchem-app と chem-caddy を登録し、起動します（自動起動・落ちたら再起動）
W7 通信の入口指定したLANからの 443（HTTPS）と 80（HTTPS へ転送）だけを開けます。データベースは開けません
W8 バックアップ毎日3時に C:\backups\chem へ取るタスクを登録し、その場で1回取ります

CHECK

最後の「状態」で、chem-app・chem-caddy・postgresql-x64-16 が Running / Automatic、https://127.0.0.1/api/health が 200 と {"ok":true,"db":"up"} であること。

途中で止まったら、表示された原因を直してから同じコマンドをもう一度実行してください。 済んだところは飛ばします。

W3

社内パソコンからの接続名前と証明書

サーバーには名前で開くようにしてください（例 chem.example.local）。 社内の DNS に登録するか、各パソコンの C:\Windows\System32\drivers\etc\hosts に 192.168.10.5 chem.example.local のように1行足します。 パスキー（指紋や顔でのログイン）は、IPアドレスでは登録できません。

証明書はサーバーの中で作られます（社内用の認証局）。最初は「この接続は安全ではありません」と出ますが、 サーバーの C:\ProgramData\caddy\pki\authorities\local\root.crt を各パソコンの 「信頼されたルート証明機関」に入れると消えます（Linux 版の手順9と同じです）。 

certutil -addstore Root root.crt      # 各パソコンで管理者として

パスキーを使うなら、証明書の登録は必須です

ブラウザは、証明書の警告が出ているページではパスキーの登録・ログインを一切受け付けません （画面には「登録をやめました」と出ます）。上の登録を済ませ、ブラウザをすべて閉じて開き直してから アドレスバーに警告が無いことを確かめてください。パスワードでのログインは、警告があっても使えます。

HTTPS は必須です

ログインの記録はHTTPS のときだけ保たれる作りになっています。 http:// や :3001 で直接開かず、必ず https://名前/ で開いてください。

CHECK

社内パソコンで https://名前/ を開き、W2 で決めた管理者でログインできること。ログイン後、右上の「ユーザーマニュアル」が開くこと。

W4

状態の確認いつでも使えます

powershell -ExecutionPolicy Bypass -File C:\chem\deploy\windows\check.ps1

サービスの状態、アプリの応答、記録の末尾、空き容量をまとめて出します。 困ったときは、この出力をそのままお送りください。

Windows Server ならではの注意

項目すること
Windows Update 再起動の時間帯を業務時間の外に設定してください。サービスは自動起動なので、再起動しても復帰します
ウイルス対策 C:\chem と PostgreSQL のデータ領域をリアルタイム検査の対象外にすることを検討してください。 データベースの書き込みが遅くなることがあります
守るべきもの C:\chem\.env（設定）と、データベースの中身（毎日のバックアップ C:\backups\chem）。 バックアップは別の機器へ複製してください（scripts\backup-db.ps1 の末尾に社内NASへコピーする例）
アプリの記録 C:\chem\logs\chem-app.log（10MB で切り替わります）。困ったときに追えます

更新のしかた

新しい版も同じ形のセットでお渡しします。W1 と同じように展開し（前のフォルダは消して構いません）、 管理者の PowerShell で次を実行します。5分ほどで終わります。 

powershell -ExecutionPolicy Bypass -File C:\chem-install\scripts\update.ps1

スクリプトは、いま入っている版と届いた版を比べてデータベースの表が変わるかどうかを先に表示し、 バックアップを取り、アプリを止め、ファイルを入れ替え、表に足りない変更があれば足し、アプリを起動して状態を出します。 設定（.env）・記録・バックアップは残ります。

うまくいかなかったときは、前の版のセットで同じ手順を行えば元の版に戻ります。 データベースを戻す必要があるときは、更新の直前に取ったバックアップから復元します（scripts\backup-db.ps1 の頭にやり方）。 何を新しくするかで手順が違います。場合ごとの手順は 11 を見てください（法規制データだけの更新は画面から取り込みます）。

11. 更新の手順 場合ごと

導入したあとに何かを新しくするときの手順です。何を新しくするかで手順が違います。 お渡しする「更新のご案内」に、どの場合に当たるかを書いてあります。案内が無いときは、届いたファイルの名前で見分けてください。

4 つの場合

11-2 プログラムの更新（表が変わる）同上。案内に「データベースの表が変わります」と書いてあります同上＋表の変更に 1 分ほど案内に書いてあるときだけ
11-3 データソースの更新（LOLI・CHRIP の新しい版）データセット（chem-data-set-(日付).zip）止まりません必ず押す
11-4 法規制の変更（法律の改正）データセット、または規制リスト（.tsv）止まりません必ず押す

11-1 プログラムの更新（データベースの表は変わらない）不具合の修正・小さな機能追加

いま入っている記録（製品・判定結果・利用者）はそのまま残ります。判定結果も変わりません。

手順LinuxWindows Server
1 バックアップ./scripts/backup-db.sh（update.ps1 が取ります）
2 ファイルを置くcd /opt/chem && tar -xzf ~/chem-system-(ver).tar.gz --strip-components=1tar -xf C:\chem-install-set-(ver)-win64.zip -C C:\ のあと、できたフォルダを C:\chem-install に改名（前のフォルダは消して構いません）

戻すとき

前の版のセットで 2〜3 を行えば元の版に戻ります。データベースは触っていないので、そのままで大丈夫です。

11-2 プログラムの更新（データベースの表が変わる）案内に「表が変わります」とあるとき

手順は 11-1 と同じです。違うのは次の 3 点だけです。

  • バックアップを必ず取ってから始めます（Windows は update.ps1 が最初に取り、失敗したら止まります）。
  • 表の変更は自動で当たります。Linux は起動のときに、Windows は update.ps1 の途中（「W4 データベースの表」）で行われ、画面に「データベースの表が変わります」と出ます。
  • いま入っている記録・判定結果は残ります。案内に「判定し直してください」とあるときだけ、判定し直しを押してください（判定の決まりが変わった版です）。

戻すとき

表が変わったあとは、前の版のプログラムをそのまま戻しても動きません。 前の版のセットで入れ替えたあと、1 で取ったバックアップからデータベースを復元してください （手順 8「バックアップからの復元」／ Windows は C:\chem\scripts\backup-db.ps1 の頭にやり方）。 復元すると、更新のあとに入れた記録は消えます。

11-3 データソースの更新LOLI・CHRIP の新しい版（四半期ごと）

プログラムは変えません。届いたデータセットを画面から取り込みます。作業中もアプリは止まりません。 詳しい画面の説明はユーザーマニュアルの「データを出し入れする」にあります。

手順すること確かめること
1バックアップを取る（上の「共通のこと」）ファイルができたこと
2左メニュー データ入出力 › インポート で chem-data-set-(日付).zip を選び「アップロード」種類が「データセット（法規制）」と出ること。違うものと出たら「破棄」して、ファイルを確かめる
3「インポート」を押す（数分〜十数分。裏で読み、終わると表が出ます）件数の表で「バージョン」に追加 1、「結び付き（CAS）」に追加が多数。「読めない」が 0 であること
4「要確認」の行があれば見る（御社が画面で直した法文物質名や結び付きです。届いた値にしたい行だけ「反映する」に印を付ける）印を付けていない「要確認」は、いまの値のまま残ります
5「反映」を押す状態が「反映済」、「失敗 0 件」
6左メニュー 法規制 › バージョン で新しい版（例 2026Q4）を選び「現在のバージョンにする」上の帯の「法規制バージョン」が新しい版になること
7システム設定 › 法規制の判定 › 「全製品を判定し直す」左メニューの「要再計算」が消えること

判定結果はどうなるか

  • 判定結果は版ごとに保存されます。前の版の結果は消えず、製品の画面で版を切り替えて見比べられます。
  • 「確認済」「上書き」など人が付けた判断は、当たった法文物質名と CAS の組が前と同じなら新しい版にも引き継がれます。組が変わった製品は「要確認」になり、理由に「判断を外した」と残ります。判定し直しのあと、要確認の製品を見てください。
  • 取り込みは足す・直すだけで、消しません。前の版で御社が足した結び付き（データソース USER）はそのまま残り、届いたデータより優先されます。

11-4 法規制の変更法律の改正・新しい一覧・御社の社内基準

改正の内容によって、届くものと見るところが少し違います。取り込みの操作そのものは 11-3 の 2〜5 と同じです。

改正の種類届くもの・すること判定結果の扱い
(a) 物質が増えただけ データセット。取り込み → 反映 → 判定し直し（版の切り替えは不要） 増えた物質を含む製品だけ結果が変わります。人の判断は引き継がれます
(b) 中身が変わった（閾値・区分の移動・削除） データセット。新しい規制区分が足され、古い区分に適用終了日が入ります（古い区分は消しません）。取り込み → 反映 → 判定し直し 新しい区分の結果が新しく作られます。人の判断は区分ごとなので、新しい区分には引き継がれません。判定し直しのあと、その法律の該当を見直してください。古い区分の結果はそのまま残ります
(c) 御社の社内基準・独自の一覧 データ入出力 › エクスポートで「規制リスト」をデータソース USER で出し、行を直して（1 行 = 法文物質名 × CAS）インポート → 反映 → 判定し直し。列名と並びは変えないこと (a)(b) と同じ。中身が変わるときは、画面で新しい区分を作って古い区分に適用終了日を入れてから、新しい区分の名前でリストを作ります

CAUTION

古い規制区分を消さないでください。区分を消すと、その区分の判定結果（確認済の印を含む）も一緒に消えます。 古い区分は適用終了日で「もう効いていない」と分かるようにしてあります。

CHECK

11-3・11-4 が終わったら、代表的な製品を 1〜2 件開き、判定対象日を入れずに該当・非該当が案内どおりになっていることを見てください。 変わり目をまたぐ製品は、判定対象日に改正前の日付を入れると前の結果が見られます。
