## 1. はじめに

### 1.1 目的
化学物質・製品（混合物）・原材料の組成情報、および各種法規制情報を一元管理し、ある製品が各法規制の規制対象となるか（該当区分）を、根拠とともに自動判定・記録・出力できるWebアプリケーションを構築する。

### 1.2 スコープ
- **対象**: 物質マスタ管理、製品/原材料の組成管理、組成の物質レベル展開・統合、法規制マスタ管理、法文物質名と物質のリンク管理（情報源別・優先度付き）、規制該当判定、判定結果の保存・出力、データ取込/出力、検索、ユーザ・権限管理、監査、**ドキュメント生成（テンプレート登録＋差込による PDF/Word/Excel 生成）**、**多言語UI（ロケール登録＋UI翻訳管理）**。
- **対象外（現時点）**: SDS（安全データシート）**文面の自動作文**（テンプレートへのデータ差込は対象・§4.11）、外部DBへのリアルタイム自動同期、購買/在庫管理。【要確認 Q-S1】

### 1.3 用語定義
| 用語 | 定義 |
|---|---|
| 化学物質（物質） | システム内の独自IDで識別される単一物質。CAS番号で種類がほぼ特定されるが、CASでの一意性は保証しない。 |
| CAS番号 | CAS Registry Number。外部情報源が物質を特定する際のキー。 |
| 製品 | 化学物質または原材料を組成として持つ混合物。 |
| 原材料 | 他の製品の組成になりうる製品。製品自身が原材料にも製品にもなりうる（同一エンティティ）。 |
| 組成（原組成） | 製品に登録された、構成要素（物質または原材料）と重量含有率の集合。展開前の値。 |
| 展開 | 組成中の原材料を再帰的に物質レベルまで分解すること。 |
| 統合 | 展開の結果、同一物質が複数経路で出現した場合に含有率を合算して1件にまとめること。 |
| 法律 | 規制の最上位レイヤ（例：化審法）。 |
| 規制区分 | 法律配下の区分（例：第一種特定化学物質）。 |
| 管理番号 | 規制区分内での通番。 |
| 法文物質名 | その法律における規制対象の呼び方。単一物質の場合も、複数物質を包含する総称（例：亜鉛化合物）の場合もある。 |
| リンク | 法文物質名と化学物質（CAS）との対応情報。情報源別に保持。 |
| 情報源 | リンク情報の出所（例：LOLI、CHRIP、JAMP、ユーザデータ）。優先度を持つ。 |
| 判定 | 製品が各法規制で規制を受けるか（該当区分）を算定する処理。 |

### 1.4 前提・制約【追加提案】
- Webアプリ（マルチユーザ前提）。対応ブラウザは最新版 Chrome / Edge / Safari。
- 含有率の単位は重量パーセント（wt%）を基本とし、内部は高精度（例：小数点以下相応桁）で保持。表示桁・丸め規則は別途定義。【要確認 Q-N1】
- 法規制マスタはバージョン管理せず、変更は編集＋監査履歴で管理する。判定の再現性は、使用したリンクバージョン（例：2026Q2）と入力スナップショットで担保する。【Q-R1確定】
- **識別子（ID）方針**: 主要マスタ（物質・製品/原材料・法律・規制区分 等）は、**ユーザーが付与する業務キー（コード）**を一意識別子として持つ。内部的には別途サロゲートキーを自動生成し、FK/結合は内部キーを参照する（コード変更に強くするため）。詳細は `data-model.md` §1.4。

## 2. システム概要

### 2.1 主要サブシステム
1. **物質管理** … 化学物質マスタ、名称（和英・主従）、任意プロパティ、金属換算係数（CAS-金属-％）。
2. **製品/原材料管理** … 製品マスタ、組成（原組成）、展開・統合組成。
3. **法規制管理** … 法律→規制区分→管理番号→法文物質名の階層、判定パラメータ。
4. **リンク管理** … 法文物質名↔CASのリンクを情報源別・優先度付きで管理、取込。
5. **判定エンジン** … 製品×法規制の該当判定、根拠記録、結果保存・出力。
6. **共通基盤** … 認証・認可、検索、取込/出力、監査・履歴、整合性チェック。
7. **ドキュメント生成** … テンプレート登録、差込による PDF/Word/Excel 生成、生成履歴。
8. **多言語基盤** … ロケール登録、UI翻訳管理、ユーザー言語設定。

### 2.2 利用者（ロール）【提示要件】
3ロール構成。権限はロールベース（RBAC）とし、上位は下位の権限を包含する。

| ロール | 概要 | できること | できないこと |
|---|---|---|---|
| システム管理者 | システム全体の管理者 | 全機能（ユーザ・権限管理、システム設定を含むすべて）。編集は常に可。 | なし |
| 特権ユーザー | 業務データの全権ユーザー | 化学物質・法規制・製品/組成など業務データの全操作（参照・登録・編集・削除）。**すべての製品組成を閲覧可能**。判定の実行・結果閲覧。編集は常に可。 | ユーザ・権限管理、システム設定 |
| 非特権ユーザー | 一般利用者 | 業務データの利用（2.3のアクセス制御の範囲内）。製品本体は既定で閲覧可、**組成公開フラグがオンの製品のみ組成を閲覧可**。**編集権限（可/不可）を個別に付与でき**、不可の場合は参照・判定実行のみ。 | **非公開フラグがオンの製品は丸ごと閲覧不可**。組成公開フラグがオフ（既定）の製品の組成・組成由来明細は閲覧不可。編集権限が無い場合は登録・変更・削除・一括取込が不可。 |

**編集権限【Q-A1確定】**: ユーザに編集権限（可/不可）を持たせる。システム管理者・特権ユーザーは常に「可」。非特権ユーザーは「可（登録・変更・削除・一括取込ができる）」または「不可（参照・判定実行・ダウンロードのみ）」を設定できる。閲覧可否（2.3）とは独立した軸。

### 2.3 機密性アクセス制御【提示要件】
非特権ユーザーに対する開示を、**製品本体**と**組成**の2つの独立した制御で行う。既定値は逆向き（本体は公開、組成は非開示）。

**(1) 製品本体の公開** — 製品に **非公開フラグ** を持たせる。**既定はオフ（＝公開）**。
- オフ（既定）: 非特権ユーザーは製品の存在・ヘッダ情報（ID・名称・非機密プロパティ）を閲覧できる。
- オン（非公開）: 非特権ユーザーから当該製品を**丸ごと**隠す（一覧・検索・判定対象にも出ない）。

**(2) 組成の公開** — 製品に **組成公開フラグ** を持たせる。**既定はオフ（＝非開示）**。
- オフ（既定）: 非特権ユーザーは組成を閲覧できない（本体は公開なら製品名等は見える）。
- オン: 非特権ユーザーにも組成を開示する。

**両フラグの関係**: 非公開フラグがオンの製品は本体ごと隠れるため、組成公開フラグの値に関わらず非特権ユーザーには一切見えない。組成公開フラグは「本体公開（非公開フラグオフ）」の製品に対してのみ意味を持つ。

| 非特権ユーザーから見た状態 | 非公開フラグ | 組成公開フラグ | 製品名・存在 | 組成 |
|---|---|---|---|---|
| 既定 | オフ | オフ | 見える | 見えない |
| 組成も開示 | オフ | オン | 見える | 見える |
| 完全非公開 | オン | （不問） | 見えない | 見えない |

- 非開示（組成公開オフ）の製品について、非特権ユーザーは原組成・展開統合組成・展開明細・組成由来の判定明細（寄与物質・含有率）を閲覧できない。判定の**結論（該当区分）**を見せるかは Q-A4。
- システム管理者・特権ユーザーは両フラグに関わらず全製品・全組成を閲覧可能。フラグ設定はシステム管理者・特権ユーザーが行う。

> 注意（情報漏洩経路）: 組成を隠しても、判定結果の根拠明細・逆引き検索（「この物質を含む製品」）・エクスポートから組成が推測されうる。マスキングはこれらにも一貫適用する。対象範囲は Q-A4。

## 3. ドメインモデル（データ要件）

> 記法: `1` = 1件、`0..1` = 任意1件、`1..*` = 1件以上、`0..*` = 0件以上。

### 3.1 化学物質（Substance）【提示要件】
| 属性 | 必須 | 説明 |
|---|---|---|
| 物質コード | ○ | **ユーザーが付与する業務キー**。一意（正規化して突合）。画面表示・TSV突合に使用。 |
| 物質ID（内部） | ○ | 内部サロゲートキー（自動生成）。FK/結合はこれを参照。 |
| CAS番号 | ○ | **1件必須**（1物質につき最大1件）。物質をほぼ特定。**一意制約は課さない**（別々の物質が同一CASを持ちうる）。【Q-D1確定】 |
| メイン日本語名称 | ○ | 1件（必須）。 |
| サブ日本語名称 | − | 0..*。 |
| 任意プロパティ | − | 0..*。物性値・構造式（SMILES/InChI/分子式等）など自由項目。 |

- 【追加提案・運用注意】CAS必須の帰結: ポリマー・UVCB・新規/企業秘密物質など**CASを持たない物質は登録できない**。実データでこれらが出た場合は、暫定CAS運用（例: 社内採番のプレースホルダCAS）か本ルールの緩和を別途検討する（現時点は必須で確定）。
- 名称の構造（Substance Name）: 各名称は **日本語名称** と対応する **英訳（任意）** を持つ（和英ペア）。種別＝メイン/サブ、表示順を持つ。メインは1件のみ。【提示要件】
- 物質名称（SubstanceName）
  | 属性 | 必須 | 説明 |
  |---|---|---|
  | 物質ID | ○ | 親物質。 |
  | 種別 | ○ | メイン / サブ。メインは1物質1件。 |
  | 日本語名称 | ○ | |
  | 英語名称 | △ | 英訳。**任意**（サブ名称にも英訳は必須でない）。【Q-D2確定】 |
  | 表示順 | − | サブ名称の並び。 |
- 任意プロパティ【Q-D3確定・併用方式】: **定義マスタ方式（EAV）と自由JSONを併用**する。**検索・絞り込み・判定に使う項目は必ず定義マスタ（EAV）**に持たせ、雑多なそれ以外の項目は**表示専用の自由JSON**に持つ。
  - **移植性ルール（重要）**: 自由JSONは Prisma `Json` 型（3DB対応）で**表示専用の入れ物**とし、**JSON内部を条件検索・並べ替え・集計に使わない**（PG/MySQL/SQL Server でJSON演算子が異なり移植性を損なうため）。検索したくなった項目は定義マスタへ昇格させる。
  - **構造式の保持**: **SMILES / InChIKey / 分子式（molecular formula）をテキスト項目（定義マスタ項目）として保持**する。InChIKey は将来の物質名寄せ（Q-G7）にも活用。構造式**画像**は保持形式に含めず、必要なら添付ファイル（Q-G4）として扱う。
  - プロパティ定義マスタ（SubstancePropertyDef）
    | 属性 | 必須 | 説明 |
    |---|---|---|
    | プロパティ定義ID | ○ | |
    | プロパティ種別（キー） | ○ | 例：融点、密度、SMILES、InChIKey、分子式。一意。 |
    | データ型 | ○ | 数値 / テキスト。 |
    | 既定単位 | △ | 数値プロパティの単位（例：℃、g/cm³）。 |
    | 表示順 | − | |
  - 任意プロパティ値（SubstanceProperty・EAV値）
    | 属性 | 必須 | 説明 |
    |---|---|---|
    | 物質ID | ○ | |
    | プロパティ定義ID | ○ | 定義マスタ参照。 |
    | 値 | ○ | テキスト/数値（型は定義マスタに従う）。 |
    | 単位 | △ | 数値プロパティの単位（未指定時は既定単位）。 |
  - 自由プロパティ（SubstanceExtra・表示専用JSON）
    | 属性 | 必須 | 説明 |
    |---|---|---|
    | 物質ID | ○ | |
    | 追加項目 | − | Prisma `Json`。定型化しない雑多な項目。**内部を条件検索しない**。 |
- 金属換算係数（MetalConversionFactor）【Q-J5確定・PRTR金属換算判定用】
  CAS基準で管理する独立マスタ（物質ID基準ではない）。1組 = `CAS - 金属(元素) - ％`。
  | 属性 | 必須 | 説明 |
  |---|---|---|
  | CAS番号 | ○ | 対象物質をCASで特定。 |
  | 金属元素 | ○ | 元素記号。例：Pb, Zn, Cr。 |
  | 割合(%) | ○ | 当該CASの物質分子中における当該金属元素の重量割合。例：ある鉛化合物で Pb=50%。 |
  - 同一CASに複数金属の係数を持ちうる（0..*）。
  - 判定時は、物質のCAS＋法文物質名の判定金属元素で本マスタを引き、寄与量を金属換算する（5.1）。
  - バージョン管理の対象外（法規制マスタ・物質と同じく、変更は編集＋監査履歴で管理）。【Q-J7確定】

### 3.2 製品 / 原材料（Product）【提示要件】
製品と原材料は**同一エンティティ**として扱う。区別は「他製品の組成として利用可能か」のフラグ等で表現。

| 属性 | 必須 | 説明 |
|---|---|---|
| 製品コード | ○ | **ユーザーが付与する業務キー**。一意（正規化して突合）。 |
| 製品ID（内部） | ○ | 内部サロゲートキー（自動生成）。FK/結合はこれを参照。 |
| 日本語名称 | ○ | |
| 英語名称 | △ | |
| 原材料利用可フラグ | − | **既定オフ**。オンにすると、この製品を他の製品/原材料の組成（構成要素）として使用できる。製品と原材料は同一エンティティで、本フラグ以外に違いはない（製品を原材料として使いたくなったらオンにする）。【Q-D4確定】 |
| 非公開フラグ | − | 既定オフ（本体公開）。オンで非特権ユーザーから製品を丸ごと隠す。【提示要件・2.3】 |
| 組成公開フラグ | − | 既定オフ（組成非開示）。オンで非特権ユーザーにも組成を開示。【提示要件・2.3】 |
| 任意プロパティ | − | 0..*。製品固有のオプション項目。 |

- **原組成（CompositionLine）**【提示要件】: 製品が直接持つ構成要素と重量含有率。
  | 属性 | 必須 | 説明 |
  |---|---|---|
  | 親製品ID | ○ | |
  | 構成要素種別 | ○ | 物質 / 製品（原材料）。 |
  | 構成要素ID | ○ | 物質IDまたは製品ID（ポリモーフィック参照）。 |
  | 重量含有率(%) | ○ | **単一の数値のみ**（Decimal）。範囲（min–max）・「<X」・「N.D.」等の特殊表現は**非対応**。残部は balance（Q-D5）で表現。【Q-G1確定】 |
  - 原組成は製品ごとに 1..* 行。**含有率合計の検証ポリシーはシステム設定としてシステム管理者が切替可能【Q-D5確定】**。既定は「標準」。
    - **検証モード（システム設定・管理者が変更可）**:
      - **厳格(strict)**: 合計 = 100%（±ε）を必須とし、外れたら**登録不可（エラー）**。
      - **標準(standard・既定)**: **> 100%（+ε超）は拒否**、**< 100% は許容し警告**（多数の企業に受容される標準的取扱い）。
      - **緩和(lenient)**: 合計を検証しない（警告のみ／無検証）。範囲・残部・非開示成分が多いデータ向け。
    - **許容誤差 ε（システム設定・数値）**: 丸め差の吸収。Q-N1（保持精度）確定後に既定を固定（仮値 ε = 0.01 wt%）。
    - **balance（残部）許容（システム設定・on/off・既定on）**: on の場合 balance は**1成分のみ指定可**とし、内部で `100% − 既知成分合計` を補完（負値になる場合は誤差エラー）。含有率そのものは単一の数値のみ（範囲・不等号・N.D.は非対応＝Q-G1確定）。
    - **判定での未開示残部/残部(balance)**: 既定は非対象物質として寄与0。
    - 検証モードは**登録・一括取込（TSV）の両方に一貫適用**する。既存データはモード変更で遡及的にエラー化せず、次回編集・再検証時に評価する。

- **展開・統合組成（ExpandedComposition）**【提示要件】: 原組成中の原材料を再帰的に物質レベルへ展開し、同一物質を合算統合した結果。**原組成と展開・統合後組成の両方を保持**する。
  | 属性 | 必須 | 説明 |
  |---|---|---|
  | 製品ID | ○ | |
  | 物質ID | ○ | 統合後は製品内で一意。 |
  | 統合後含有率(%) | ○ | 経路ごとの寄与（親含有率×子含有率…）の総和。 |
  | 算出基準日時 | ○ | 再計算のトレース用。【追加提案】 |
- **展開明細（ExpandedPath）【Q-D6確定・保持する】**: 統合前の経路別寄与（どの原材料経由で何%か）。トレーサビリティ・監査のため保持する。

### 3.3 法規制階層【提示要件】
- 法律（Law）
  | 属性 | 必須 | 説明 |
  |---|---|---|

### 3.5 判定実行・結果【追加提案】
- 判定実行（DeterminationRun）: 対象製品、**使用リンクバージョン（例：2026Q2）**、（法規制マスタ版があればその基準日／版）、実行者、実行日時、適用した情報源優先度スナップショット。
- 判定結果（DeterminationResult）: 法律・区分・法文物質名ごとの 該当/非該当、算定値（合算量・金属換算量）、採用情報源、使用バージョン、寄与物質明細、最終該当区分、抑制された下位区分。
- 結果は再現可能性のため、入力スナップショット（組成・リンクバージョン・閾値）への参照または値を保持。

## 4. 機能要件

### 4.1 物質管理
- FR-S-01 物質の登録/編集/削除（論理削除）。【提示要件】
- FR-S-02 メイン日本語名称（必須・1件）とサブ日本語名称（0..*）の管理、各名称の英訳管理。【提示要件】
- FR-S-03 CAS番号の登録（**必須**・非一意許容）。別物質が同一CASを持つのは許容。重複CAS登録時は警告表示。【Q-D1確定】
- FR-S-04 任意プロパティ（物性、構造式 等）の登録。定義マスタ項目（EAV・検索対象）＋表示専用JSON の併用。構造式は SMILES/InChIKey/分子式 をテキスト保持。【Q-D3確定】
- FR-S-05 金属換算係数（CAS-金属-％）の登録・編集（PRTR金属換算判定用の参照マスタ）。【Q-J5確定】
- FR-S-06 物質一覧の検索（ID/CAS/名称（和英）/プロパティ）。【追加提案】

### 4.2 製品 / 原材料管理
- FR-P-01 製品の登録/編集/削除。日本語/英語名称、任意プロパティ。【提示要件】
- FR-P-02 原組成（構成要素＝物質 or 製品、重量含有率）の登録。【提示要件】
- FR-P-03 製品を他製品の組成（原材料）として参照可能にする。【提示要件】
- FR-P-04 循環参照（A→B→A 等）の検出と登録拒否。【追加提案】
- FR-P-05 含有率合計の検証。**検証ポリシー（モード=厳格/標準/緩和・許容誤差ε・balance許容）はシステム設定でシステム管理者が切替**。既定=標準（>100%拒否・<100%警告・balance1件補完）。登録・TSV取込に一貫適用。【Q-D5確定】

### 4.3 組成の展開・統合【提示要件】
- FR-X-01 原組成中の原材料を再帰的に物質レベルまで展開する。
- FR-X-02 各経路の寄与含有率は「親含有率×子含有率×…」で算出する。【追加提案・算出規則明確化】
- FR-X-03 同一物質が複数経路で出現した場合、含有率を合算して統合する。
- FR-X-04 原組成・展開統合後組成の両方を保持する。（展開明細の保持は Q-D6）
- FR-X-05 展開は明示実行/自動（保存時・依存変更時）を選べる。再計算トリガと鮮度表示。【追加提案・Q-X1】
- FR-X-06 展開深さ上限、丸め/誤差の扱いを定義（合算後の合計が理論値からずれた場合の表示）。【追加提案・Q-N1】

### 4.4 法規制管理【提示要件】
- FR-R-01 法律→規制区分→法文物質名エントリ（管理番号付き）の階層管理。
- FR-R-02 規制区分の rank・兼ね合いフラグ・兼ね合いグループ・**合算方式（区分全体/法文物質名単位/合算なし）**・区分閾値・結果抑制フラグ の設定。
- FR-R-03 法文物質名の 該当含有率範囲（オプション）・判定方式・判定金属元素 の設定。（合算可否は規制区分の合算方式に集約）
- FR-R-04 法規制マスタはバージョン管理せず、変更は編集＋監査履歴で管理する。【Q-R1確定】（リンクデータのみバージョン管理：3.4）

### 4.5 リンク・情報源・バージョン管理【提示要件】
- FR-L-01 法文物質名↔CASのリンクを情報源別・バージョン別に登録/編集/削除。
- FR-L-02 情報源マスタと優先度の設定（登録時に優先順位設定可）。
- FR-L-03 外部情報源（LOLI/CHRIP/JAMP）のリンクデータ取込（インポート）。取込先のバージョンを指定。形式は別途定義。【提示要件＋Q-I1】
- FR-L-04 ユーザデータ（自社判断）のリンクを手動登録（対象バージョンを指定）。【提示要件】
- FR-L-05 判定時の情報源フォールバック: 同一バージョン内で、上位情報源に情報が無い場合に下位を採用。フォールバック単位は【要確認 Q-L2】。
- FR-L-06 リンクデータセットバージョンの作成/複製/編集/廃止。バージョンコード（例：2026Q2）の付与。【提示要件】
- FR-L-07 既存バージョンを複製して新バージョンの編集起点にできる（差分投入の利便）。【追加提案・Q-V4】
- FR-L-08 バージョン間の差分比較（追加/変更/削除されたリンク）。【追加提案】
- FR-L-09 判定で使用する既定バージョンの指定（最新／明示指定）。【追加提案・Q-V1】

### 4.6 判定エンジン【提示要件】（詳細は「5. 判定仕様」）
- FR-J-01 製品を指定し、対象法規制（全件/選択）に対して判定を実行する。**使用リンクバージョンを指定**（既定は最新／明示選択）。
- FR-J-02 展開・統合後組成と、指定バージョン内で情報源優先度に基づき解決したリンクを用いる。
- FR-J-03 判定パターン（後述）を法文物質名・規制区分の設定に従って適用する。
- FR-J-04 最終的な「該当区分」を算定し、根拠（寄与物質・採用情報源・算定値）を記録する。
- FR-J-05 結果抑制設定に従い、上位該当時の下位区分表記を制御する。
- FR-J-06 判定結果の保存・履歴・再実行・差分比較。【追加提案】
- FR-J-07 一括判定: 全製品／選択製品（原材料含む）をバッチで判定実行できる。【追加提案・Q-G2】
- FR-J-08 影響分析・再判定: リンクバージョン投入や法規制マスタ・金属換算係数の変更時に、影響を受ける製品（過去判定が陳腐化した製品）を特定し、再判定対象として一覧化・一括再判定できる。【追加提案・Q-G2】
- FR-J-09 鮮度管理: 各製品の最新判定が、現在の最新バージョン・最新組成に基づくかを示し、「要再判定」を可視化する。【追加提案・Q-G2】

### 4.7 取込 / 出力【提示要件＋追加提案】
- FR-IO-00 **個別操作**: すべての主要データ（化学物質、製品/原材料、法規制（法律・規制区分・法文物質名エントリ）、法文物質名↔化学物質リンク、情報源、リンクバージョン 等）は、画面から**個別に登録・変更・削除**できる（削除は論理削除を基本）。【提示要件】
- FR-IO-01 **TSV一括登録**: 次の各データは TSV ファイルによる一括登録（インポート）ができる。【提示要件】
  - 製品 / 原材料、化学物質、法規制、法文物質名↔化学物質リンク
  - 仕様: タブ区切り（TSV）、文字コードは UTF-8（Excel互換のためBOM要否は Q-IO1）、1行目はヘッダ。エンティティごとに列定義（テンプレート）を提供。
  - バリデーション後に取込、エラー時は行単位でエラー内容を提示（部分取込/全件ロールバックの方針は Q-IO2）。
  - 取込モードは新規登録を基本とし、既存データの更新（upsert）・一括削除を含めるかは Q-IO3。upsert時の突合キー（ID/CAS/コード等）は Q-IO4。
  - 階層・関連を持つデータの表現: 法規制（法律→規制区分→法文物質名）の階層、リンク（バージョン・情報源・法文物質名・CASの組）の TSV 列設計は別紙化（Q-I1, Q-IO5）。

## 5. 判定仕様（最重要）

判定は次の独立した設定軸の組合せで定義する。固定の5パターンではなく**設定駆動**とし、ご提示の各ケースを設定の組合せとして表現する。

### 5.1 共通：寄与量の定義
製品 P の展開・統合後組成 `{(物質 i, 含有率 r_i [wt%])}` に対し、法文物質名 S に該当する物質集合 `M(S)`（リンク解決＋情報源フォールバック後）を求める。物質 i の S への寄与量を次で定義する。

- S.判定方式 = **含有率方式**: `寄与(i,S) = r_i`
- S.判定方式 = **金属換算方式（PRTR型）**: `寄与(i,S) = r_i × f(CAS_i, e) / 100`
  - `e` = S.判定金属元素（法文物質名のフィールド。多くの場合NULL。設定されている場合に金属換算を行う）。
  - `f(CAS_i, e)` = 金属換算係数マスタから引いた、物質 i のCASにおける元素 e の重量割合(%)。
  - 例：法文物質名「鉛および鉛化合物」(e=Pb)、物質Aが鉛化合物で含有率 r=10%、Aの金属換算係数 f(CAS_A, Pb)=50% → 寄与 = 10 × 50/100 = 5%（これを閾値と比較）。

### 5.2 設定軸
1. **合算方式（区分単位の3択。法文物質名ごとのフラグは廃止）**【Q-J2確定】
   - **法文物質名単位合算**（最頻）: 区分内の各法文物質名 S ごとに `S該当量 = Σ_{i∈M(S)} 寄与(i,S)`。S該当量 ≥ 閾値 で S 該当、いずれかの S 該当で区分該当。**同一物質が同区分内の複数の法文物質名に該当する場合、各法文物質名でそれぞれ合算する（名称をまたいだ重複は許容）**。
   - **区分全体合算**: 区分内で該当する物質を集めて合算するが、**同一物質は1回のみ計上（多重合算しない）**。`区分該当量 = Σ_{distinct i ∈ ∪_S M(S)} 寄与(i)`。`区分該当量 ≥ 区分閾値` で区分該当。
   - **合算なし**: 区分内の各該当物質 i を個別に `寄与(i)` で閾値判定し、いずれか該当で区分該当。
2. **判定方式**: 含有率 / 金属換算（5.1）。法文物質名ごとに設定。
3. **閾値（該当含有率範囲）**: 下限と上限。**該当 ⟺ 下限 ≤ 値（かつ上限が設定されていれば 値 ≤ 上限）**。上限超過は当該区分では非該当となり、別区分に振り分ける用途がある（濃度帯で区分を分ける規制）。比較の境界（以上/超過、以下/未満）は Q-N2。**閾値は法文物質名・規制区分の両方に持てる。法文物質名の閾値はオプションで、設定があれば優先、無ければ規制区分の閾値を使用する。**【Q-J1/Q-J6確定】
4. **区分の兼ね合い（累積判定）**: 区分に**兼ね合いフラグ**（既定オフ＝独立判定）。**オフの大多数は区分ごとに独立して判定する**。オンの区分は、自区分の判定時に自区分より上位（rank が小さい＝厳しい）区分の物質を累積して判定する。【Q-J3確定】
5. **結果抑制**: 兼ね合いで複数区分が該当した場合、最も厳しい該当区分（rank最小）のみを最終結果とし、下位の該当を抑制する（既定オン）。【Q-J4確定】

> 補足（区分全体合算と金属換算）: 区分全体合算は含有率方式（判定金属元素=NULL）を前提とする。金属換算（判定金属元素あり）の判定は法文物質名単位合算で行う運用とし、区分全体合算への金属換算の混在は対象外。【Q-J5確定】

### 5.3 ご提示ケースの表現
| # | ケース | 設定 | 算定 |
|---|---|---|---|
| 1 | 最頻：法文物質名で合算 | 合算方式=法文物質名単位 | 各 S で `S該当量=Σ r_i ≥ 閾値` で S 該当。同一物質が複数名称に該当すれば各名称で合算（名称間の重複可）。 |
| 2 | 合算しない | 合算方式=合算なし | 各 `r_i ≥ 閾値` のいずれかで区分該当 |
| 3 | 区分全体で合算 | 合算方式=区分全体 | `Σ_{distinct i} r_i ≥ 区分閾値` で区分該当。**同一物質は1回のみ計上** |
| 4 | 区分の兼ね合い（既定は独立判定。特定規制のみ累積） | 兼ね合いフラグ＋rank | **既定（フラグオフ）は区分ごとに独立判定。** フラグオンの区分は、自区分の判定対象に自区分より上位（rank小）区分の物質を累積。複数区分が該当した場合は最も厳しい該当区分のみを最終結果とし、下位を抑制 |
| 5 | PRTR金属型 | 金属換算方式＋判定金属元素 | `Σ r_i × f(CAS_i,e)/100 ≥ 閾値` で該当（f=金属換算係数） |

> ケース4の確定例（化審法 第1種〜第3種を想定。rank: 1種=1 が最も厳しい）:
> - 3種の判定（兼ね合いオン、3種閾値=5%）に、1種・2種・3種の該当物質を累積する。
> - 例：3種物質が3%、2種物質が3%含有 → 3種単独では3%<5%で非該当に見えるが、**上位の2種が3種を兼ねる**ため 3%+3%=6% ≥ 5% となり、**3種に該当**と判定する（この例の最終結果＝3種）。
> - 同様に 2種判定は1種+2種の合計、1種判定は1種の合計で行う。1種にも2種にも該当する場合は、結果抑制により最も厳しい1種のみを最終結果とする。

> 注：合算方式は「区分単位の単一設定」、判定方式（含有率/金属換算）は「法文物質名単位の設定」であり、両者は独立に組み合わさる（併用の優先規則は不要）。

### 5.4 判定アルゴリズム（概要）
1. 使用するリンクバージョン（例：2026Q2）を確定（既定＝最新 or 明示指定）。法規制マスタ版があれば基準日で確定。
2. 対象製品の展開・統合後組成を取得（無ければ展開実行）。
3. 各法文物質名 S について、**選択バージョン内で**情報源優先度順にリンクを探索し、最初に情報を持つ情報源を採用（フォールバック単位は Q-L2）。CAS→物質ID解決。
4. 区分の合算方式に応じて区分該当量を算定し、閾値（法文物質名にあればそれ、無ければ区分閾値）と比較して該当可否を判定。
   - 法文物質名単位合算: 名称ごとに合算（名称間の物質重複可）。
   - 区分全体合算: 該当物質を1回のみ計上して合算。
   - 合算なし: 物質ごとに個別判定。
5. 兼ね合いフラグONの区分は、自区分より上位区分の物質を累積して判定（独立判定が既定）。
6. 複数区分該当時は、結果抑制により最も厳しい該当区分（rank最小）を最終結果とする。
7. 根拠（寄与物質・採用情報源・使用バージョン・算定値）とともに結果を保存。

## 9. 確認事項（オープンクエスチョン）

### データモデル
- **Q-D1**【確定】CAS番号は物質に **1件必須**（1物質1CAS）。ただし**一意ではなく、別々の物質が同一CASを持つことを許容**する。判定は製品組成の物質→そのCAS→法文物質名リンクの突合で行う（同一CAS共有は矛盾なく扱える）。
- **Q-D2**【確定】名称の英訳は**任意**。サブ名称にも英訳は必須でない。
- **Q-D3**【確定】任意プロパティは**定義マスタ（EAV）＋表示専用JSONの併用**。検索/判定に使う項目はEAV、雑多な項目はJSON（内部検索しない・移植性のため）。構造式は **SMILES/InChIKey/分子式をテキスト保持**、画像は添付扱い（Q-G4）。詳細は §3.1。
- **Q-D4**【確定】製品と原材料は同一エンティティ。区別は**原材料利用可フラグ（既定オフ）のみ**で、オンにすると他の製品/原材料の組成として使える。それ以外の違いは無い。
- **Q-D5**【確定】原組成の含有率合計の**検証ポリシーはシステム設定でシステム管理者が切替可能**（モード=厳格/標準/緩和・許容誤差ε・balance許容）。**既定=標準**（>100%拒否・<100%許容＋警告・balance1件内部補完）。未開示残部は判定で既定は寄与0（最悪ケース評価は Q-G1）。丸め誤差 ε の既定は Q-N1 で確定。詳細は FR-U-05・§3.2。
- **Q-D6**【確定】展開明細（統合前の経路別寄与）を**保持する**。

### 判定
- **Q-J1**【確定】閾値は法文物質名・規制区分の両方に持てる。法文物質名の閾値はオプションで、あれば優先、無ければ区分閾値を使用。
- **Q-J2**【確定】合算可否は法文物質名ごとのフラグを廃止し、規制区分の「合算方式」3択（区分全体/法文物質名単位/合算なし）に集約。法文物質名単位合算では同一物質が複数名称に該当すれば各名称で合算（名称間の重複可）。区分全体合算では同一物質を1回のみ計上（多重合算禁止）。
- **Q-J3**【確定】既定は区分ごと独立判定。特定規制のみ「兼ね合いフラグ」をオンにし、自区分より上位（rank小＝厳しい）区分の物質を累積して判定（例：3種判定に1種+2種+3種を合算）。rank は明示設定、累積は同一兼ね合いグループ内のrank比較で機械的に決定。
- **Q-J4**【確定】兼ね合いで複数区分が該当した場合、最も厳しい該当区分（rank最小）のみを最終結果とし、下位を抑制（結果抑制フラグ既定オン）。前述の例では最終結果＝3種。
- **Q-J5**【確定】金属換算は法文物質名の「判定金属元素」（多くはNULL）で制御。NULLなら含有率方式、元素が入っていれば `寄与 = 含有率 × 金属換算係数/100`。金属の割合は **金属換算係数マスタ（CAS-金属-％）** をCASで引く。区分全体合算への金属換算混在は対象外。
- **Q-J6**【確定】該当含有率範囲に上限を持て、上限超過は当該区分では非該当（濃度帯で別区分に振り分ける用途）。判定は 下限 ≤ 値（≤ 上限）。
- **Q-J7**【確定】金属換算係数マスタはバージョン管理しない。法規制マスタ・物質と同じ扱い（変更は編集＋監査履歴）。

### リンク・情報源
- **Q-L1**: CAS→物質ID解決で多重一致/未一致が起きた場合の扱い（警告のみ/該当扱い/除外）。
- **Q-L2**: 情報源フォールバックの単位。「法文物質名ごと」に上位情報源が当該名称のリンクを1件でも持てば採用か、「リンク（CAS）ごと」か、「法律ごと」か。

### 法規制・版管理・リンクバージョン
- **Q-R1**【確定】バージョン管理の対象はCASリンクのみ。法規制マスタ（法律・規制区分・法文物質名エントリ・閾値）はバージョン対象外で、変更は編集＋監査履歴で管理する。
- **Q-V1**: 判定で使用する既定バージョンの決め方。「常に最新の有効バージョン」か、製品/案件ごとに固定指定か、実行時に毎回選択か。
- **Q-V2**: 情報源優先度はシステム共通（グローバル）か、バージョンごとに設定するか。
- **Q-V3**: バージョンに状態（ドラフト/有効/廃止）のライフサイクルを設けるか。投入途中のバージョンを判定対象から除外する仕組みの要否。
- **Q-V4**: 新バージョン作成時、空から投入か、直前バージョンを複製して差分投入か（両対応が望ましいか）。
- **Q-V5**: バージョンは全情報源を必ず含むか、一部情報源だけ更新した部分バージョンを許すか。

### 取込・出力・連携
- **Q-I1**: LOLI/CHRIP/JAMP の取込ファイル仕様・サンプル提供可否。
- **Q-I2**: 判定レポートの様式・必須項目。
- **Q-I3**: 外部システム連携API（提供/利用）の要否。
- **Q-IO1**: TSVの文字コード。UTF-8とし、Excelでの文字化け回避にBOM付きとするか。
- **Q-IO2**: TSV取込でエラー行があった場合、エラー行のみスキップして他を取込むか、全件ロールバックか。
- **Q-IO3**: TSV一括は「新規登録」のみか、既存更新（upsert）・一括削除も含めるか。
- **Q-IO4**: upsert時の突合キー（化学物質＝ID/CAS、製品＝ID/コード、リンク＝バージョン+情報源+法文物質名+CAS 等）。
- **Q-IO5**: 法規制（階層）・リンク（多関連）の TSV 列設計。1ファイルで階層を表すか、階層レベルごとにファイルを分けるか。

### 非機能・認可
- **Q-A1**【確定】非特権ユーザーに編集権限（可/不可）を個別付与する。不可は参照・判定実行・ダウンロードのみ。閲覧可否（2.3）とは独立の軸。
- **Q-A2**: 認証方式（自前/SSO・OIDC/SAML）。
- **Q-A3**【確定】製品ごとの「組成公開フラグ」方式。既定オフ（非開示）、オンで非特権ユーザーへ組成開示。（ユーザ/グループ単位の許可リストは不採用。将来必要なら拡張）
- **Q-A4**: (a)【確定】製品本体は既定公開・非公開フラグで丸ごと非表示。残る論点 → (b)本体公開かつ組成非開示の製品で、判定の最終結論（該当区分）を非特権ユーザーに見せるか／結論ごと隠すか、(c)逆引き検索・エクスポートでのマスキング適用の確認。
- **Q-N1**: 含有率の保持精度・表示桁・丸め規則。
- **Q-N2**: 閾値比較の境界（以上/超過、以下/未満）。
- **Q-N3〜N5**: 性能目標、想定データ量、可用性/保持期間。
- **Q-N6**【確定】UI多言語化は**対応**（ロケール登録式・不特定言語を追加可能・日英を初期提供）。詳細は §3.7・§4.12。
- **Q-S1**: スコープ除外項目（SDS文面生成、在庫等）の確認。

### レビュー指摘（一般的な化学物質管理機能とのギャップ）
本書を一般的な化学物質（含有）管理システムの機能と照合して抽出した論点。採否・仕様を確定する。
- **Q-G1 含有率の表現**【確定】組成含有率は**単一の数値のみ**とする。範囲（min–max）・「<X%」・「N.D.」等の特殊表現は**非対応**。残部は balance（Q-D5、1成分のみ）で表現し、判定では非対象（寄与0）扱い。
- **Q-G2 影響分析・再判定**: バージョン投入やマスタ変更時の、影響製品の特定・一括判定・鮮度（要再判定）可視化（FR-J-07〜09, FR-SR-03）を入れるか。コンプライアンス運用の要。
- **Q-G3 削除制約**: 参照されているデータの削除ポリシー（論理削除＋参照警告／カスケード禁止）（FR-AU-04）でよいか。
- **Q-G4 添付ファイル**: SDS・サプライヤ成分表等のファイル添付（FR-SR-04）を範囲に含めるか。保存先・容量・権限（非開示組成との関係）。
- **Q-G5 サプライヤ/取引先管理**: 原材料の仕入先・製品の納入先を管理するか。組成非開示の運用（取引先別の見せ方）と関係しうる。
- **Q-G6 取扱量ベースの集計/届出**: 含有率判定に加え、PRTR届出等で必要な年間取扱量（絶対量）の集計・届出支援を範囲に含めるか（現状は含有率による該当判定のみ）。
- **Q-G7 CASの別名・旧番号、物質の名寄せ/マージ**: 廃止・統合されたCASや重複登録物質のマージ操作を扱うか。
- **Q-G8 兼ね合い×合算方式の相互作用**: 兼ね合い（累積）判定で上位区分の物質を累積する際、合算は各区分の合算方式に従うか、グループ共通ルールか。対象規制の実挙動で確定。
- **Q-G9 判定単位**: 製品（混合物）全体での判定を前提とするが、RoHS等「均一材料単位」での判定が必要な規制を対象に含めるか（現状は製品単位）。
- **Q-G10 組成公開の伝播**: 組成公開の製品Pが組成非開示の原材料Rを含む場合、Pの展開組成にRの構成物質が現れる。Pの公開でRの中身まで見せるか、Rの非開示を優先してマスキングするか（2.3の機密制御と展開機能の整合）。

### 追加機能（ドキュメント生成・多言語）
- **Q-DOC1**【確定】差込タグは `{{entity.field}}` ドット記法＋繰り返しループ。項目辞書は §4.11 実装時に `docs/document-template-tags.md` として整備。

- **Q-DOC4**【確定】PDF 変換は LibreOffice ヘッドレスを既定（Docker 同梱）。レポート系の HTML 由来は HTML→PDF も可。
