# S7 — 製品 / 原材料マスタ

確定日: 2026-08-16

## これは何か

判定の対象そのもの。**製品と原材料は同じもの**で、`usable_as_material` が立っているものだけ
他の製品の組成に部品として入れられる。それ以外に両者の違いは無い。

## データ項目

| 項目 | 型 | 必須 | 備考 |
|---|---|---|---|
| 製品コード | 20文字 | ○ | 物質と揃えた。正規化列（64文字）に一意制約 |
| 日本語名称 / 英語名称 | 500文字 | ○ / − | 英語が無ければ英語表示でも日本語（`pickName`） |
| 状態 | `ACTIVE` / `DISCONTINUED` | ○ | 廃番でも一覧には出る |
| 備考 | text | − | 日本語のみ。検索対象 |
| 原材料として使える | bool | ○ | 既定オフ |
| 非公開 | bool | ○ | 既定オフ。オンだと権限が無い人には**存在ごと**見えない |
| 組成を公開する | bool | ○ | **既定オン**。オフだと本体は見えるが組成は非開示 |
| 別名 | 子テーブル | − | 最大100件。旧品番・社内の呼び方 |
| 拡張属性 | 子テーブル | − | 管理者が定義した項目 |
| 監査4列 + `deleted_at` | | | 既存マスタと同じ |

`extra`（自由JSON）は作らない。v1 にはあったが画面が無く死んでいた。拡張属性が代わりを果たす。

### 拡張属性は物質と定義を共有する

`substance_property_defs` を **`property_defs` に改名し `target`（`SUBSTANCE` / `PRODUCT`）を足した**。
一意制約は `(target, key)` なので、**物質と製品で同じキーを使ってよい**。
値の表は FK を保つため分けてある（`substance_properties` / `product_properties`）。

管理画面はグループ管理と同じ形で「物質の項目」「製品の項目」の2節に分けた
（`components/property-def-section.tsx`。URLのクエリは `useTableState` の `paramPrefix` で分ける）。

**組成公開の既定を `true` にした理由**: このフラグを変えられるのは `COMPOSITION_VIEW_PRIVATE` を
持つ人だけなので、既定が `false` だと、その権限が無い人が作った製品の組成を本人が見られなくなる。

## 権限

| 操作 | 必要な権限 |
|---|---|
| 一覧・詳細・検索 | `PRODUCT_VIEW` |
| 非公開の製品も見る | ＋ `PRODUCT_VIEW_PRIVATE` |
| 登録・更新・削除 | `PRODUCT_EDIT` |
| 非公開フラグの変更 | `PRODUCT_EDIT` ＋ `PRODUCT_VIEW_PRIVATE` |
| 組成公開フラグの変更 | `PRODUCT_EDIT` ＋ `COMPOSITION_VIEW_PRIVATE` |
| 拡張属性の項目定義 | `ADMIN` |

**自分が見られない区分のフラグは触らせない。** 見えないものを非公開にする／非開示のものを
公開にする、のどちらも防ぐ。値を変えていなければ権限は要らない（触れない項目があっても保存はできる）。

### 非公開製品の隠し方

- 一覧・検索から**除外**する（`total` にも入れない）
- 詳細・更新・削除は **404**。403 だと「その ID の製品は在る」と分かってしまう
- 判断はすべて `visibilityWhere(actor)` に集約し、サーバー側で掛ける
- 画面でも「非公開」列自体を出さないが、これは見やすさのためで、隠す仕事はサーバーがしている

情報の漏れ方の方針は `docs/decisions/0007` に分けて書いた。

## v1 から直したこと

1. コードを 100文字 → **20文字**（物質と揃えた）。正規化で全角→半角も吸収する
2. **削除したコードを再登録できる**（`docs/decisions/0005` の退避方式）
3. コード重複のメッセージに**コードを入れた**（v1 の PUT は「製品コードが既に使用されています」だけだった）
4. 特権かどうかの2値だったフラグ制御を、**4権限**に置き換えた
5. `extra` JSON をやめた

## 検証結果（実測）

権限×エンドポイントは curl（PowerShell から `curl.exe`）で実測した。

- **admin**: 非公開製品・組成非開示製品を登録 → 201。一覧は3件すべて見える
- コード21文字 → 400 ／ 重複 → 409「製品コード「SECRET-001」は既に使われています」
- 全角 `ＰＲＤ-001` で登録 → `code_normalized = PRD-001`。後から `prd-001` を登録すると **409**
- **editor**（`PRODUCT_EDIT`、非公開権限なし）:
  - 一覧は **2件**（`SECRET-001` は件数にも出ない）
  - 非公開製品の GET / PUT / DELETE → すべて **404**
  - `privateFlag: true` で登録 → 403「非公開の設定を変えるには…」
  - `compositionPublicFlag: false` で登録 → 403「組成公開の設定を変えるには…」
  - 既定のフラグなら 201。削除 → **同じコードで再登録できる**
  - 画面では2つの機密フラグが操作不可になり、理由が出る。組成非開示の製品も
    **フラグを変えなければ名称などは編集できる**（実測）
  - 物質用の項目IDを製品に付けようとすると 400「定義されていない項目が含まれています」
- **viewer**（`PRODUCT_VIEW` なし）: 一覧・詳細・登録すべて 403。左メニューに「製品 / 原材料」が出ない
- 拡張属性: 製品側に `melting_point` を追加できる（物質側と同じキーでよい）。
  同じ用途で重複させると 409
- 英語表示で全項目が英語になること、モバイル幅375pxで横スクロールが出ないことを確認
- typecheck / lint / prettier / build / テスト87件すべて通過

## 共通テーブルで見つけて直したこと

**はい/いいえ の列で絞り込むと 500 になっていた。**
Prisma の Boolean 型には `in` が無いのに `{ field: { in: [true] } }` を渡していた。
製品の3つのフラグだけでなく、**ユーザーの「有効」・グループの「有効」・お知らせの「ピン留め」も
同じ理由で落ちていた**（S4 以降ずっと壊れていた）。値そのものを渡す形に直し、
「はい・いいえ両方」を選んだ場合は絞り込まない扱いにした（列は null を取らないため）。
`lib/table-query.test.ts` に固定した。
