## 1. 要件（2026-11-03 にいただいたもの）

1. 組織のあり方はここでは決めない。「管理部門」などの部署名は例で、特定の名前に限らない
2. 製品・原材料と物質には、全社で見られるものと、特定の部署に限ったものがある
3. 製品・原材料の組成は、管理部門など特定の部署の人だけが見られる。その中で、編集の権限を持つ人だけが直せる
4. 自分が見られない物質を組成に含む製品・原材料は、組成を見ることも直すこともできない
5. 組織には「会社」と、その下の「部署」が要る。会社はいくつあってもよい

あわせて「シンプルにしたいので、所属部署だけでユーザーの権限が決まるように」（11-03）と指示をいただきました。
11-04 に、権限とデータの持ち主は実際の組織とは別の「権限グループ」で決め、権限グループには階層を持たせない、と決めていただきました。

## 2. 考え方（ひと言で）

**その人に何ができるかは、その人が入っている権限グループの設定だけで決まります。**

```
人 ──入る（いくつでも）──▶ 権限グループ ──表で決める──▶ どの権限グループのデータに、何ができるか
人 ──所属する（1 つ）──▶ 組織（実際の組織図）         … 権限とは関係ない
```

- 権限グループごとに、「どの権限グループのデータに対して、何ができるか」を表 1 枚で設定します
- 製品・原材料・物質は、どれか 1 つの権限グループに所属します（データの持ち主）
- 組織は実際の組織図です。帳票の差出人・宛先などに使い、権限とは関係ありません。人を登録するとき、権限グループを最初から選んでおくのに使います（8 章）
- 人に直接付ける権限はありません。システム管理者も「システム管理グループ」という権限グループで表します。そこに入っている人は、表に関係なく何でもできます（9 章）

Oracle の Role に近いものです。違いは、権限グループがデータの持ち主にもなることです。

## 3. 言葉

| 言葉 | 意味 |
| --- | --- |
| 組織 | 実際の組織図。いちばん上は会社で、その下（部・課・グループ・事業所など）は会社ごとに自由。取引先も組織の 1 つ。**権限とは関係ありません** |
| 権限グループ | 人に何ができるかを決め、データの持ち主にもなるもの。上下は無く、1 列に並びます（例：「A 社 全体」「製造部」「品質保証部」）。コードと名前を持ちます |
| コード | 権限グループに利用者が付ける、全体で一意の記号。TSV の取り込み・出力で所属先を指すのに使います（7 章） |
| 所属（人） | 人がどの組織にいるか。必ず 1 つ |
| 入る | 人がどの権限グループに入っているか。いくつでも。兼務はここで表します。どれにも入っていない人は、ログインはできますが何も見られず何もできません |
| 所属先（データ） | 製品・原材料・物質が、どの権限グループのものか（「製造部に所属する製品」のように言います） |
| 表・印 | 権限グループの設定の表と、そこに付けるチェック。印は「どの権限グループが、どの権限グループに対して」持つかで言います |
| 最初に選ばれる権限グループ | 人を登録するとき、最初から選ばれた状態で出る権限グループ。組織ごとに組織の画面で決めておきます（システム管理グループの人だけ）。登録する人が外したり足したりできます |
| システム管理グループ | 最初からある特別な権限グループ。入っている人は、表に関係なく何でもできます（9 章） |

## 4. 組織

- 必ず階層になります。いちばん上はどこかの会社で、その下に部・課・グループなどがぶら下がります。何段でもかまいません。会社はいくつあってもかまいません
- どういう構造にするかは、その会社の自由です。決め打ちの組織名はありません
- 人は組織に必ず 1 つ所属します（システム管理グループの人も同じ）。兼務は、組織ではなく権限グループで表します
- 組織は、帳票の差出人・宛先などに今までどおり使います。取引先や事業所のように、権限と関係の無い組織も登録できます
- 組織図を直しても、誰が何をできるかは変わりません

## 5. 権限グループ

- 上下の無い 1 列の一覧です。コードと名前を持ちます。コードは全体で一意で、TSV の取り込み・出力で所属先を指すのに使います（ほかのマスタと同じく、利用者が付けます）。名前は自由に付けられます
- 「A 社 全体」（会社の全員を入れて、会社のデータを見せる）、「製造部」「品質保証部」（部署ごと）のように、用途に合わせて作ります。「システム管理グループ」だけは最初からあります（9 章）
- 人は権限グループにいくつでも入れます。異動のときは付け替えます。どの権限グループにも入っていない人がいてもかまいません（ログインはできますが、何も見られず何もできません）。会社には最初に選ばれる権限グループ（8 章）を設定するので、ふつうはどこかに入ります。入らないのは、管理者がわざと外したときだけで、それはそう設定した結果です
- **消せるのは、入っている人がおらず、所属するデータ（製品・原材料・物質）も無い権限グループだけです。**データがあるときは、先に所属先を移します。消すと、ほかの権限グループの表にあったその行と、最初に選ばれる権限グループの設定からも自動で消えます。「使わない」にして残す状態は持ちません（消すか、残すか）

## 6. 権限グループの設定

### 6-1. 表の形

権限グループごとに、次の表を 1 枚持ちます。行は相手の権限グループ、列は 6 つの印です。

| 相手の権限グループ | 製品・原材料 参照 | 製品・原材料 編集 | 組成 参照 | 組成 編集 | 物質 参照 | 物質 編集 |
| --- | :-: | :-: | :-: | :-: | :-: | :-: |
| （例）A 社 全体 | ✓ |  | ✓ |  | ✓ |  |
| （例）製造部 | ✓ |  | ✓ | ✓ | ✓ |  |

- 相手の権限グループは、一覧から 1 つずつ選びます。一覧には「すべて選択」を置きます。押した時点にある権限グループに印を付けるだけで、あとから作った権限グループは自動では入りません（足し忘れは見られないことですぐ気づく、作ることはまれ、のため）
- 自分自身も相手に選べます。自分の権限グループに所属するデータを扱うには、自分の行が要ります

### 6-2. 印どうしの連動

筋の通らない組み合わせにならないよう、自動で連動させます。

- 「編集」に印を付けると、同じ種類の「参照」にも印が付く。「参照」を外すと「編集」も外れる
- 「組成 参照」に印を付けると、「製品・原材料 参照」にも印が付く
- 「組成は直せるが、製品の名前などは直せない」形は許します
- **「組成 参照」を付けても、「物質 参照」は付きません。**組成を見るには、組成に並ぶ物質が見えること（10 章の条件 3）も要るので、表の画面に「組成を見せるには、同じ行の『物質 参照』も要ります」と注意書きを出します。実務では、組成を見られる人が見る製品は、その人が見られる物質から組成を作るのがふつうなので、食い違いはほとんど起きません（11-06）

### 6-3. 表とは別の権限

製品・物質・組成のほかの権限も、人ではなく権限グループに付けます。どれも「どの権限グループのデータか」に関係しないので、表とは別の欄で「できる・できない」だけを決めます。

- 承認する（承認する人は、承認待ちの製品・物質も見られます。未公開のものを見られるのは、承認する人と作った本人だけで、別の権限は持ちません。7 章）
- 法規制を見る／直す（金属換算係数・情報源などを含む）
- データを出力する（TSV・帳票のダウンロード）、データを取り込む
- ドキュメントの様式を直す・作る・開く／落とす・他人のドキュメントも見る
- 組織を作る・直す
- お知らせを投稿する、他人のお知らせも直す
- フィードバックを見る／書く

同じ権限グループの中で差を付けたいとき（A さんだけ承認できる、など）は、権限グループを分けて、その人だけを入れます。

- 規制の判定を実行する・逆引き検索は、「製品・原材料 参照」に含みます（今と同じ）。無効（廃番）にする／戻すも別の権限にせず、所属先に「編集」の印があればできます
- **承認の仕組みは変えません。**承認する人が承認する製品の組成を見られるよう、「承認する」を持つ権限グループの表には、承認する製品の所属先の行に「組成 参照」の印を付けておきます（運用の注意。11-06）
- **PRTR の届出データの入力は、ここには入れず別途検討します**（11-06）。自分の工場（事業所）の分だけを入力する人と、各工場の入力を集計する人を分ける必要があり、「どの組織の分か」が要るためです（組織が権限に関係する唯一の例外になります）。決まるまでは今の仕組みのままです

### 6-4. 新しく作った権限グループの最初の印

**何も付きません。**作る画面に表を出し、管理者がその場で付けます。
権限グループは用途（部署用・会社全体用など）がまちまちで、どれにも合う最初の印が無いためです。

### 6-5. たどれるのは 1 段だけ

品質保証部が製造部を参照でき、製造部が開発部を参照できても、品質保証部が開発部を参照できるようにはなりません。
印でできるようになるのは、その行の相手の権限グループに**所属するデータ**だけです。
10 章の「原材料の組成も何段でも」は、1 つの製品の組成の中身を順にたどって見えるかを確かめることで、印が何段も伝わることではありません。

### 6-6. いくつも入っている人

2 つ以上の権限グループに入っている人は、**入っている権限グループの印を全部合わせたもの**になります。どれか 1 つが印を持っていれば、その人はできます。

## 7. データの所属先

- 製品・原材料・物質は、1 件ごとに 1 つの権限グループに所属します
- **作るとき**は、作る人が「編集」の印を持つ権限グループの中からだけ選べます（製品・原材料なら「製品・原材料 編集」、物質なら「物質 編集」）。作ったのに自分で直せないデータができるのを防ぐためです
  - 選べるのが 1 つなら、自動でそれに決まります（ふつうの人はほとんどこれ）
  - 2 つ以上なら、何も選ばれていない状態で出し、必ず選ばせます。選ばないと保存できません。間違って見せたくない人に見せないためです
  - システム管理グループの人は、どの権限グループでも選べます（表が無いため）。自動では決めず、必ず選ばせます（11-06）
- **所属先を変えられる**のは、今の所属先と移す先の両方に「編集」の印がある人です。移せないところへ移す必要が出たら、システム管理グループの人に依頼します（印に関係なく移せます。9 章）
- **原材料・物質を移すときは、確認を出します。**移すと、それを組成に含む製品の組成を見られなくなる人が出ることがあるためです。「この原材料・物質を使っている製品が N 件あります。移すと、それらの組成を見られなくなる人が出ることがあります」と出し、了承してから移します。止めはしません（11-06）
- **コードは今までどおり全体で一意です。**見えない所属先に同じコードの製品・物質があるときは「このコードは使えません」とだけ出します（見えないものの存在を知らせないため、理由は言いません）。消そうとしたものが見えない製品の組成で使われているときは「ほかで使われているため消せません」と出します。見えない物質を組成に使いたいときは、システム管理グループの人に依頼して、その物質の所属先を共通の権限グループ（「A 社 全体」など）へ移してもらいます（11-06）
- **TSV の取り込みでは、所属先の決め方を画面で選びます**（11-06）
  - 「画面で選んだ所属先にする」… 作るときと同じく、「編集」の印を持つ権限グループから 1 つ選びます（1 つなら自動）。TSV に所属先の列があっても無視します
  - 「TSV の所属先の列を使う」… 行ごとに、所属先の列に書いた権限グループのコードで決めます。空・無いコード・「編集」の印が無い権限グループの行は、その行だけエラーにして、ほかの行は取り込みます
  - 既にある行を更新するには、今の所属先に「編集」の印が要ります。所属先を変える行は、今の所属先と移す先の両方に要ります
  - 出力の TSV には、所属先（コード）の列を含めます
- **公開の状態**（作成中・承認待ち・差し戻し・公開済み）は、今までどおりこれとは別に確かめます。未公開のものは、作った本人と承認する人（「承認する」を持つ人）だけに見えます。作った本人も、所属先に対する印を外されれば、自分の作成中のものも見えなくなります（印と公開状態の両方を満たしたときだけ見えます。11-06）
- **無効（廃番）は隠しません。**印どおりに全員に見えます（無効になっても製品の組成に残っているものを、組成を見られる人が見られないと困るため）。一覧は絞り込みの既定を「有効のみ」にします。組成に原材料・物質を選ぶ画面には、公開済みで有効なものしか出しません（今と同じ）。「無効を見る」という権限は持ちません（11-06）

## 8. 人を登録するとき（最初に選ばれる権限グループ）

### 8-1. 最初に選ばれる権限グループの設定

組織ごとに「その組織の人を登録するとき、最初から選ばれた状態にしておく権限グループ」を設定しておきます（以下、最初に選ばれる権限グループ）。システム全体の設定で、直せるのはシステム管理グループの人だけです。直す場所は組織の画面（組織の登録・編集）で、設定画面には置きません。組織を作る・直す権限だけの人には、この欄は出ません（2026-11-09 画面設計で決定）。

- **ある組織に設定した権限グループは、その下の部・課などの人を登録するときにも選ばれます。**A 社に設定すれば、A 社のどの部・課の人を登録するときにも選ばれます
- **上の組織に設定したものも、一緒に選ばれます**（下の例）
- 全部の組織に設定する必要はありません。会社に 1 つ、部に 1 つ、のように必要なところだけで足ります
- システム管理グループは選べません（9 章）

| 組織 | 最初に選ばれる権限グループ |
| --- | --- |
| A 社 | A 社 全体 |
| A 社 > 製造部 | 製造部 |
| A 社 > 品質保証部 | 品質保証部 |

この例で A 社 > 製造部 > 第 1 課の人を登録すると、「A 社 全体」と「製造部」が最初から選ばれた状態で出ます。A 社 > 営業部 > 営業 1 課の人なら、営業部にも営業 1 課にも設定が無いので、A 社に設定した「A 社 全体」だけです。営業部や営業 1 課に、わざわざ設定を作る必要はありません。

### 8-2. 登録と異動

1. 組織を選ぶ
2. その組織の、最初に選ばれる権限グループが選ばれた状態で出る
3. 必要なら外したり足したりして保存する

- **この設定は、登録するときに最初から選ばれた状態にするだけです。**人の権限グループは人ごとに保存します。あとで最初に選ばれる権限グループの設定を変えても、すでに登録した人の権限グループは変わりません
- **異動で組織を変えると**、権限グループが選び直され、新しい組織に設定された「最初に選ばれる権限グループ」が選ばれた状態で出ます。前の部署の権限が残らないようにするためです。保存する前に見直して直せます。新しい組織にもその上にも設定が無く、選ばれる権限グループが 0 になっても、そのまま保存できます（その人は何も見られなくなります。5 章）

## 9. システム管理グループ

- 「システム管理グループ」という特別な権限グループを 1 つ、最初から用意します。消せず、コードも名前も変えられません
- **入っている人は、何でもできます。**すべての製品・原材料・物質を見て直せ、組成も 10 章の条件に関係なく見られ、表とは別の権限（ユーザーの管理・システム設定・監査ログを含む）も全部持ちます。この権限グループには表がありません
- 最後の 1 人は外せません。設定を誤っても、管理者が誰もいなくなる（誰も設定を直せなくなる）ことを防ぐためです
- システム管理グループの人も、組織に必ず 1 つ所属します。会社の中ではどこかの部署にいるので、その管理のためです。ほかの権限グループには入る必要はありません（入ってもかまいません）
- 最初に選ばれる権限グループ（8 章）には選べません
- 依頼されてデータの所属先を移すときは、印に関係なくそのまま移せます（7 章）。新しく作るときの所属先は、どの権限グループでも選べます（自動では決めず、必ず選ばせます）
- 辞めた人は、ユーザーを止めてログインできなくします。組織や権限グループに入っているかどうかとは関係ありません

## 10. 組成を見られる条件

見る人が入っている権限グループ（B）と、製品の所属先の権限グループ（A）で決まります。印を持つのは B です。A 自身の設定は関係しません。
見る人が 2 つ以上の権限グループに入っているときは、印を全部合わせて考えます。

1. B の表の A の行に「製品・原材料 参照」の印がある（2 に印があれば連動で付いているので、2 があれば必ず満たします）
2. B の表の A の行に「組成 参照」の印がある
3. 組成の中身が、その人に全部見える
   - 組成に並ぶ物質が全部見える（その物質の所属先に対して「物質 参照」の印がある）
   - 組成に並ぶ原材料が全部見える（その原材料の所属先に対して「製品・原材料 参照」の印がある）
   - 原材料の組成も、同じ条件で見える（何段でも）。原材料の組成を見られない人は、その原材料を含む製品の組成も見られません。製品の画面には原材料を中身まで分けて合計した成分も出るので、原材料の中身が分かってしまうためです

**組成を直すには、2 の代わりに「組成 編集」の印が要ります**（1 と 3 は同じ）。

条件 3 は、権限グループの印だけで決まります。組成に入れられるのは公開済みで有効な原材料・物質だけなので、未公開のものが組成に並ぶことはありません。あとから無効（廃番）になったものが組成に残っていても、無効のものは隠さないので（7 章）、条件 3 の妨げにはなりません（11-06）。

- 条件 3 を満たさない人には、組成の欄に「見られない物質を含むため、組成を表示できません」と出します。組成全体を見せず、直すこともできません。製品のほかの項目（名前・用途など）は、印どおりに見られ、直せます
- 規制の判定はすべての成分で行うので、判定の正しさは変わりません。組成を見られない人にも、製品として当たる規制区分は見せますが、原因の物質や内訳は見せません
- 組成の手がかり（添付ファイル、CAS 番号での製品の絞り込み、判定の内訳など）は、今と同じく組成を見られない人には出しません。逆引き検索・CAS 番号での絞り込み・判定の内訳・反応前の組成は、製品ごとにこの 3 つの条件で確かめてから出します
- 組成に入れる原材料の候補には、その原材料の組成がその人に条件 3 で見えるものだけを出します（見えない原材料を入れると、自分で組成を見られない製品ができるため）
- 組成を見られない人が製品のほかの項目を直して保存しても、組成は消えません（見えない部分には触れません）
- 作った本人も例外ではありません。自分が作った製品でも、所属先に対する印を外されれば、組成も製品も見えなくなります（11-06）

### ドキュメント（帳票）

**見られない情報を含む帳票は、作った本人も含めて誰も開けません**（11-06）。

- 製品・物質 1 件の帳票は、その製品・物質が見えること。組成が載っていれば、上の 3 つの条件も満たすこと
- 一覧の帳票は、載っている製品・物質が全部見えること。そのために、帳票に何を載せたかを記録しておきます
- 未公開のものの帳票は、作った本人と承認する人だけが開けます
- 他人の帳票を一覧に出す入口は、今までどおり「他人のドキュメントも見る」の権限です。見える帳票かどうかは、そのうえでこの条件で確かめます

**組織**: A 社の下に製造部（その下に第 1 課）・開発部・品質保証部・営業部（その下に営業 1 課）・総務部、B 社の下に開発部。

**人**（8 章の、最初に選ばれる権限グループのまま登録）: 製造部 第 1 課の人は「A 社 全体」「製造部」、品質保証部の人は「A 社 全体」「品質保証部」、営業部 営業 1 課の人は「A 社 全体」だけ、のように入ります。

開発部の試作品に、開発部に所属する新しい物質が入っているとき:

- 製造部の人は、試作品そのものが見えません（入っている権限グループのどの表にも、開発部の行が無い）
- 品質保証部の人は、試作品は見えますが、組成は見られません（条件 1・2 は満たすが、開発部に対する「物質 参照」が無く、条件 3 を満たさない）
- 開発部の人は、試作品も組成も見られ、直せます

営業部 営業 1 課の人（「A 社 全体」だけに入っている。会社で共通のものだけを見せたい人）:

- 「A 社 全体」に所属する製品・原材料・物質を、見ることだけができます。直すことも、組成を見ることもできません（「A 社 全体」の表には、「A 社 全体」の行に「製品・原材料 参照」「物質 参照」の印しか無い）
- 製造部・開発部・品質保証部に所属するデータは、製品そのものが見えません
- ここでいう「会社で共通のもの」は、「A 社 全体」に所属させたデータのことです。製造部の人が製造部の所属で作った製品は、営業の人には見えません。営業に見せたい製品は、「A 社 全体」に所属させます

## 12. 今のデータとユーザーの移し方

移す先は、公開検証環境（2 つ）と評価機です。お客さんの環境はまだ無いので、移した日に困らない程度にします。
**権限グループは、移す処理がそれぞれの DB の中身を見て作ります。**環境ごとに手で作る必要はありません。

- **データ**: 「全体」という権限グループを 1 つ作り、今ある製品・原材料・物質を全部そこに所属させます
- **ユーザー**: 今の権限の組み合わせが同じ人どうしを、1 つの権限グループ（「移行 1」「移行 2」…）にまとめます。表の「全体」の行と表とは別の欄に、今と同じ権限を付けます。移した日に、誰のできることも変わらないようにするためです。名前や分け方は、あとで管理者が直します
  - 今の「製品を直せる」は組成を直すことも含むので、「製品・原材料 編集」と「組成 編集」の両方を付けます
  - 組成を見られる人には「物質 参照」も付けます（付けないと条件 3 で組成が見えなくなるため）
  - 今のシステム管理者（「システム管理」の権限を持つ人）は、システム管理グループに入れます
  - 今の「無効・未公開のデータも見られる／編集できる」は無くなります。無効は全員に見え、未公開は承認する人と作った本人だけが見えます。この権限だけを持っていて「承認できる」を持たない人は、他人の未公開のものが見えなくなります（移した日に変わる唯一のこと）
  - PRTR の届出の権限と組織の所属は、別途検討するまで今のまま残します
  - 「全体」「移行 1」…のコードは、移す処理が付けます（例：ALL・MIG1）。あとで管理者が直せます
- **組織**: 今は上下が無いので、移したあと管理者が会社の下へ並べ直します。それまでは、上の組織が無いままでも動くようにします。2 つ以上の組織に所属している人は、先頭の 1 つだけを残します（できることは権限グループで引き継がれます）。組織に所属していない人（管理者など）は所属無しのまま移し、あとで管理者が付けます
- 公開検証環境でどんな権限グループができるかを事前に見るには、本番の DB を読む必要があります。反映するときに、読んでよいかを改めて確かめます
