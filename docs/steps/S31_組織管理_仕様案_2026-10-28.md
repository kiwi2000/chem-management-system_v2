# 組織管理 仕様案（白紙からの作り直し）

2026-10-28 作成。前の設計書と仕様確認資料を白紙に戻し、いただいた要件だけから考え直した案です（前の 2 つは同日に削除）。
9 章の 17 個は 2026-10-28 に決めていただき、本文をそれに合わせて直しました。

## 1. いただいた要件

1. 組織は階層になっている。下の組織は必ず 1 つの上の組織に属する
2. 製品は見られても、その組成（組成の手がかりになるものも）を見られない人がいる。よくあるのは、開発部門や管理部門だけが組成を見られる形
3. 人はふつう 1 つの組織に所属するが、複数の組織への所属も認める（管理職が 2 つの部署を受け持つことがあるため）
4. 製品・原材料・物質には、「全社」に所属するものと、特定の組織に所属するものがある
5. 自分の組織の製品・原材料は見られる。ほかの製品・原材料は、権限の設定しだいで見られたり見られなかったりする
6. 利用者が足した物質を、同じ部署の人にしか見せたくない場合もある
7. 上の組織の人の権限は、下の組織の製品・原材料にも及ぶ（部長が、部の製品も課の製品も見られるように）
8. ある組織の人に、ほかの組織（いくつでも選べる）の製品・原材料・物質を「見る」または「編集する」権限を持たせられる

## 2. 仕組みの芯（決まりは 3 つだけ）

| 決まり | 中身 |
| --- | --- |
| ① 何ができるかは、**人と組織に付けた権限**で決まる | 「製品を見られる」「製品を編集できる」「組成を見られる」「物質を編集できる」などの権限は、**人にも組織にも付けられます。**その人ができることは、人に直接付けた権限と、所属する組織に付けた権限の**足し合わせ**です（決定 9）。ただし「全社のデータを作れる」だけは人にしか付けられません（決定 16） |
| ② どのデータに及ぶかは、**組織**で決まる | 製品・原材料・物質にはそれぞれ「所属先」があります。その人の所属と所属先の位置関係、それに組織に付けた「担当先」で、そのデータに手が届くかが決まります |
| ③ 両方そろったときだけできる | 手が届くデータに対して、自分の持っている権限の分だけのことができます |

- 異動したときは、所属を付け替えるだけで、組織に付けた権限も入れ替わります。開発部に「組成を見られる」を付けておけば、開発部に入った人は組成を見られ、出た人は見られなくなります
- 管理職が 2 つの部署を受け持つ場合は、2 つの部署に所属させます（要件 3）。権限は両方の組織の分の足し合わせになり、どちらの部署の製品にも同じように効きます。**一方の組織の権限が、もう一方の組織の製品にも効く**ことに注意します（例：開発部〔組成を見られる〕と品質保証部〔見るだけ〕の兼務の人は、品質保証部を通して届く製品の組成も見られる）。困る組み合わせなら、兼務させずに片方の所属だけにします
- 要件の「製品・原材料」と「物質」を、**同じ決まりで扱います**（一般化した点 1）。物質だけ別の決まりにはしません
- 公開の状態（作成中・承認待ち・公開済み）と有効・無効の決まりは、いままでどおり、これとは別に効きます。両方を満たしたときだけ見えます

## 3. 言葉

| 言葉 | 意味 |
| --- | --- |
| 組織 | 社内の会社・部・課など。**階層に入るのは社内の組織だけです。**帳票の宛先に使う取引先は、いまのまま宛先として残し、階層やデータの所属先には使いません |
| 上の組織・下の組織 | すぐ上の組織は 1 つだけ。下には何段でも組織を作れます。いちばん上（会社）が複数あってもかまいません（グループ会社） |
| 所属 | 人がどの組織にいるか。ふつう 1 つ、兼務なら複数 |
| 所属先 | 製品・原材料・物質がどの組織のものか。**1 つの組織か、「全社」のどちらか** |
| 全社 | データのいちばん大きな所属先。全社に所属するデータには、このシステムを使う全員の手が届きます（いまのデータはすべて全社に所属します）。組織の階層の中の組織ではなく、データの所属先にだけ使う呼び名です（2026-10-28 利用者。前は「全社共通（どこにも所属しない）」と呼んでいた） |
| 組織の権限 | 組織に付ける権限。その組織と、その下の組織（何段下でも）に所属する人全員が、その権限を持ちます（決定 10）。人に直接付けた権限と足し合わせます |
| 担当先 | 組織に付ける設定。「この組織の人は、自分の組織のほかに、あの組織のデータも、自分の組織のデータと同じように扱える」を表します（要件 8）。いくつでも付けられます |

## 4. 製品・原材料・物質に手が届くか

表の ○ は「その権限を持っている人ならできる」という意味です。権限は、人に直接付けたものか、所属する組織に付けたものです。どちらでも持っていなければ、○ でもできません。

### 4-1. 製品・原材料

| データの所属先（自分から見て） | 見る | 組成を見る | 直す |
| --- | --- | --- | --- |
| 全社 | ○ | ○ | ○ |
| 自分が所属する組織 | ○ | ○ | ○ |
| その下の組織（何段下でも） | ○ | ○ | ○ |
| 担当先の組織とその下（何段下でも） | ○ | ○ | ○ |
| 上のどれにも当たらない組織（上の組織・横の組織） | × | × | × |

- 組成を見るには、これまでどおり「製品を見られる」と「組成を見られる」の**両方の権限**が要ります（要件 2）
- 下の組織の人には、上の組織の製品は見えません。会社全体に見せたいものは「全社」に所属させます
- 担当先の組織のデータは、**自分の組織のデータと同じに扱います**（決定 2）。「見るだけ」「直せる」の区別は、担当先には持たせず、その人の権限（人と組織の足し合わせ）で決まります。見るだけにしたい組織には「製品を見られる」だけを付けます
- 担当先は、付けた組織の人だけでなく、**その下の組織の人にも効きます**（決定 4）。品質保証部に担当先を付ければ、その下の課の人にも効きます

### 4-2. 物質

製品・原材料と同じ表です。物質には組成が無いので、「組成を見る」の列はありません。

### 4-3. 所属先を決める・変える

| 場面 | 決まり |
| --- | --- |
| 作るとき | 既定の所属先を、**システム設定で製品・原材料・物質ごとに選べます。**「全社」か「作った人の所属先」で、初めて使うときは全社です（決定 15）。要件 6 の「部署の人にしか見せたくない」会社は、物質を「作った人の所属先」にします（一般化した点 2）。兼務の人は、作る画面で所属のどちらかを選びます |
| あとで変えるとき | 元の所属先と新しい所属先の**両方**を直せる人だけが変えられます。自分の手の届かない所へ押し出したり、よその部署のデータを勝手に引き込んだりできないようにするためです |
| 全社に所属させるとき | **「全社のデータを作れる」権限**を持つ人だけが、所属先を全社にできます（決定 16）。作るときも、あとで全社に変えるときも同じです（組織のデータとして作ってから全社に移す、という抜け道をふさぐため）。**この権限は人にだけ付け、組織には付けられません** |
| 権限が無い人が作るとき | 既定が全社でも、所属先は自分の所属する組織になります。兼務の人は、どちらかを選びます。どこにも所属していない人は、作れません |

### 4-4. 範囲を分けるかどうかの切り替え（決定 11〜14）

会社によっては、全員が全部の製品を見てよい場合があります。そのため、システム設定に**「組織で見える範囲を分ける：する／しない」**を置きます。

| 項目 | 決まり |
| --- | --- |
| 切り替えの単位 | **製品・原材料・物質ごと**に選べます。例：製品・原材料は「しない」、物質だけ「する」（要件 6 の会社） |
| しない | 所属先に関係なく、権限を持つ人は全部のデータに手が届きます（いまのシステムと同じ動き）。**組織に付けた権限は効いたまま**です。切り替わるのは「どのデータに手が届くか」だけです |
| する | この章の 4-1〜4-3 のとおり |
| 初めて使うときの既定 | **する**。ただし、いまのデータはすべて全社に所属するので、所属先を付け直すまでは見え方は変わりません |
| 「しない」の間の所属先 | **「しない」の間も、データの所属先は記録します。**作るときは 4-3 の既定どおりに入り、画面にも出して直せるようにします。「する」に切り替えれば、その所属先で範囲が分かれます |

## 5. 組成の手がかりとして隠すもの（要件 2）

「組成を見る」ができない人には、次のものを出しません。

- 組成の表（成分・含有率・反応前の組成）
- 添付ファイル（原材料の SDS など、組成が書かれていることが多いため）
- 製品の一覧で、CAS 番号や物質名で製品を絞り込む機能
- 判定の内訳（どの成分で当たったか、その含有率）
- 法規制の画面の「この区分に当たる製品」の中の、原因の成分
- 組成を載せた帳票と、データの出力

製品として該当する法規制（規制区分）は見せ、法文物質名は見せません（決定 6。いまの作りのまま。非該当の区分も出しません）。

### 5-1. 組成の中に、手の届かない原材料・物質があるとき（決定 7）

その製品の組成を見られる人にも、自分の手が届かない原材料・物質の行は、**コード（ID）・CAS 番号・名前をすべて伏せ、含有率だけ**を出します。
組成の表には「見せられない成分があります」と表示し、伏せた行があることが分かるようにします。判定はすべての成分で行うので、判定の正しさは変わりません。

## 6. 例

```
○○化学（会社）
├ 開発部 …… 組織の権限：製品を見る・編集・組成を見る
│ ├ 開発一課
│ └ 開発二課
├ 製造部 …… 組織の権限：製品を見る
└ 品質保証部 …… 組織の権限：製品を見る／担当先：○○化学
```

| 人 | 所属 | 権限（どこから来るか） | 扱えるもの |
| --- | --- | --- | --- |
| A さん（開発部長） | 開発部 | 製品を見る・編集・組成を見る（開発部の権限） | 開発部・開発一課・開発二課の製品を見て、組成も見て、直せる。製造部・品質保証部の製品は見えない（要件 5・7） |
| B さん（課長・兼務） | 開発一課と開発二課 | 製品を見る・編集・組成を見る（上の開発部の権限が届く。決定 10） | 両方の課の製品を扱える。上の開発部の製品は見えない（要件 3） |
| C さん | 品質保証部 | 製品を見る（品質保証部の権限） | 担当先によって、会社のすべての製品を見られる。組成の権限が無いので組成は見えず、編集の権限が無いので直せない（要件 2・8） |
| D さん | 製造部 | 製品を見る（製造部の権限） | 製造部と全社の製品を見られる。組成は見えない（要件 2・5） |
| E さん | 開発一課 | 物質を見る・編集（人に直接）。ほかに上の開発部の権限も届く | システム設定で物質を「作った人の所属先」にしてあれば、E さんが足した物質は開発一課のものになる。開発一課の人、上の開発部の A さん、兼務の B さん、担当先の C さんには見え、製造部の D さんには見えない（要件 6） |

| F さん | 製造部 → 開発部に異動 | 製造部の権限 → 開発部の権限 | 所属を付け替えるだけで、組成を見られ、開発部の製品を直せるようになる。製造部の製品は見えなくなる（決定 9） |

全社に所属する製品・原材料・物質は、全員が自分の権限の分だけ扱えます（要件 4）。

## 7. 要件との対応

| 要件 | 満たす所 |
| --- | --- |
| 1 階層 | 3 章「上の組織・下の組織」 |
| 2 組成を見られない人 | 4-1 の「組成を見る」の列と 5 章。組成は、人か組織に付けた「組成を見られる」権限で守る |
| 3 兼務 | 2 章。複数所属し、その全部の分だけ手が届く |
| 4 全社のものと組織のもの | 3 章「所属先」 |
| 5 自分の組織のものは見られる | 4-1 の「自分が所属する組織」の行 |
| 6 部署の人だけの物質 | 4-3 のシステム設定 |
| 7 上の人は下にも及ぶ | 4-1 の「その下の組織」の行 |
| 8 ほかの組織を見る・編集する | 3 章「担当先」と 4-1 の担当先の行。見るか編集するかは人の権限で決まる |

## 8. 前の案から無くしたもの

- 組織ごとの管理者（管理者はいまのシステム管理者だけ）
- 下の組織の人が上の組織のデータを見られる決まり
- 「主な所属」と、所属先とは別の「公開先」という項目（データの所属先は 1 つだけ）
- 範囲の付与の「見る」「直す」を組織どうしの組み合わせで細かく登録する仕組み（組織に付ける担当先にまとめ、段階は持たせない）

お知らせ・ドキュメント・PRTR の届出は、この仕様では変えません。ドキュメントは、もとの製品と組成が見えるかどうかに従うだけです。

## 9. 決めたこと（2026-10-28）

| # | 決めること | 決定 |
| --- | --- | --- |
| 1 | 担当先を何に付けるか | **組織に付ける**。その組織の人に効く |
| 2 | 担当先の段階 | **段階は持たせない。自分の組織のデータと同じ**に扱う。見る・組成を見る・直すは人の権限で決まる |
| 3 | 担当先にした組織の、下の組織にも及ぶか | **及ぶ**。会社を 1 つ選べば、会社全体に届く |
| 4 | 担当先を付けた組織の、下の組織の人にも効くか | **効く** |
| 5 | 全社のデータを直せる人 | **人の権限による**（「編集できる」権限があれば誰でも。いまと同じ） |
| 6 | 組成を見られない人に、法規制の該当を見せるか | **製品として該当する法規制は見せ、法文物質名は見せない**（いまの作りのまま） |
| 7 | 組成の中に、手の届かない原材料・物質があるとき | **見せられない成分があることを表示し、コード（ID）・CAS 番号・名前をすべて伏せ、含有率だけ出す** |
| 8 | 所属先が変わって手が届かなくなったとき、作った本人には見え続けるか | **見えなくてよい** |
| 9 | 異動したら組成の見え方が変わるようにするには | **組織にも権限を付け、人に直接付けた権限と足し合わせる** |
| 10 | 組織に付けた権限が、その下の組織の人にも効くか | **効く**（担当先の決定 4 とそろう。会社に付ければ全員に行き渡る） |
| 11 | 範囲を分けない会社のための切り替え | **システム設定で「組織で見える範囲を分ける：する／しない」を切り替える**。製品・原材料・物質ごとに分ける |
| 12 | 初めて使うときの既定 | **する** |
| 13 | 「しない」に切り替えたときの所属先 | **残す**。「する」に戻せば元の範囲に戻る |
| 14 | 「しない」の間の新しいデータ | **所属先を記録する** |
| 15 | 作るときの既定の所属先（4-3 のシステム設定）の、初めて使うときの値 | **全社** |
| 16 | 全社のデータを作れる人 | **「全社のデータを作れる」権限を持つ人だけ**。製品・原材料・物質に共通の 1 つの権限で、人にだけ付ける |
| 17 | いまの利用者に、その権限を最初から付けるか | **いま「製品を編集できる」か「物質を編集できる」を持つ人全員に付ける**（いまと同じく、編集できる人は全社のデータを作れるままにする）。システム管理者にも付ける |

決定 10 により、上の組織に付けた権限は、下の組織だけ外すことはできません。下の組織で付けたくない権限は、上の組織には付けず、付けたい組織にだけ付けます。

決定 2 により、組成を見られる開発の人がいる組織に、よその部署を担当先として付けると、その人にはよその部署の組成も見えます。組成を見せたくない人がいる組織には、担当先を付けずに済む形（所属を分ける・人の権限を絞る）で対応します。
