# S0〜S3（一部）— 立ち上げ・DB基盤・ログイン・アプリシェル

確定日: 2026-08-13

「まずはログイン画面が出来ていればOK。サイドバーはボタンで開閉」という指示に合わせ、
S0（立ち上げ）・S1（DB基盤）・S2（認証）・S3（アプリシェル）を、ログインが通るところまで通しで実装した。

## できたこと

| 機能 | 内容 |
|---|---|
| ログイン | メール＋パスワード。MFA有効ユーザーは6桁コード欄が出る |
| ログアウト | トップバー右端。DBのセッションを削除しCookieを破棄 |
| パスワード変更 | `/change-password`。変更すると他端末のセッションを全失効 |
| アプリシェル | 左サイドバー＋トップバー。**左上のボタンで開閉** |
| 稼働確認 | `GET /api/health`（認証不要・DB疎通のみ返す） |

## 動作の決めごと（今回の実装値）

1. ログインIDはメールアドレス。小文字化して突合する
2. パスワードは12文字以上・英字と数字を各1文字以上
3. 失敗5回で15分ロックアウト。失敗理由は「メールアドレスまたはパスワードが正しくありません」に統一（アカウントの存在を推測させない）
4. 存在しないユーザーでもダミー検証を走らせ、応答時間から存在を推測させない
5. セッションは12時間。Cookie名 `chem_session`（httpOnly / SameSite=Lax / 本番のみ Secure）
6. セッションはトークン生値をCookie、DBにはSHA-256ハッシュのみ保存
7. 未ログインで画面を開くと `/login` へ、ログイン済みで `/login` を開くと `/` へリダイレクト
8. サイドバー幅 224px。**広い画面（768px以上）は本文を押し出す開閉**、**狭い画面は本文に重ねるドロワー**。どちらもトップバー左端の同じボタンで操作
9. サイドバーの開閉状態は `localStorage: chem.sidebar.open` に記憶（広い画面のみ。狭い画面は毎回閉じた状態から）
10. メニュー項目は未実装の画面も含めて先に並べてある（実装のたびに順次つながる）
11. トップバー右にメールアドレス・権限バッジ・「参照のみ」バッジ・ログアウト
12. 初期セットアップは `npx tsx scripts/set-password.ts <メール> <パスワード> --create`

## ログインしていないときの動き（2026-08-15 追記）

middleware は Edge ランタイムで動くため DB に触れず、**Cookie の有無しか見られない**。
そのため「Cookie は残っているがセッションは無効」（管理者による無効化・権限変更・期限切れ）が素通りし、
シェルの無い画面に「ログインが必要です」とだけ出る状態になっていた。3段構えで塞いだ。

1. **Cookie が無い** → middleware が `/login` へ
2. **Cookie はあるがセッションが無効** → `components/app-shell.tsx`（サーバー側）が `/login?expired=1` へ。
   middleware にパスを `x-chem-path` ヘッダーで渡してもらい、ログイン画面自身は素通しする
3. **画面を開いたまま無効化された** → API が 401 を返した時点で
   `lib/auth-redirect.ts` の `redirectIfUnauthorized()` が `/login?expired=1` へ

`expired=1` を付けるのは**堂々巡りを防ぐため**。middleware は「Cookie あり＋ログイン画面 → ホームへ」
という規則を持つので、この印が無いと 2 の遷移とループする。

**ログイン画面とパスワード変更画面には 3 を入れない**。この2つは 401 を
「パスワードが違う」の意味で使っており、入力ミスでログイン画面へ飛ばされてしまうため。

検証（実測）:
- Cookie を消して `/news` → `/login`
- ログイン中に自分自身を更新（セッション失効・Cookieは残る）してから `/news` → `/login?expired=1` で
  「ログインの有効期限が切れました。もう一度ログインしてください」が出る。ループしない
