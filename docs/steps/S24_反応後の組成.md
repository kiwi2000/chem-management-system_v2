# S24 反応後の組成

> **状態: 実装済み（2026-09-29）。** 製品は製造後に化学反応を起こし、配合したときと違う成分構成になることがある。
> その「反応後の組成」を利用者が入力でき、判定などの計算はすべて反応後に対して行う。反応前は表示だけ。

## 決めたこと（利用者の指示、2026-09-29）

- 反応後を入力しなければ、今のまま（何も変わらない）
- 「反応後の組成入力」を押すと、まず組成を丸ごとコピーし、コピー前のものを**反応前**として保存、編集したものを**反応後**として保存する
- 法規制判定などすべての計算や表示は反応後に対して行う
- 反応前は、とりあえず組成の表示ができるだけでよい
- **反応後の出発点は、原材料展開・CAS 合算がある場合はそちら（物質ごとの表）**（追加指示）
- 実装方法は任せる。「コピーしたほうを反応前としてよい。元の組成を反応後と呼んで既存の編集機能を使えば簡単」（利用者の案。採用）

## 作り

**登録組成（`composition_lines`）を「有効な組成」のまま使い、反応前を別の表に凍結する。**
組成を読む 13 か所（判定・合算・展開・帳票・TSV 出力・一覧の絞り込み・公開・取り込み…）に一切手を入れない。
組成に「反応前／反応後」の印を持たせる作りは、読む側の 1 か所でも印を見落とすと古い組成が計算に混ざるので採らなかった。

| 何を | どこに | 備考 |
| --- | --- | --- |
| 反応前の写し | `product_pre_reaction_lines`（`ProductPreReactionLine`）、移行 `20260929020000_product_pre_reaction_lines` | 列は `composition_lines` と同じ。物質・原材料への参照は Restrict（登録組成と同じ扱いで、写しだけに残っている物質も消させない。`countUsesOfSubstance` / `countUsesAsMaterial` が写しも数える） |
| 印 | `products.pre_reaction_at` / `pre_reaction_by` | 入っていれば登録組成は反応後。空なら従来どおり |
| 始める | `POST /api/products/[id]/composition/pre-reaction` | 組成を編集できる人。登録組成を写し取り → 原材料が含まれていれば `aggregateComposition` の行（代表物質のコードから物質を引く）で登録組成を置き換え、展開できなかった原材料は原材料の行のまま残す → 印を立てる → 展開結果を作り直す → 監査。2 回目は 409 |
| 読む | `GET /api/products/[id]/composition` の `preReaction`（日時・人・行・合計）。`?source=pre-reaction` で写しそのものを組成の形で返す。`…/composition/aggregate?source=pre-reaction` で写しを根にした合算（`aggregateComposition` の `rootLines`） | 写しがある製品だけ。原材料の中身は登録組成から下ろす |
| 画面 | `components/composition-editor.tsx`（`source="pre-reaction"` で自分自身を読むだけの状態で再利用）、`composition-aggregate-table.tsx`（同じ `source`） | 編集中で写しが無いときだけ見出しに「反応後の組成入力」。押すと確認のうえ実行。以後、見出し「組成」の横に「反応後」の印、その下に「反応前組成」のカードを**組成と同じ見た目**で出す（組成の木・原材料展開・CAS 合算・寄与元・インベントリ列・列の出し入れ）。**該当法規制の列と、判定に関わる操作（再計算・差分・要確認・含有率不足）だけ出さない**（判定は反応後に対するものなので。2026-09-29 指示） |

**勝手に決めた点**

- 押す前に確認の窓を出す（戻す手段が無いため）。戻す機能（反応前に戻す）は作っていない
- 見出しの文字は「組成」のまま、横に「反応後」の印。見出しの文字を変えると、開閉の記憶が見出しの文字を鍵にしているため押した瞬間に閉じてしまう
- 権限は組成の編集と同じ（`PRODUCT_EDIT` ＋ 組成を見られる）
- TSV 出力・帳票・取り込みは反応後（登録組成）だけ。反応前は出さない。取り込みで組成を置き換えても反応前の写しはそのまま
- 合算の行を反応後の行にするとき、CAS の無い物質は物質ごとの行、備考は合算の備考（「／」つなぎ）をそのまま

## 反応前について、あると実務で役立ちそうなこと（提案。未実装）

1. **PRTR の届出**は「取り扱った原料」が基準なので、届出の取扱量は反応前組成から数えるのが本来。PRTR の画面で「反応前で計算」を選べるようにする
2. **安衛法**（表示・通知・リスクアセスメント）は製造時に扱う物質が対象。反応前組成に対する法規制判定を「製造時の判定」として別に持つ
3. **化審法の製造数量・新規化学物質**は反応後に生じる物質の話。反応前と反応後の**差分**（消えた物質・生じた物質・残った未反応分）を並べて見せると、届出要否の当たりを付けやすい
4. 配合を変えたときに、反応前を直してから**反応後を作り直す**（反応前をもう一度写し取って反応後を作り直す）操作
5. 反応前の TSV 出力と帳票への出力（原料構成の証明に使う）
6. 反応前組成にも承認の流れを掛けるかどうか（いまは製品の公開状態に従う）
