# S30 SDS 作成 — 要件（2026-10-18 に利用者から預かったもの）

SDS 作成機能（SDS 版のオプション。決定 0016）の要件を 1 か所に集める。GHS 判定の仕様は S25・S27、競合との比較は
`docs/競合調査_NITE-Gmiccs_2026-10-18.md`。ここは「何ができなければならないか」だけを書き、作り方は各ステップの文書に書く。

## 1. 利用者の指示（2026-10-18）

1. **各国版**: 1 つの製品に対して、仕向け先の国ごとの SDS を作る（国のレイヤー＝JIS 2025／JIS 2019／EU CLP／米国 HCS／韓国／中国／台湾 …）
2. **1 つの SDS に対して複数言語**: 国の版と言語を分ける。例: 中国語版の SDS の英訳も作れる（「中国の決まりで作った SDS を英語で読む」）
3. **改版時の差分表示と履歴の保存**: 同じ製品の SDS を改版したとき、前の版との違いを示し、全部の版を残す
4. **SDS の検索**
5. **SDS の配布**: システムの利用者が、自社製品の販売先へ SDS を公開する。**完全公開**（誰でも）と**限定公開**（決めた相手だけ）。**取得履歴**（誰が・いつ・どの版を取ったか）を残す

Gmiccs 調査（2026-10-18）で「取り入れる」と決めた機能:

6. 注意書き（P 文）の 4 段階の絞り込みと、JIS Z 7253 の優先順位による省略の切り替え
7. 標的臓器名の統合
8. JIS／国連の 2 ルールの切り替え（当方はレイヤー。国を増やせる形）
9. 「濃度限界未満でも SDS に書く成分」の提示
10. CSV の入出力を全工程で揃える。**Gmiccs の CSV（組成・成分・分類結果・SDS 要素）の取り込み**

凌駕のための優先策（同調査 §10。利用者が「是非対応」と指示）:

11. 製品の画面に GHS 判定と追える根拠を出す（S27 §5 の 4）
12. 旧 JIS 2019 のレイヤー
13. 物理化学的危険性の計算を選択点つき・根拠つきで広げる
14. ラベル要素の計算とフレーズ辞書、SDS 16 項目の自動化（第 15 項は法規制判定の結果）
15. 他国のレイヤー

## 2. 以前からの決定（S25・S23・記憶）

- SDS の書式はドキュメント生成に組み込む。SDS 版だけの部品を差込口で足す（2026-10-17）
- フレーズ（H 文・P 文・定型文）は辞書（DB）に持ち、編集できる。多言語
- 判定は判定対象日を持つ。規制が変わったら区分を新しく作って古いものも残す
- 外部サービスへの通信はゼロ（翻訳 API も使えない）

## 3. 決めてもらうこと（配布と翻訳。作る前に）

1. **公開の入口**: いまの運用は VPN の中（社内 LAN／Tailscale）で、外の人は入れない。「完全公開」「限定公開」には、インターネットに面した入口が要る。
   候補: (a) 公開用の小さな別サービス（SDS の公開ファイルと取得履歴だけを持ち、本体から押し出す）、(b) 本体そのものを公開する（勧めない。機密の本体を外に向ける）。おすすめは (a)
2. **限定公開の相手の識別**: (a) 相手ごとの合言葉つきのリンク（ログイン不要）、(b) 取引先のアカウント（ログイン）、(c) 両方。取得履歴の精度が変わる。おすすめは (c)（まず (a)、要る相手だけ (b)）
3. **翻訳の手段**: 定型文（H 文・P 文・項目名・決まり文句）は辞書で各言語を持てる。自由文（組成の注記・用途・会社の注意事項など）は、外部の翻訳サービスが使えないので、
   (a) 人が訳して辞書に登録、(b) 社内に置いた翻訳の部品（オフラインの機械翻訳）、(c) 外部サービスの利用を SDS の自由文に限って認める。おすすめは (a)＋(b)（(c) は方針と衝突）
4. **差分の単位**: 項目（16 項目×小項目）ごとの文の差分でよいか。判定の差（区分の変化）は別に強調する

## 4. 進め方（案）

GHS 判定（11）→ 旧 JIS レイヤー（12）→ ラベル要素とフレーズ辞書（14 前半）→ SDS 16 項目（14 後半。各国版・多言語の土台）→ 改版の差分・履歴・検索（3・4）
→ 配布（5。§3 の決定の後）→ 物理化学の拡張（13）→ 他国のレイヤー（15）→ Gmiccs CSV の取り込み（10）。順は作業の都合で入れ替える。
