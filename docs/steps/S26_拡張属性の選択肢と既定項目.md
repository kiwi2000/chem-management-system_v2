# S26 拡張属性の選択肢・測定の条件・既定の項目

- 作成: 2026-10-17
- 置き場所: **標準**（chem・sds の両方）。物質・製品の拡張属性（S5・S7）を広げたもの
- きっかけ: GHS 判定（S25）と SDS に要る性状・毒性値を、最初から入れておく（2026-10-17 指示）

## 決めたこと（2026-10-17 の回答）

| 論点 | 決定 |
| --- | --- |
| A. 項目の範囲 | GHS 判定・SDS に過不足なく。中身はこちらで決めた（下の表） |
| B. 測定の条件 | 値ごとに「条件」の欄を足す。**項目ごとに登録した選択肢から選び、合わないときは「その他」で書く**。選択肢の無い項目は自由に書く |
| C. 選んで入れる種類 | 種類に「選択肢」を足す（物理状態・形状・急速分解性） |
| D. 画面 | 表示のみのときは値の入った項目だけ。編集のときは全部を、まとまりごとに開け閉めできる形で |
| E. 項目の保護 | 最初から入れる項目は「システムの項目」。削除できず、種類も変えられない。名前・単位・表示順・まとまり・選択肢・「使う」は変えられる |

## データの持ち方

- **値の入った項目だけ行を作る**（S5 の決めごと 11 のまま）。空の項目は場所を取らない
- 条件は値の行に 2 列（`condition_code` = 選択肢のコード、`condition_text` = 「その他」の自由記入）。空なら NULL
- 選択肢は `property_options`（`kind` = VALUE / CONDITION）。**コードは保存した値との対応なので変えない**。
  外した選択肢は、使われていれば「使わない」にして残し、使われていなければ消す
- 種類が「選択肢」の値は `value_text` に選択肢のコードを入れる（DB の「片方だけ」の CHECK 制約はそのまま効く）
- 項目に `group`（まとまり）と `system_flag`（システムの項目）を足した
- 既定の項目は移行 `20261017090100_property_defaults` で入れる。**同じキーの項目が既にある環境では、その項目には手を付けない**
  （選択肢も足さない）。管理者が足した項目は、システムの項目にはならない
- 列挙に値を足した移行（`CHOICE`）と、それを使う移行は分けた（足した移行の中では使えないため）

## 画面

- 物質・製品の拡張属性は、まとまり（物理的・化学的性質／健康への影響（毒性）／環境への影響／その他）ごとに開け閉めする
- 表示のみ: 値の入った項目だけを「名前　値 単位（条件: …）」で並べる。1 つも無ければ「入力された項目はありません」
- 編集: 使う項目を全部出す。「使わない」にした項目も、値が入っていれば出す。「使わない」選択肢は、入力済みの値のときだけ選べる
- 製品の拡張属性は、基本情報の最後に移した（項目が増え、上の並びに混ぜると読みにくいため）
- 管理画面（システム › 拡張属性）: 種類「選択肢」、まとまり、選べる値・測定の条件の選択肢の並び、「システムの項目」の印。
  システムの項目は種類を選べず、削除しようとすると断る（ほかに選んだ項目は消す）

## 確かめたこと（2026-10-17・開発環境）

- 物質「鉛」に 物理状態＝固体（20℃・101.3 kPa）、経口 LD50＝4665 mg/kg（ラット）、蒸気圧＝0.13 Pa（その他: 30℃）、急速分解性＝なし を保存 → 200
- 選択肢に無い値（物理状態「液状」）→ 400「『物理状態』は選択肢から選んでください」
- システムの項目の削除 → 409
- 表示のみ・編集の両方の画面と、管理画面の写真を見た
