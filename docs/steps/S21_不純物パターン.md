# S21. 不純物種別（不純物として含む物質の、規制ごとの非該当）

状態: 仕様確定（2026-09-18）／ 実装前

> 呼び名の変更（2026-09-19）: 画面では「不純物パターン」を **「不純物種別」** に改めた（左ペインの項目は「不純物」）。データベースの表・列名（`impurity_patterns` / `impurity_pattern_id`）とコードの識別子（`impurityPattern`）は据え置き。

## 1. 目的

不純物・副生成物として含まれる物質は、規制によっては裾切値以上でも非該当になる
（化審法の届出、K-REACH の登録、TSCA の新規化学物質届出など）。
一方、安衛法の表示・通知、化管法、RoHS のように、不純物でも対象にする規制もある。
いまの判定は含有率と CAS だけで見ているので、この違いを表せず、判定修正で 1 行ずつ直すしかない。

**「不純物種別」を物質の属性として持ち、種別ごとに「どの規制区分・法文物質名で非該当にするか」を
設定できるようにする。**判定はその設定に従い、除外したことを根拠として残す。

## 2. 用語と決めごと

| 用語 | 意味 |
| --- | --- |
| 不純物種別 | 「同じ該非判定になる不純物どうし」をまとめた区分。0「不純物ではない」と 1「不純物」は組み込み（消せない。名前は変えられる）。0 が既定。2 以降は好きなだけ登録できる。たいていの会社は 1 だけで足りる（2026-09-18 決定） |
| 除外 | ある種別の物質を、ある規制区分（または法文物質名）で**必ず非該当**にすること |
| 代表物質 | 同じ CAS × 同じ種別の物質のうち、合算表などに名称を出す 1 件 |

**決めたこと（2026-09-18）**

1. 不純物種別は**物質の属性**にする。組成の行には付けない。不純物として入る物質は、種別ごとに別の物質として登録する（仕入先ごとに同じ CAS を分けるのと同じ扱い）。原材料をたどっても物質の種別がそのまま伝わる
2. CAS 合算は **CAS × 不純物種別** で行う。種別をまたいで足さない。
   「不純物と決めた物質は、その規制に対しては必ず非該当」という運用の前提に立つ（利用者の決定。種別 0 と 1 を足すと閾値を超える、という場合を心配しなくてよい）
3. 代表物質は **CAS × 種別ごとに 1 つ**。合算の行が CAS × 種別なので、その行の名称もその組で決まる
4. 除外の設定は **規制区分単位を基本**にし、**法文物質名単位で両方向に上書き**できる（区分は除外しないがこの法文物質名は除外、その逆も）。法律の行で全区分をまとめて付け外しできる
5. 除外は無条件。POPs の UTC のように許容濃度が付く除外は「その濃度以下で入るものを種別 N にする」と利用者が決めることで表す。濃度の条件はシステムに持たせない（要望が出てから）
6. 権限は、種別と除外の設定が **REGULATION_EDIT**、物質への種別の付与が **SUBSTANCE_EDIT**

## 3. データ

### 3-1. 不純物種別 `impurity_patterns`

| 列 | 内容 |
| --- | --- |
| id, code, code_normalized | コードは一意（`normalizeCode`）。組み込みは id を固定する（0 = `ip-none`、1 = `ip-impurity`。データソースの `src-user` と同じやり方）。code は `0`・`1` |
| name_ja, name_en, note | 名前と説明。0 の名前は「不純物ではない」（変えられる。消せない） |
| display_order | 並び順 |
| builtin | 0 と 1 が true。消せない。0 は除外の設定も持たない |
| created/updated/deleted_at | 論理削除。**物質から使われている種別は消せない**（件数を示して断る） |

移行で 0 と 1 を入れる。`substances.impurity_pattern_id` の既定は `ip-none`。
`product_expansion_lines` にも `impurity_pattern_id` を持ち、一意キーに加える（同じ CAS が種別違いで 2 行になるため）。

### 3-2. 物質 `substances.impurity_pattern_id`

- NOT NULL、既定は 0。既存の全物質は移行で 0
- 代表物質の一意性を **(cas_normalized, impurity_pattern_id)** にする。いまの「CAS ごとに 1 件」の制約を組で持ち直す
- 「同じ CAS の物質が既にあります（合計 N 件）」の警告は、同じ CAS × 同じ種別の中で数える

### 3-3. 除外の設定

| 表 | キー | 列 |
| --- | --- | --- |
| `impurity_exemptions` | (pattern_id, category_id) 一意 | excluded（true＝非該当にする）、note、updated_at/by |
| `impurity_exemption_substances` | (pattern_id, statutory_substance_id) 一意 | excluded（true＝除外する／false＝除外しない。**区分の設定を上書き**）、note、updated_at/by |

- 行が無い＝区分の設定に従う（区分の行も無ければ除外しない）
- 区分・法文物質名を消しても行は残す（区分は論理削除なので参照は切れない）。画面では出さない
- 両方の表を `premisesChangedAt`（要再計算の判定）の対象に入れる

## 4. 判定

`lib/judge-calc.ts` の流れに、次を足す。

1. 展開の各行に、物質の `impurityPatternId` を持たせる
2. **合算の鍵を `cas × pattern`** にする。同じ CAS でも種別が違えば別の行
3. 規制対象 CAS の解決（データソースの合算・優先度）は **種別に関係なく CAS で** 行う。ここは変えない
4. 判定の単位（区分 × 法文物質名、または区分）ごとに、当たった `cas × pattern` の寄与を並べ、
   **pattern ≠ 0 で除外に当たるものを落とす**。除外の判定は「法文物質名の上書き → 区分の設定 → 除外しない」の順
5. 落とした寄与は、結果に **「不純物のため非該当」** として残す（含有率不足による非該当と同じ並び。黙って消さない）。
   同じ単位に除外されない寄与が残っていれば、そちらで閾値と比べる
6. 区分でまとめる区分（`aggregation ≠ NONE`）でも同じ。除外した寄与は区分の合計に入れない
7. **前提（`premiseOf`）に種別を含める。**`<法文物質名>:<cas>@<pattern>,...`。除外の設定を変えると前提が変わり、人の判断は要確認に戻る
8. 物質のスコアは、その物質の種別で除外される区分の点を入れない。不純物の物質は主成分より低い点になる

判定の優先順位: 除外 → 閾値。除外された寄与は閾値と比べない。

## 5. 画面

### 5-1. 法規制 > 不純物種別（新設）

金属換算係数の画面と同じ作り（項目が 3 つなので、一覧の上のフォーム）。

- **上：種別の一覧**。列はコード・名前・説明・使っている物質の数。0 は先頭固定で、削除のチェックが出ない。
  行を選ぶと下の表がその種別の設定になる
- **下：除外の設定**。法律の一覧と同じ階層の表（地域・国・法律 → 区分）。区分の行に **「非該当にする」のチェック**。
  法律の行にもチェックがあり、押すとその法律の全区分をまとめて付け外しする（一部だけ付いていれば中間状態の表示）
- 区分の行の右端に **「例外 N 件」**。押すと、その区分の法文物質名の一覧を出す小画面（絞り込みつき）。
  各行に「区分に従う／除外する／除外しない」の 3 択。例外のある行だけを出す切り替えを付ける
- 種別 0 を選ぶと、下の表は出さず「不純物ではない物質は、データソースの合算で決まります」と出す
- 表の上に、どの種別の設定を見ているかをはっきり出す（バッジ）

### 5-2. 物質

- 登録・編集のフォームに **「不純物種別」の選択**（既定 0）。0 以外を選ぶと、同じ CAS × 同じ種別の物質が既にあれば警告（合計 N 件）
- 一覧に列「不純物種別」と絞り込み（選択肢）。既定では列を出し、0 は空欄で出す（0 ばかりの表を「0」で埋めない）
- 代表物質の印と選び直しは CAS × 種別の中で動く。詳細の「同じ CAS の物質」の一覧にも種別を出す
- 詳細のスコア・ランクは、その種別で除外される区分を除いた値

### 5-3. 製品・組成

- 組成の候補検索の結果に、種別が 0 以外なら **バッジ**（種別のコード）を出す。主成分用と不純物用を選び分けるため
- 組成の表・原材料展開の表でも、0 以外の行にバッジ
- CAS 合算の表は **CAS × 種別** で行を分け、列「不純物種別」を足す（0 は空欄）
- 法規制判定の表に、**「不純物のため非該当」** の印（含有率不足の三角と並ぶ、別の印）。「該当のみ表示」では出ない。
  凡例のボタンで表示の切り替えができる（含有率不足と同じ）

### 5-4. 帳票

- CAS 合算の表（差込の表）に列「不純物種別」を選べるようにする
- 法規制判定の表に「不純物のため非該当」の行を含める／含めないの選択

### 5-5. 外部データベース・法文物質名

- 変更なし。規制対象 CAS の「物質名」は、種別 0 の代表物質の名称を出す（無ければいままでどおり）

## 6. 取り込み・書き出し

- 物質の TSV に列「不純物種別」（コード）。空欄は 0。無いコードは取り込みで断る
- データセット（スナップショット）に種別と除外の設定を含める。評価機で作った設定を本番へ運ぶため
- 当方が配る規制リスト・データセットは、種別は 0 だけ、除外の設定は含めない（お客様の運用で決めるもの）

## 7. 権限

| 操作 | 権限 |
| --- | --- |
| 種別の登録・変更・削除、除外の設定 | REGULATION_EDIT |
| 物質に種別を付ける | SUBSTANCE_EDIT |
| 見る | REGULATION_VIEW / SUBSTANCE_VIEW |

## 8. マニュアル

- 法規制のページに「不純物種別」の節。画面の操作 → 判定での効き方 → 例（化審法の届出は区分ごと、副生 PFOA は法文物質名で上書き）
- 物質のページに「不純物として入る物質は、種別ごとに別の物質として登録する」
- 製品のページの判定の説明に「不純物のため非該当」の印
- 変更履歴はデプロイ時

## 9. 使いやすさのための決め

- 不純物種別の名前は自由（「不純物（化審法届出除外）」のように、意味が分かる名前を付けてもらう）
- 除外の表は、法律で絞り込める。区分が多い法律（安衛法）でも探しやすい
- 除外の付け外しは 1 回ごとに保存する（保存ボタンを押し忘れて設定が残らない、を防ぐ）。左下の「要再計算」がその場で出る
- 種別を消すときは、使っている物質の数を示して断る。付け替えてから消す
- 判定の一覧で「不純物のため非該当」の行を開くと、どの種別のどの設定で除外したかが読める

## 10. 対象外（今回はやらない）

- 濃度の条件付きの除外（UTC の許容濃度など）。種別の割り当てで吸収する
- 組成の行に付ける「判定対象外」（製品 × CAS の除外）。要望が続けば、同じ「由来」の考えで別に作る
- 用途・剤型による除外（保留事項のまま）
