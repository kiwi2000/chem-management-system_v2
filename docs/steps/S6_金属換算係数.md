# S6 — 金属換算係数

確定日: 2026-08-14

## これは何か

「この CAS の物質には、その金属元素が重量で何パーセント含まれるか」を持つマスタ。
規制該当の判定で「金属としての量」を求めるときに使う。

    寄与 = 含有率 × 換算係数 ÷ 100

**CAS番号 × 金属元素 がキー**で、そこから係数を1件引ける。

## データ項目

| 項目 | 型 | 必須 | 備考 |
|---|---|---|---|
| CAS番号 | 20文字 | ○ | ここではキーなので**必ず必要**（システム設定の「CAS任意」は効かない） |
| 金属元素 | 4文字 | ○ | 元素記号。`^[A-Z][a-z]{0,2}$` |
| 換算係数 | Decimal(9,6) | ○ | 重量パーセント。**0 より大きく 100 以下** |

一意制約は `(正規化CAS, 金属元素)`。範囲と元素記号の形は CHECK 制約でも担保している。

## 動作の決めごと

1. **物質マスタとは物理FKで繋がない。** CAS で引ければよく、物質として未登録の CAS でも
   係数を先に持てるようにするため
2. CAS は物質マスタと同じ `normalizeCas()` で正規化する。**全角で入力しても同じ行になる**
3. 物質として未登録の CAS を登録すると**警告**を出す（保存は通す）。打ち間違いに気づけるように
4. 一覧には「該当する物質」列があり、その CAS を持つ物質へのリンクを出す。
   同じ CAS を複数の物質が持てるので**複数出ることがある**
5. 同じ組み合わせを登録しようとすると 409
6. **削除（論理削除）した組み合わせを登録し直すと、その行を復活させて内容を更新する。**
   キー自体を退避させると意味が壊れるため、物質マスタとは違うやり方にした（`docs/decisions/0005` の例外）
7. 編集でキーを変えるとき、その組が論理削除済みなら先に片付けてから入れ替える
8. 項目が3つだけなので、別画面にせず**一覧の上のフォームで追加・編集**する

## 検証結果（実測）

- 登録: `7439-92-1 / Pb / 100` → 201、警告なし。一覧の「該当する物質」に **pb-001 と PB-002 の2件**が並ぶ
  （同一CASを複数物質が持つケースが正しく出る）
- 全角: `１３１４－４１－６` で登録 → `1314-41-6` として保存される
- 未登録CAS: `1333-82-0 / Cr` → 201＋「このCAS番号の物質は登録されていません」の警告
- 重複: 同じ `7439-92-1 / Pb` → 409
- 範囲外: `120` → 400「0 より大きく 100 以下で入力してください」／`0` も 400
- 元素記号: `cd`（小文字）→ 400「元素記号で入力してください」
- **復活**: 削除 → 同じ CAS×元素 で再登録 → 201、`id` が削除前と同じ、「復活させました」の警告
- 編集: 一覧の「編集」でフォームに値が入り、係数を 90.66 → 92.83 に更新できる
- 共通テーブル: 換算係数（数値列）で降順ソート → `100, 92.83, 52.5`。
  「以上 90」で絞ると 2件。URL は `?sort=ratioPct:desc&f.ratioPct=gte:90`
- 権限: 閲覧のみ → GET 200 / POST・PUT・DELETE 403、画面にフォームも操作ボタンも出ない。
  法規制権限が無いユーザー → GET も 403
- 前回の絞り込みが復元されることも確認（閲覧のみユーザーで開いたとき 2件のまま）
- 英語表示、モバイル幅375pxで横スクロールなし
- typecheck / lint / prettier / build / テスト79件すべて通過

## 共通テーブルで見つけて直したこと

**演算子を先に選ぶと、値を入れる前にリセットされていた。**
「以上」を選んでから数字を入力するのが自然な順序なのに、`eq` に戻ってしまっていた。
値が空でも選んだ演算子を覚えておくように直した（`components/data-table/filter-cell.tsx`）。
共通部品なので全一覧に効く。
