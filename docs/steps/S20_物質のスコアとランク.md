# S20 物質のスコアとランク

2026-09-02 実装。物質そのものに**点数**を付け、それを**段階**に読み替える。

## 1. 何をするものか

| | |
| --- | --- |
| **規制区分のスコア** | 人が決める評価点。任意の数値。既定は 0 |
| **物質のスコア** | その物質が当たっている規制区分の、スコアの**合計** |
| **物質のランク** | スコアを段階に読み替えたもの。対応表はシステム設定 |

**製品とは関係しない。**含有率も組成も見ない、物質そのものに付く値。
製品の該非判定（`judge-calc.ts`）とは別の仕組みで、互いに影響しない。

## 2. 合計の数え方（決めたこと）

- **「当たっている」は、現在のバージョンのCASリンクがあること。**閾値は見ない
- **同じ区分は1回だけ数える。**同じ区分に法文物質名が2つあっても2回足さない
- **「判定に使う」印の付いた区分だけ**を合計する（2026-09-02 利用者の判断）。
  印を外した区分（VOCから除かれる物質、水質の水素イオン濃度等）は入らない。
  スコア用の印を別に作らず、既にある印をそのまま使う
- 非該当で確定させたリンク（`excluded`）は数えない
- CAS番号を持たない物質も対象。合計は 0 になり、0点として段に当たる
- 削除済みの物質は対象外

## 3. ランクの当て方

段は**何段でも**登録できる。名前は数字でなくてよい（`A` `要注意` など）。

```
物質スコア          ランク
0 ≦ x < 30         0
30 ≦ x < 70        1
70 ≦ x            2
```

- 上下の境目は**値と不等号**で持つ。`以上 / を超える`、`未満 / 以下` を段ごとに選ぶ。
  隣どうしで同じ値を使えるようにするため（`… < 30` の次が `30 ≦ …`）
- 値が空なら、その側に限りが無い
- **並び順に見て、最初に当てはまった段を採る。**重なっていても結果が1つに決まる
- **上下とも空の段は受け皿**になる（「その他」）
- どの段にも当てはまらなければ、ランクは空欄
- 段が1つも無ければ、全員のランクが空欄

境目の重なり・穴・使われない段は、設定画面で**気づきとして出すだけ**。保存は止めない。
境目の決め方は業務の都合で決まるもので、機械が正しさを決められないため。

## 4. いつ計算されるか

| きっかけ | 範囲 |
| --- | --- |
| 規制区分の**スコア**または**「判定に使う」印**を保存した | その区分に当たっている物質だけ |
| 物質を**登録**した | その1件 |
| 物質の**CAS番号を変えた** | その1件 |
| **ランクの対応表**を保存した | 全物質 |
| 管理画面の「全物質のスコアを計算し直す」 | 全物質 |
| `scripts/rescore.ts` | 全物質 |

**全件でも数秒。**1文のSQLでCAS番号ごとの合計を出し、同じ値の物質はまとめて書く
（6万件・3〜6秒。1件ずつ引くと本番のトンネル越しに何十分もかかる）。

取り込みスクリプトでCASリンクを入れ替えたあとは、`scripts/rescore.ts` を流すこと。
**スクリプト側からは自動では走らない。**

## 6. 決めた理由

**区分のスコアの既定を 0 にした。**null にすると「まだ付けていない」と「0点」を
区別することになり、合計のたびに扱いを決めることになる。0 なら合計を動かさない。

**物質のスコアは書き込む（その場で数えない）。**一覧で6万件を並べ替え・絞り込みするので、
表示のたびに56万件のリンクを数えると間に合わない。

**入れられる範囲はシステム設定で決める。**点の付け方は運用側の話で、
こちらが上限を決め打ちすると使えなくなる。範囲の検査は**サーバーで行う**
（範囲を狭めたあとに、前から入っていた値がそのまま保存されるのを防ぐため）。

**区分のスコアの範囲は、画面へサーバーコンポーネントから渡す。**
システム設定は管理者しか見られないので、APIを緩めずに必要な2つの値だけを渡す
（CLAUDE.md §4・`app/laws/page.tsx`）。

## 7. まだしていないこと

- 製品の側でスコアを使う（合計・平均・最大など）。**物質固有の値**という指示なので手を付けていない
- スコアの履歴。いまは最後に計算した値だけを持つ
- ランクによる絞り込みの選択肢（いまは文字として絞り込む）
