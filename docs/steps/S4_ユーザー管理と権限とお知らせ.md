# S4 — ユーザー管理・権限・お知らせ

確定日: 2026-08-14

権限の考え方は `docs/decisions/0003` を参照。ここには画面と動作を書く。

## 権限（13種類）

| グループ | 権限 | 備考 |
|---|---|---|
| 製品 / 原材料 | 製品を見られる | 規制該当の判定・逆引き検索を含む |
| | 非公開の製品も見られる | |
| | 製品を編集できる | 組成の編集・TSV取込を含む |
| 組成 | 組成を見られる | |
| | 非公開の組成も見られる | |
| 物質 | 物質を見られる / 編集できる | |
| 法規制 | 法規制を見られる / 編集できる | 編集は金属換算係数・情報源・リンクバージョンを含む |
| データの持ち出し | データを出力できる | TSV出力・帳票ダウンロード |
| お知らせ | 投稿できる | 自分の投稿は編集・削除できる |
| | 他人のお知らせも編集・削除できる | 投稿権限を含意する |
| システム | システム管理 | ユーザー・設定・監査ログ |

## 動作の決めごと

1. 権限の含意は**付与時に展開して保存する**。画面のチェックも連動する（前提を外すと依存側も外れる）
2. プリセットは「閲覧のみ / 一般担当 / 法規制担当 / システム管理者 / すべて外す」。押すと一括でチェックが入る
3. メニューは**権限の無い項目を出さない**。直接URLを開いても、サーバー側で確認して中身を描画しない
4. トップバーのバッジは、管理者なら「管理者」、何も編集できないなら「参照のみ」
5. ユーザー作成時は初期パスワードを管理者が決め、**初回ログインで変更を強制**する
6. パスワード再発行・権限変更・無効化をすると、**対象ユーザーのセッションを全て切る**
7. 締め出し防止: 自分から管理権限を外せない／自分を削除できない／管理者が0人になる操作は拒否
8. ユーザーの削除は論理削除（`deleted_at`）
9. 権限の付与・変更・削除・パスワード再発行はすべて監査ログに残す

## お知らせ

10. 閲覧は**全ログインユーザー**。投稿だけを権限で絞る
11. ホームの本文に**掲載中のものを最大5件**、重要なものを先頭にして表示する
12. 状態は「下書き / 公開」。**下書きは、その投稿を編集できる人にしか見えない**
13. 掲載期間は開始日・終了日を日付で指定。空欄なら制限なし。終了日は**その日いっぱい**含む
14. 「重要」を付けると一覧・ホームの先頭に固定される
15. タイトル・本文は日本語必須、英語は任意。**英語が未入力なら英語表示でも日本語を出す**
16. 本文の改行はそのまま表示する

## 画面

- `/admin/users` 一覧（メール・表示名・権限数・最終ログイン）／`/admin/users/new` 作成／`/admin/users/[id]` 編集＋パスワード再発行
- `/news` 一覧／`/news/new` 作成／`/news/[id]` 編集
- ホーム `/` に掲載中のお知らせ

## 検証結果（実測）

- **含意の自動展開**: `PRODUCT_EDIT` だけ指定してユーザー作成 → 保存結果は
  `["PRODUCT_VIEW","PRODUCT_EDIT","COMPOSITION_VIEW","NEWS_POST"]`
- **画面の連動**: 「製品を編集できる」にチェック → 製品を見る・組成を見るが自動で入る。
  「組成を見られる」を外す → 製品を編集できるも外れ、製品を見られるは残る
- **権限の強制（curl）**
  - 閲覧のみユーザー → `GET /api/admin/users` = 403、`POST /api/news` = 403、`GET /api/news` = 200
  - 投稿ユーザー → 自分の投稿の編集 = 200、他人の投稿の編集 = 403、削除 = 403
- **締め出し防止**: 自分から ADMIN を外す = 409、自分を削除 = 409。権限は変わらないままであることを確認
- **メニューの出し分け**: 閲覧のみユーザーでは 製品 / TSV取込 / ドキュメント生成 / ユーザー管理 が消え、
  「参照のみ」バッジが出る
- **画面のガード**: 権限の無いユーザーが `/admin/users` を直接開くと、一覧を描画せず「権限がありません」だけを表示
- **お知らせ**: 投稿 → ホームに「重要」バッジ付きで表示、改行も保持。日英切替で英語タイトル・本文に切り替わる
- **認可の呼び忘れ検出**: 認可を通さない route.ts を1本置いてテストを実行 → 期待どおり失敗することを確認（その後削除）
- typecheck / lint / prettier / build / テスト20件すべて通過
