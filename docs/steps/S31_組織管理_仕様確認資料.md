# 組織管理 仕様確認資料

2026-10-28 作成。公開先の呼び名は「全体に公開」（2026-10-28 利用者。前の資料では「全体で共通」）。組織管理（組織の階層・権限の受け継ぎ・データの見える範囲）を作る前に、仕様を確かめていただくための資料です。

## 1. 何のために作るか

いまのシステムでは、登録した製品・原材料は（公開すれば）**全員に見えます**。会社が大きくなると、次のことができません。

- 部署ごとに製品を分け、ほかの部署には見せない
- 子会社・グループ会社の製品を、親会社の担当者だけが見る
- 化学物質管理の部署が、全部署の製品をまとめて見る（直すのは各部署）
- 異動のたびに、人の権限を 1 つずつ付け直さずに済ませる

そこで、組織を**会社 → 部署 → 課**のような階層にし、権限と「見える範囲」を組織に付けられるようにします。

## 2. いまと、これからの違い

| | いま | これから |
| --- | --- | --- |
| 組織 | 平ら（会社・部署・取引先が横に並ぶだけ） | 階層にできる（親は 1 つ、何段でも） |
| 人の所属 | 何件でも所属できる | 同じ。そのうち 1 つを「主な所属」にする |
| 権限 | 人にだけ付ける | 人にも組織にも付けられる。上の組織に付けた権限は下の組織の人にも効く |
| 製品・原材料 | 公開すれば全員に見える | 公開先（「全体に公開」か、組織 1 つ）を持つ。公開先の線上の人だけに見える |
| 他部署のデータを見る | （区別が無いので全部見える） | 「範囲の付与」で、特定の組織にほかの組織のデータを見せる・直させる |
| お知らせ | 組織とは別の「グループ」宛て。1 人 1 グループ | 組織宛てにまとめる。上の組織宛てのお知らせは下の組織の人にも届く |
| 管理者 | 全部見える | 同じ（全部見える）。管理者の権限を組織に付けることもできる |

**入れた日に、誰の見え方も変わりません。**いまある製品はすべて「全体に公開」になり、組織にはまだ何も付いていないためです（11 章）。

## 3. 言葉

| 言葉 | 意味 |
| --- | --- |
| 組織 | 会社・部署・課・取引先など。階層にできる |
| 親・下の組織 | 組織のすぐ上が親。親は 1 つだけ。その下に何段でも組織を作れる |
| トップ | 親の無い、いちばん上の組織。会社が複数あれば、トップも複数 |
| 線上 | ある組織から見て、上（親・その親…）、自分、下（子・その子…）の組織。横の枝は入らない |
| 種別 | 会社・部署・取引先・その他。**呼び名にすぎず、階層の意味は持たない**（部署の下に会社を置いてもよい） |
| 所属 | 人がどの組織に属するか。複数可 |
| 主な所属 | 所属のうちの 1 つ。新しく製品を作るときの公開先の既定に使う |
| 公開先 | 製品・原材料ごとに 1 つ。「全体に公開」か、組織を 1 つ |
| 範囲の付与 | ある組織に「別の組織（とその下）の製品を見られる／直せる」を付けること |
| 管理者 | システム管理の権限を持つ人。全部見える |

## 4. 組織の作り方

### 4-1. 組織の決まり（決定）

- 親は 1 つ。何段でも作れる
- 同じ親の下に、同じ名前の組織は作れない（トップどうしも同じ名前は不可）。別の親の下なら同じ名前でもよい（例：A 社の「営業部」と B 社の「営業部」）
- 種別（会社・部署・取引先・その他）は、いままでどおり選ぶ。階層の意味は無い
- 組織の自由項目（住所など、帳票の差出人に使うもの）はいままでどおり

### 4-2. 組織を無効にする・消す

| 操作 | 動き |
| --- | --- |
| 無効にする | その組織とその下の組織は、権限も範囲の付与も**効かなくなる**。所属する人の、本人に付いた権限は残る（決定） |
| 無効にした組織が公開先のデータ | **消えない。**上の組織の人・範囲の付与を受けた組織・管理者からは見え続ける（仮決め） |
| 消す | 次のどれかが残っていると消せない：下の組織、所属している人、公開先にしている製品、宛先にしているお知らせ、PRTR の届出データ、範囲の付与。先に付け替えてから消す（決定） |

### 4-3. だれが組織を直せるか

| 操作 | できる人 |
| --- | --- |
| 組織を作る、名前・種別・自由項目・表示順を直す、有効・無効を切り替える | 「組織を作れる・直せる」権限を持つ人（いまと同じ） |
| 親を付け替える（木の形を変える） | **管理者だけ**（仮決め） |
| 組織に権限を付ける・外す | **管理者だけ**（仮決め） |
| 範囲の付与を付ける・外す | **管理者だけ**（仮決め） |
| 人の所属を変える | 管理者だけ（いまと同じ。ユーザー管理の中） |

親の付け替え・権限・範囲を管理者だけにするのは、**抜け道を防ぐため**です。たとえば「組織を直せる」だけの人が、自分の組織を管理者の組織の下へ移せてしまうと、自分が管理者の権限を受け継いでしまいます。

## 5. 人と所属

- 1 人が複数の組織に所属できる（いまと同じ）。権限と見える範囲は、**所属するすべての組織の分の足し合わせ**
- 所属のうち 1 つを「**主な所属**」にする。使い道は「新しく製品・原材料を作るときの公開先の既定」だけ
- 異動したら、所属を付け替えるだけ。組織に付けた権限と範囲がそのまま付け替わるので、人の権限を 1 つずつ直す必要はない
- 人に直接付けた権限も、いままでどおり使える（例外の調整に使う）

## 6. 権限（何ができるか）

### 6-1. 権限の出どころ

| 出どころ | 効くか |
| --- | --- |
| 本人に付けた権限 | 効く（いまと同じ） |
| 所属する組織に付けた権限 | 効く |
| 所属する組織の上（親・その親…）に付けた権限 | 効く。**上で付けた権限は下の組織の人全員に効く** |
| 所属する組織の下に付けた権限 | 効かない（下で付けたものは上へは効かない） |
| 横の枝の組織に付けた権限 | 効かない |
| 無効にした組織（とその下）に付けた権限 | 効かない |

- 「禁止」の設定は作りません。どこか 1 か所で許可されていれば許可です。だから**上と下で食い違うことがありません**（決定）
- 上の組織で付けた権限を、下の組織だけ外すことはできません。外したい組織があるなら、上には付けず、付けたい組織にだけ付けます
- 権限の種類（「製品を見られる」「製品を編集できる」「組成を見られる」など 24 種類）は変わりません

### 6-2. 権限の変更が効く時

- 組織の権限を変えると、**その組織の人の次の操作から**効きます。ログインし直す必要はありません
- 人に直接付けた権限を変えたときは、いまと同じく、その人のログインが切れます（入れ直し）

## 7. 製品・原材料が見えるか・直せるか

### 7-1. 基本の決まり

**見るには「製品を見られる」権限、直すには「製品を編集できる」権限が、いままでどおり要ります。****組成を見るには、「製品を見られる」権限に加えて「組成を見られる」権限も要ります**（製品が見えるだけでは組成は見えない。2026-10-28 利用者）。そのうえで、製品の公開先と、自分の所属の位置関係で決まります。

| 製品の公開先 ＼ 自分の所属 | 同じ組織 | その上の組織 | その下の組織 | 横の枝 | 範囲の付与「見る」を受けた組織 | 範囲の付与「直す」を受けた組織 | 管理者 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 全体に公開 | 見る○ 直す○ | 見る○ 直す○ | 見る○ 直す○ | 見る○ 直す○ | 見る○ 直す○ | 見る○ 直す○ | 見る○ 直す○ |
| 組織 X | 見る○ 直す○ | 見る○ 直す○ | 見る○ 直す○ | 見る× 直す× | 見る○ 直す× | 見る○ 直す○ | 見る○ 直す○ |

- **同じ縦の線上にいる人は見える**のが芯です。上の人は下の組織の製品を見られ、下の人は上の組織に公開された製品を見られます。横の枝だけが見えません
- 下の人が上の公開先を見られるのは、「トップ（会社）に公開」が「同じ会社の全員に見える」という意味になるようにするためです
- 公開状態（公開済み・作成中・承認待ち）と有効・無効の決まりは、これとは別に**いままでどおり**効きます。未公開のものは「無効・未公開のデータも見られる」権限を持つ人か、作った本人だけ。**両方の決まりを満たしたときだけ見えます**
- 「無効・未公開のデータも見られる」権限があっても、**見える範囲の外の製品は見えません**（範囲はゆるまない）

### 7-2. 作るときの公開先（決定）

| システム設定（製品と原材料で別々に選ぶ） | 作るときの既定 | 手で変えられる先 |
| --- | --- | --- |
| 全体に公開 | 全体に公開 | 自分の線上の組織のどれか |
| 組織内のみ | **主な所属のトップ**（会社） | 同上。トップより下の組織に限るときは手で選ぶ |

- 製品と原材料の区別は、いまの「原材料として使える」の印で見ます
- いまある製品は、すべて「全体に公開」になります。必要なものから手で変えます

### 7-3. 公開先を変える

- 元の公開先と新しい公開先の**両方**を、自分が直せる範囲に持っているときだけ変えられます（仮決め）
- 自分の範囲の外へ押し出す（自分も見えなくなる）、外から引き込む（他部署の製品を自分のものにする）を防ぐためです
- 作った本人は、ほかの人が公開先を自分の範囲の外へ変えても、**見え続けるかどうかが要決定**です（13-1）

### 7-4. 組成・添付・判定・帳票

| もの | 見え方 |
| --- | --- |
| 組成の中身 | 製品が見えて（見える範囲の中で「製品を見られる」権限がある）、**かつ「組成を見られる」権限**があるとき。製品が見えるだけでは組成は見えない（いまと同じ決まりに、範囲が加わる） |
| 添付ファイル・判定の結果・帳票 | 製品に従う。製品が見えなければ出ない |
| 製品の組成に、見えない原材料（横の枝に公開）が入っている | その原材料は「開けない原材料」になる。中身は出ず、合算と判定は「要判断」の印が付く（いまの「開けない原材料」と同じ扱い） |
| 物質・法規制・インベントリ・金属換算係数などの共通のデータ | 範囲の対象にしない。いままでどおり権限だけで決まる（決定） |

部署をまたいで使う原材料は「全体に公開」に、同じ会社の中だけで使うなら「トップ」に公開するのが素直です。

## 8. 範囲の付与（ほかの組織のデータを見せる）

化学物質管理の部署のように、**自分の線上でない組織のデータも見る必要がある組織**に付けます（決定）。

- 付け方：「どの組織が」「どの組織（とその下）を、または全部を」「見る／直す」
- 付与を受けた組織の下の組織の人にも効きます（権限と同じく上から下へ）
- **連鎖しません。**A 組織が B 組織を、B 組織が C 組織を見られても、A 組織は C 組織を見られません（仮決め）
- 「直す」付与があっても、実際に直すには「製品を編集できる」権限が要ります
- お知らせには効きません（お知らせはデータではなく連絡なので、9-2 の決まりで届く）

## 9. 管理者・お知らせ・帳票・PRTR

### 9-1. 管理者

- 管理者は**全部見えて、全部直せます**（いまと同じ。決定）
- 管理者の権限は、人にも組織にも付けられます。「管理者」という組織を作り、そこに所属させる使い方ができます（決定）
- **管理者が 0 人になる操作は拒否します。**組織から受け継いだ管理者も数えます（仮決め）。拒否するのは、組織から管理者の権限を外す、組織を無効にする・消す、所属を外す、人を無効にする、人から管理者の権限を外す、のうち最後の 1 人が消える場合です
- 万一締め出されたときの復旧の手順（サーバーで管理者の権限を付け直す）は、いまと同じに使えます

### 9-2. お知らせ（決定：組織にまとめる）

| | いま | これから |
| --- | --- | --- |
| 宛先 | お知らせのグループ（組織とは別） | 組織、または全員 |
| 読めるもの | 自分の 1 グループ宛て ＋ 全員宛て | 全員宛て ＋ 所属する組織宛て ＋ その上の組織宛て |
| 投稿できる先 | — | 所属する組織とその下（「お知らせを投稿できる」権限）。「他人のお知らせも編集・削除できる」権限なら全部 |

- 1 人 1 グループの制限は無くなります
- いまのお知らせのグループは、**同じ名前のトップの組織**として移し、グループの人をその組織に所属させます。そのときの組織の種別が**要決定**です（13-4）

### 9-3. 帳票の差出人

帳票の差出人（自社の名前・住所など）に使う組織の決め方が**要決定**です（13-2）。

### 9-4. PRTR の届出データの入力

いまは「自分の所属する組織の分だけ」入力できます。上の組織の人が、下の組織の分も入力できるようにするかが**要決定**です（13-3）。

## 10. 例で確かめる

次の木で、全員が「製品を見られる」「製品を編集できる」を持っているとします。

```
A社（トップ）
├─ 営業部
│   ├─ 営業1課
│   └─ 営業2課
└─ 技術部
    └─ 化学物質管理課   ← 範囲の付与「全部を見る」
B社（トップ）
```

| 人 | 所属 |
| --- | --- |
| 甲 | 営業1課 |
| 乙 | 営業部 |
| 丙 | 技術部 |
| 丁 | 化学物質管理課 |
| 戊 | B社 |
| 己 | 管理者 |

| 製品 | 公開先 |
| --- | --- |
| P1 | 全体に公開 |
| P2 | A社 |
| P3 | 営業部 |
| P4 | 営業1課 |
| P5 | 営業2課 |
| P6 | B社 |

誰に何が見える・直せるか（○ 見る＋直す、△ 見るだけ、× 見えない）

| | P1 共通 | P2 A社 | P3 営業部 | P4 営業1課 | P5 営業2課 | P6 B社 |
| --- | --- | --- | --- | --- | --- | --- |
| 甲（営業1課） | ○ | ○ | ○ | ○ | × | × |
| 乙（営業部） | ○ | ○ | ○ | ○ | ○ | × |
| 丙（技術部） | ○ | ○ | × | × | × | × |
| 丁（化学物質管理課） | ○ | ○ | △ | △ | △ | △ |
| 戊（B社） | ○ | × | × | × | × | ○ |
| 己（管理者） | ○ | ○ | ○ | ○ | ○ | ○ |

- 甲は自分の線上（A社・営業部・営業1課）の製品が見える。横の営業2課（P5）は見えない
- 乙は営業部の下（営業1課・営業2課）も見える
- 丙は技術部なので、営業部の枝（P3〜P5）は見えない
- 丁は範囲の付与で全部見えるが、直せるのは自分の線上（P1・P2）だけ。付与を「直す」にすれば全部直せる
- 戊は別の会社なので、A社の製品は共通の P1 しか見えない
- 丁が営業部に異動したら、所属を付け替えるだけで乙と同じ見え方になる

権限の受け継ぎの例：A社に「組成を見られる」を付けると、A社の全員（甲・乙・丙・丁）が組成を見られる。営業部にだけ付けると、乙と甲（営業1課は営業部の下）だけが見られる。B社の戊には効かない。

## 11. 入れた日に何が起きるか

| もの | 入れた日の状態 |
| --- | --- |
| 組織 | いまの組織がすべてトップになる（親なし）。木の形はあとで管理者が組む |
| 組織の権限・範囲の付与 | 何も付いていない |
| 主な所属 | 所属が 1 つの人はそれ。複数の人は、いまの並び（種別と表示順）の先頭 |
| 製品・原材料の公開先 | すべて「全体に公開」 |
| お知らせのグループ | 同じ名前のトップの組織になり、グループの人がその組織に所属する。お知らせはその組織宛てになる |
| 見え方・できること | **誰も変わらない**（変わらないことを試験で確かめてから出す） |

## 12. 増える画面・変わる画面

| 画面 | 中身 |
| --- | --- |
| 組織の一覧 | 木の形（入れ子）で見せる。組織を作るときに親を選ぶ |
| 組織の権限・範囲（管理者だけ） | 組織に付ける権限、範囲の付与（どの組織を、見る／直す） |
| ユーザー管理 | 所属に「主な所属」の印。「この人に効いている権限と、その出どころ（本人・どの組織から）」の表示 |
| 製品・原材料 | 公開先を選ぶ欄（全体に公開／自分の線上の組織）。一覧に公開先の列と絞り込み |
| システム設定 | 製品・原材料それぞれの公開先の既定（全体に公開／組織内のみ） |
| お知らせ | 宛先を組織から選ぶ |
| マニュアル | 「組織」「だれが何をできるか」の説明を足す |

## 13. 決めていただくこと（要決定）

### 13-1. 作った本人の見え方

ほかの人が製品の公開先を、作った本人の見える範囲の外へ変えたとき、作った本人には見え続けるか。

| 案 | 動き | 良い点 | 気になる点 |
| --- | --- | --- | --- |
| **見え続ける（推奨）** | 作った本人は、公開先に関係なく自分の作った製品を見られる | 自分の作ったものが急に消える驚きが無い。いまも「作った本人は未公開でも見える」ので、それとそろう | 異動・退職した人に、元の部署の製品が見え続ける（人を無効にすれば止まる） |
| 見えなくなる | 公開先の範囲だけで決まる | 範囲の決まりが 1 つで分かりやすい | 作った人が自分の製品を見失う |

### 13-2. 帳票の差出人に使う組織

| 案 | 動き |
| --- | --- |
| **いままでどおり（推奨）** | 所属する組織のうち、種別で絞って表示順の先頭（いまの帳票の作りを変えない） |
| 主な所属 | 主な所属の組織を差出人にする |

### 13-3. PRTR の届出データの入力

| 案 | 動き |
| --- | --- |
| **下の組織の分も入力できる（推奨）** | 上の組織の人は、所属する組織とその下の組織の分を入力できる（権限が上から下へ効くのとそろう） |
| いままでどおり | 所属する組織の分だけ |

### 13-4. お知らせのグループを組織に移すときの種別

| 案 | 動き |
| --- | --- |
| **その他（推奨）** | 種別は「その他」。名前はグループの名前のまま |
| 部署 | 種別を「部署」にする |
| 移したあと手で直す | 一度「その他」で移し、管理者が木の中の正しい場所へ付け替える |

## 14. 仮決めの確認（変えたければ言ってください）

1. 範囲の付与は連鎖させない（8 章）
2. 無効にした組織のデータは消さず、上の組織・範囲の付与を受けた組織・管理者からは見え続ける（4-2）
3. 親の付け替え、組織への権限・範囲の付与は管理者だけ（4-3）
4. 公開先を変えるには、元と新しい公開先の両方を直せる範囲に持っている必要がある（7-3）
5. 管理者が 0 人になる操作は、組織から受け継いだ管理者も数えて拒否する（9-1）
