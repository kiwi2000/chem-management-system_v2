# S22. PRTR 集計と届出（事業所ごとの排出量・移動量）

状態: 仕様確定（2026-09-20、同日 2 回目の確認で追記）／ 実装前

## 1. 目的

化管法の PRTR 届出は、**事業所ごと・年度ごと・第一種指定化学物質ごと**に、排出量（大気・公共用水域・
土壌・埋立）と移動量（下水道・廃棄物）を、翌年度の 4/1〜6/30 に届け出る。届出要否は、事業所での
年間取扱量が 1 トン以上（特定第一種は 0.5 トン以上）で決まる。

いまの本システムは製品ごとの該非までしか持たず、事業所という単位も無い。
**各事業所が製品の購入数量・出荷数量を登録すれば、本システムが組成と該非判定から物質ごとの量を集計し、
届出書（本紙・別紙）と、NITE の PRTR 届出システムに読み込ませる XML を出せる**ようにする。

## 2. 用語と決めごと

| 用語 | 意味 |
| --- | --- |
| 事業所 | 届出の単位。会社の中の工場・営業所。利用者はどれか 1 つの事業所を担当する |
| 事業者 | 届出者。原則 1 つだが、組織マスタに登録してある会社から選べる |
| PRTR 管理者 | 全事業所の登録内容と集計を見られ、業種・主務大臣・事業者の情報を登録する人 |
| 年度 | 4 月〜翌 3 月。届出の対象年度は「前年度」。**数量も値も、登録するときに年度を指定する** |
| 数量 | 事業所 × 年度 × 製品の購入数量と出荷数量。**kg**。単位の欄は持たない |
| 取扱量 | 購入数量 × 含有率 を製品にわたって足した、物質ごとの量。届出要否の判断に使う |
| 残量 | （購入数量 − 出荷数量）× 含有率 の合計。物質収支の元になる量 |
| 管理番号 | 届出で物質を指す 3 桁の番号。**政令番号とは別**（第 4 章） |
| 方法 | 排出量・移動量の出し方。実測値・物質収支・排出係数の 3 つ。**事業所が年度ごとに 1 つ選ぶ** |
| 届出データ | 事業所 × 年度の届出書 1 通ぶん。提出日・主務大臣・業種・担当者などをフォームで入れる |

**決めたこと（2026-09-20、発注者への確認済み）**

1. 数量は kg に換算したものを登録する。単位の換算は本システムでしない
2. 販売量 ＝ 出荷数量。物質収支は 購入数量 − 出荷数量、**排出係数は出荷数量に掛ける**
3. 方法は事業所が 1 つ選ぶ（物質ごと・経路ごとに変えない）。値は物質 × 経路ごとに持つ
4. 実測値・物質収支の割合・排出係数は、画面からも CSV / Excel の取り込みでも入れられる。
   取り込みで既に値がある物質に当たったら「上書きしますか」と尋ね、OK のときだけ取り込む
5. 数量の取り込みは、取り込み時に「同じ製品は上書き・無い製品は追加」か「事業所・年度を全部入れ替え」かを選ぶ
6. 担当者は当面 1 事業所のみ。ただし後で複数になる可能性があるので、利用者と事業所の対応は別の表に持ち、画面だけ 1 つに絞る
7. 届出用 XML は仕様が公開されていない。**支援システムが出した見本 2 つ**（`docs/prtr/`）と同じ形で出す。
   任意項目が空でも要素は出し、中身を空にする（見本で確認済み）

**2 回目の確認で決めたこと（2026-09-20）**

8. **PRTR 管理者**の権限を作る。業種（コード・名称）と主務大臣を登録し、届出データを作るときはそこから選ぶ。
   既定のデータとして、「PRTR 届出の手引き」の**業種コード・届出先一覧**を取り込んでおく
9. **提出日**は届出データのフォームで入力。既定は当日。空は許さない
10. **非公開製品**: 数量の登録と参照は、自分の事業所の分なら製品の閲覧権限に関係なくできる。製品の詳細へのリンクだけ権限に従う。集計には含める
11. **担当者情報**（部署・氏名・かな・電話・内線・メール）は届出データのフォームで入力する。事業所マスタには持たない
12. 数量・値を登録するとき（画面でも取り込みでも）**年度を指定する**
13. **事業者**は原則 1 つだが、組織マスタに登録してある会社から選べる。既定の事業者はシステム設定で決める
14. 届出要否は「取扱量が 1 t（特定第一種は 0.5 t）以上」だけで判定する。**この閾値はシステム設定で変えられる**
15. PRTR 管理者の集計画面は表を**上下に 2 つ**出す。上は各事業所の登録内容、下は会社で合算したもの。
    合算の行は展開でき、**どの事業所が何 kg か**の内訳が出る

## 3. データ

### 3-1. 事業所 `sites`

| 列 | 内容 |
| --- | --- |
| id, code, code_normalized | コードは一意（`normalizeCode`） |
| name_ja, name_kana, name_en | 事業所の名称・ふりがな |
| last_year_name | 前回の届出における名称（変えたときだけ） |
| zip, prefecture, city, town, prefecture_kana, city_kana, town_kana | 所在地とふりがな |
| employee_num | 常時使用する従業員の数（前年 4/1 現在）。届出データの既定値になる |
| display_order, note, created/updated/deleted_at | 論理削除。**数量が登録されている事業所は消せない** |

業種・主務大臣・担当者は事業所マスタに持たない。届出データ（3-7）で入れる。

### 3-2. 担当 `user_sites`

| 列 | 内容 |
| --- | --- |
| user_id, site_id | 一意。**当面は 1 人 1 行**（画面が 1 つしか選ばせない）。複数にするときは画面だけ直す |

### 3-3. 事業者（届出者） `prtr_registrants`

組織マスタ（`organisations`。帳票の差出人に使っている会社・事業所の表）の 1 件に、届出者として要る項目を添える。

| 列 | 内容 |
| --- | --- |
| organisation_id | 一意。どの組織の届出者情報か |
| name_kana | 事業者の名称のふりがな |
| represent_name, represent_name_kana | 代表者（役職＋氏名）とふりがな |
| agent_name, agent_name_kana | 代理人（任意） |
| corporate_number | 法人番号（無ければ空） |
| last_year_company_name | 前回の届出における事業者名（変えたときだけ） |
| zip, prefecture, city, town, prefecture_kana, city_kana, town_kana | 住所とふりがな |

既定の事業者はシステム設定 `prtr.defaultRegistrantOrganisationId`。届出データを作るとき、既定が入った状態で、登録してある会社から選び直せる。

### 3-4. 業種 `prtr_industries` と 主務大臣 `prtr_ministers`

| 表 | 列 |
| --- | --- |
| `prtr_industries` | code（4 桁）、name、default_minister_id（届出先の既定）、display_order、active |
| `prtr_ministers` | name（「経済産業大臣」など）、display_order、active |

どちらも PRTR 管理者が登録・修正する。既定のデータは「PRTR 届出の手引き」の業種コード・届出先一覧
（`docs/prtr/PRTR届出の手引き.pdf` 64 ページ。金属鉱業 0500 経済産業大臣 … 計量証明業 8630 まで）から
`scripts/seed-prtr-industries.ts` で入れる。主務大臣はその表に出てくる大臣（経済産業・厚生労働・農林水産・国土交通・財務・環境）を入れる。

### 3-5. 数量 `prtr_quantities`

| 列 | 内容 |
| --- | --- |
| site_id, fiscal_year, product_id | 一意 |
| purchased_kg, shipped_kg | Decimal。kg |
| source | IMPORT / MANUAL |
| import_id | 取り込みで入ったときの取り込み ID |
| created/updated_at/by | |

製品は既存の製品マスタ（会社共通）を指す。

### 3-6. 方法と値 `prtr_methods` / `prtr_values`

| 表 | キー | 列 |
| --- | --- | --- |
| `prtr_methods` | (site_id, fiscal_year) 一意 | method（MEASURED / BALANCE / FACTOR） |
| `prtr_values` | (site_id, fiscal_year, statutory_substance_id) 一意 | 経路 6 つの値 air, waters, soil, landfill, sewage, waste（Decimal）、source（IMPORT / MANUAL）、import_id |

値の意味は方法で決まる。実測値なら kg、物質収支なら残量に掛ける割合（0〜1）、排出係数なら
出荷量 × 含有率 に掛ける係数。方法を変えると既存の値の意味が変わるので、**方法の変更時は値を消すか
残すかを確認する**。

### 3-7. 届出データ `prtr_reports` と別紙の付随項目 `prtr_sheet_details`

届出書 1 通ぶんのフォームの内容。事業所 × 年度で 1 件。

| 列 | 内容 |
| --- | --- |
| site_id, fiscal_year | 一意 |
| registrant_organisation_id | 事業者（3-3）。既定はシステム設定 |
| submit_date | 提出日。**必須。**新規作成時の既定は当日 |
| minister_id | 主務大臣（3-4 から選ぶ） |
| submit_prefecture | 届出先の都道府県知事。既定は事業所の都道府県＋「知事」 |
| employee_num | 従業員数。既定は事業所マスタの値 |
| main_industry_id | 主たる業種（3-4 から選ぶ） |
| demand_flag | 法第 6 条第 1 項の請求の有無 |
| charge_post, charge_name, charge_name_kana, tel1〜3, tel_extension, mail | 担当者 |
| created/updated_at/by | |

従たる業種は子の表 `prtr_report_sub_industries`（report_id, no, industry_id）。

| `prtr_sheet_details` 列 | 内容 |
| --- | --- |
| site_id, fiscal_year, statutory_substance_id | 一意 |
| waters_name | 排出先の河川・湖沼・海域の名称 |
| landfill_type | 埋立処分の場所（1 安定型 / 2 管理型 / 3 遮断型） |
| sewage_name | 移動先の下水道終末処理施設の名称 |
| waste_methods | 廃棄物の処理方法（01〜07 の集合） |
| waste_types | 廃棄物の種類（01〜18 の集合） |

**翌年度に引き継ぐ。**新しい年度の届出データを作るとき、前年度の届出データ（提出日以外）・値・別紙の付随項目を初期値として写す（数量は写さない）。

### 3-8. 管理番号 `prtr_control_numbers`

| 列 | 内容 |
| --- | --- |
| control_number | 3 桁（`001`〜） |
| statutory_substance_id | 化管法 第一種（`C1`）または特定第一種（`SC1`）の法文物質名 |
| name | 届出に載せる名称（令別表第一の名称・別名） |

経産省の「化管法管理番号リスト」（`docs/prtr/化管法管理番号リスト_METI_20211015.pdf`）から
`scripts/seed-prtr-control-numbers.ts` で入れる。リストは政令番号（`1-010` の形）を持つので、本システムの
`令別表第1の10` に当てる。第一種 515・第二種 134 の全部に載っている。作ったあと 515 件を目で照合する。

### 3-9. システム設定に足すもの

| 鍵 | 内容 | 既定 |
| --- | --- | --- |
| `prtr.thresholdKg` | 第一種の届出要否の閾値 | 1000 |
| `prtr.thresholdSpecificKg` | 特定第一種の届出要否の閾値 | 500 |
| `prtr.defaultRegistrantOrganisationId` | 既定の事業者 | 未設定 |

管理者だけが変えられる（既存のシステム設定と同じ）。

## 4. 計算

集計は保存しない。画面を開くたび、届出を作るたびに計算する（判定の版や組成の変更に自動で追従する）。
製品の判定が「要再計算」の状態なら、集計画面にもその印を出す。

### 4-1. 該当物質と含有率

1. その事業所・年度に数量がある製品を集める
2. 各製品の**化管法の判定結果**（現在の版）から、第一種・特定第一種で「該当」の法文物質名を取る。
   裾切値（1% / 0.1%）未満の製品と、不純物種別で除外した物質はここで落ちる（判定がそう決めている）
3. その法文物質名に当たる CAS の含有率を製品の展開結果から取る。金属化合物は金属換算済みの値

### 4-2. 物質ごとの量

```
取扱量   = Σ 購入数量 × 含有率
出荷量   = Σ 出荷数量 × 含有率
残量     = 取扱量 − 出荷量
届出要否 = 取扱量 ≥ 閾値（システム設定。既定 1,000 kg、特定第一種 500 kg）
```

### 4-3. 排出量・移動量（経路ごと）

| 方法 | 計算 | 値の確認 |
| --- | --- | --- |
| 実測値 | 値そのもの | — |
| 物質収支 | 残量 × 割合 | 6 つの割合の合計が 1 を超えたら警告（残量より多く配ることはできない） |
| 排出係数 | 出荷量 × 係数 | — |

丸めは別紙の注 5 のとおり。**有効数字 2 桁**、1 kg 未満は小数第 2 位以下を四捨五入。
届出書と XML に載せるのは丸めた値、画面には丸める前の値も出す。

## 5. 画面

左ペインに「PRTR」を足し、その下に並べる。事業所担当には自分の事業所の分しか出ない。

### 5-1. PRTR > 事業所（PRTR 管理者）

- 一覧は `components/data-table`。コードのリンクで詳細へ。**表示のみ → 編集** の型
- 詳細は 3-1 の項目。利用者への担当の割り当ては **管理 > 利用者** の画面で行う

### 5-2. PRTR > 業種・主務大臣・事業者（PRTR 管理者）

- 業種と主務大臣は項目が少ないので、一覧の上のフォームで足す型（マスタの作り分けの決まり）
- 事業者は組織マスタの会社を選び、3-3 の項目を編集する

### 5-3. PRTR > 数量

- 上に 事業所（PRTR 管理者だけ選べる）・年度 の選択。既定は前年度
- 一覧は data-table。列: 製品コード（閲覧権限があればリンク）・製品名・購入数量・出荷数量・登録元・更新日時。
  行末の鉛筆で編集、先頭のチェックでまとめて削除、上に「取り込み」と「1 件登録」
- 1 件登録は 年度・製品コード・購入数量・出荷数量 を入れる小さな入力

### 5-4. PRTR > 集計

- 上に 事業所・年度・方法（その事業所・年度の方法。変えると確認）
- **事業所担当**: 物質ごと 1 行の表。列: 管理番号・名称・区分（第一種／特定第一種）・取扱量・出荷量・残量・届出要否・
  経路 6 つの値（入力欄）・経路 6 つの排出量（計算結果）・値の登録元。
  値を入れるとその場で排出量が変わる。届出要否なのに値が無い物質は「未入力」と目立たせる
- **PRTR 管理者**: 表を上下に 2 つ出す
  - 上: **各事業所の登録内容**。事業所 × 物質の行で、上と同じ列。事業所で絞り込める
  - 下: **会社で合算**した物質ごとの行（取扱量・出荷量・残量・排出量の合計）。
    行を展開すると**事業所ごとの内訳（何 kg）**が出る。参照のみ
- 上に「係数・実測値の取り込み」

### 5-5. PRTR > 届出

- 事業所・年度を選ぶ。届出データが無ければ「作成」で作る（前年度があれば写す）
- フォーム: 事業者（既定から選び直せる）・提出日（既定は当日、必須）・主務大臣・届出先・従業員数・
  主たる業種と従たる業種（登録してある業種から選ぶ）・法第 6 条の請求・担当者
- 別紙の一覧（届出要否の物質）と、別紙ごとの付随項目（3-7）。「表示のみ / 編集中」の型
- 「XML をダウンロード」。ファイル名は見本と同じ `届出YYYYMMDD<事業所名>.xml`
- 未入力（提出日・主務大臣・業種・方法の値・付随項目の必須分）があれば、その項目を挙げて XML を作らない

## 6. 取り込み

既存の取り込み画面（下見 → 適用）に種類を 2 つ足す。CSV（UTF-8 / Shift_JIS）と Excel（.xlsx）。
Excel の読み込みは帳票で使っている `exceljs`。**どちらも年度を指定する**（画面で選ぶか、列で持つ）。

### 6-1. PRTR 数量 `PRTR_QUANTITIES`

- 列: 製品名・製品コード・購入数量・出荷数量。任意で 事業所コード・年度（無ければ画面で選んだもの）
- 製品は製品コードで当てる。無いコードの行は「読めない」。製品名が製品マスタと違う行は警告（取り込みは通す）
- 数量は数値で kg。負や空は「読めない」
- **重ね方は取り込み時に選ぶ**: 「同じ製品は上書き・無い製品は追加」（既定）か「この事業所・年度を全部入れ替え」。
  下見に、上書きになる製品数と、入れ替えで消える件数を出す

### 6-2. PRTR 係数・実測値 `PRTR_VALUES`

- 1 行 = 物質。列: 管理番号（または名称）・大気・公共用水域・土壌・埋立・下水道・廃棄物。任意で 事業所コード・年度
- 値の意味は、その事業所・年度に選んである方法で決まる。方法が未設定なら取り込めない（先に選ばせる）
- **既に値がある物質に当たったら、下見で「n 件に値があります。上書きしますか」と尋ね、OK のときだけ取り込む。**
  OK しなければ何も取り込まない（値のある物質だけ飛ばす、という中途半端はしない）

### 6-3. 書き出し

数量と値は、一覧の書き出し（既存の TSV）で出せる。取り込みの形と同じ列にして、直して戻せるようにする。

## 7. 届出用 XML

- 見本（`docs/prtr/届出見本1.xml`・`届出見本2.xml`）と**同じ要素・同じ並び・同じ字下げ**で出す。
  UTF-16（BOM 付き）、LF、`standalone="yes"`、`REGISTER_VERSION` は見本の値（NITE が版を上げたら定数を変える）
- 任意項目（代理人・前回の名称・メール 2・内線など）は空でも要素を出す
- 選択項目は選択肢ごとの要素に `1`（選択）/ `2`（非選択）。埋立の場所 3 つ、処理方法 7 つ、廃棄物の種類 18 つ
- 別紙は届出要否の物質を管理番号順に並べ、`SHEET_NO` を 1 から振る。`SHEET_NUM` はその枚数
- 単位 `UNIT` は 1（kg）。ダイオキシン類（mg-TEQ）は対象外（第 11 章）
- 数量は丸めた値をそのまま（`110`・`0.5`）。0 は `0.0`
- **確認の手段**: できた XML を NITE の届出システムの「ファイル読込み」に通す。ここが最終確認で、通らなければ見本との差を直す

## 8. 権限

| 権限 | できること |
| --- | --- |
| `PRTR_SITE` | 自分の担当事業所の数量・値・付随項目・届出データの登録・変更・参照、届出書の表示と XML |
| `PRTR_ADMIN` | 全事業所について同じこと。集計の上下 2 つの表。事業所・業種・主務大臣・事業者の登録。`PRTR_SITE` を含む |

- 担当の割り当て（`user_sites`）は `ADMIN`（利用者の画面）。閾値と既定の事業者は `ADMIN`（システム設定）
- **行単位の権限は本システムで初めて。**`lib/authz.ts` に `requireSiteAccess(actor, siteId)` を足し、
  PRTR の API 全部で `requirePermission` の後に通す。`PRTR_SITE` だけの人は自分の事業所以外は 404
- 呼び忘れは `authz-coverage.test.ts` で検出（PRTR の API は `requireSiteAccess` も必須にする）
- 非公開製品: 数量の API は事業所で絞るだけで、製品の閲覧権限は見ない（決めごと 10）。製品名は返す。
  製品の詳細へのリンクは画面側で権限を見て出し分ける
- デプロイ時、管理者に `PRTR_ADMIN` を付ける移行を入れる（`deploy-with-manual` の決まり）

## 9. マニュアル

`apps/web/app/spec/prtr/` を新設。手順の順: 事業所・業種・主務大臣・事業者の登録 → 担当の割り当て →
数量の取り込み → 方法と値 → 集計の見かた → 届出データと XML → 届出システムでの読み込み。
翻訳キーは各画面と一緒に足す。

## 10. 使いやすさのための決め

- 年度の既定は「前年度」（届出の対象）。年度を変えたら、その画面の中だけ変わる
- 新しい年度の届出データを作るとき、前年度の届出データ・方法・値・付随項目を写すか尋ねる（数量は写さない）
- 集計の一覧で、届出要否の物質を上に、それ以外を下にまとめる
- 物質収支の割合は **0〜1 の小数に統一**（1 を超えたら警告）
- 業種を選ぶと、その業種の既定の届出先（主務大臣）が入る。選び直せる

## 11. 対象外（今回はやらない）

- 排出係数の基準量の上書き（発注者の回答で出荷数量に確定したため）
- 工程（用途）ごとの係数。要望が出たら製品の用途ごとに値を持てるよう広げる
- 在庫の増減。厳密にしたい事業所は購入数量に 期首在庫 − 期末在庫 を含めて登録する
- ダイオキシン類（単位 mg-TEQ）、燃料小売業の算出
- 届出の控え（提出した XML の保存）、変更届・取下げ
- 複数事業所の担当（表は用意する。画面は 1 つ）
- 従業員数や業種による事業者要件の判定
