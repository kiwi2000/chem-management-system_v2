# S22. PRTR 集計と届出（工場 → グループ → 会社）

状態: 仕様確定（2026-09-21）／ 実装前。**届出フォームと XML（S22-4）は保留**

## 1. 目的

化管法の PRTR 届出は、届け出る単位ごと・年度ごと・第一種指定化学物質ごとに、排出量・移動量を
翌年度の 4/1〜6/30 に届け出る。届出要否は年間取扱量が 1 トン以上（特定第一種は 0.5 トン以上）で決まる。

お客様の運用は、**データを入れるのは工場、届け出るのは都道府県ごと**（同じ都道府県の複数工場を
合算して 1 通）。会社全体の集計も見たい。いまの本システムは製品ごとの該非までしか持たず、
工場や届出の単位も無い。

**工場が方法に応じた数量を登録すれば、本システムが組成と該非判定から物質ごとの排出量を計算し、
グループ（届出単位）と会社で合算して見せる。**届出書と XML はその合算から作る（保留）。

## 2. 用語と決めごと

| 用語 | 意味 |
| --- | --- |
| 工場 | データを入れる単位。数量・方法・値を持つ |
| グループ | 届け出る単位。お客様の場合は都道府県。工場を 1 つ以上まとめる。工場 1 つだけのグループもある |
| 会社 | 全グループの集計を見る単位。届出はしない |
| 事業者 | 届出者。原則 1 つだが、組織マスタに登録してある会社から選べる |
| 年度 | 4 月〜翌 3 月。届出の対象年度は「前年度」。**数量も値も、登録するときに年度を指定する** |
| 方法 | 排出量の出し方。実測値・物質収支・排出係数の 3 つ。**工場が年度ごとに 1 つ選ぶ** |
| 取扱量 | 購入数量 × 含有率 の合計（物質ごと）。届出要否の判断に使う |
| 管理番号 | 届出で物質を指す 3 桁の番号。**政令番号とは別**（3-9） |

**方法ごとの入力と計算（2026-09-21 決定）**

| 方法 | 入力するもの | 排出量（物質ごと） |
| --- | --- | --- |
| 実測値 | 物質コード・実測値（kg、年間） | そのまま |
| 物質収支 | 製品コード・購入数量・出荷数量（kg） | Σ（購入数量 − 出荷数量）× 含有率 |
| 排出係数 | 製品コード・出荷数量（kg）と、物質ごとの排出係数（%） | Σ 出荷数量 × 含有率 × 係数 ÷ 100 |

- 数量は kg に換算したものを登録する。単位の換算は本システムでしない
- 実測値も年間の kg に直したものを入れる（濃度 × 流量 の計算は本システムでしない）
- 排出係数は %（排出量 kg ÷ 出荷量 kg × 100）。**工場 × 物質**で持つ（製品ごとにはしない）
- 入力は画面でも、CSV / TSV / Excel の取り込みでも可能
- **経路（大気・水域・土壌・埋立・下水道・廃棄物）への配分は、届出フォームと一緒に保留**。
  それまで排出量は物質ごとに 1 つの数で持つ

**決めたこと（2026-09-20〜21、発注者への確認済み）**

1. 販売量 ＝ 出荷数量
2. 方法は工場が年度ごとに 1 つ選ぶ
3. 取り込みで既に値がある行に当たったら「上書きしますか」と尋ね、OK のときだけ取り込む。
   数量の取り込みは「同じ製品は上書き・無い製品は追加」か「この工場・年度を全部入れ替え」かを取り込み時に選ぶ
4. 担当は当面 1 人 1 つ（工場か、グループ）。表は複数対応にし、画面だけ 1 つに絞る
5. **グループ担当は、自分のグループの工場のデータを登録・修正できる**（工場の入力を待たずに締められる）
6. 届出要否は「グループの取扱量 ≥ 1 t（特定第一種は 0.5 t）」だけで判定。**閾値はシステム設定**
7. 非公開製品: 数量の登録と参照は、自分の工場（グループ）の分なら製品の閲覧権限に関係なくできる。
   製品の詳細へのリンクだけ権限に従う。集計には含める
8. 業種・主務大臣は PRTR 管理者が登録するマスタ。既定のデータは「PRTR 届出の手引き」の
   業種コード・届出先一覧から取り込む。事業者は組織マスタから選び、既定はシステム設定
9. 届出用 XML は仕様が公開されていない。支援システムが出した見本 2 つ（`docs/prtr/`）と同じ形で出す（保留）
10. 複数工場を 1 通にまとめる運用は、お客様が自治体と了解済みという前提。本システムは強制も検査もしない

## 3. データ

### 3-1. グループ `prtr_groups`

届出上の事業所にあたる。届出の本紙に要る項目を持つ（届出フォームは保留だが、名称と所在地は集計の見出しに要る）。

| 列 | 内容 |
| --- | --- |
| id, code, code_normalized | コードは一意（`normalizeCode`） |
| name_ja, name_kana, name_en | 名称（例「千葉県」「千葉事業所」）とふりがな |
| zip, prefecture, city, town（＋かな） | 届出上の所在地 |
| employee_num | 常時使用する従業員の数 |
| display_order, note, created/updated/deleted_at | 論理削除。**工場が属しているグループは消せない** |

### 3-2. 工場 `prtr_sites`

| 列 | 内容 |
| --- | --- |
| id, code, code_normalized, group_id | コードは一意。必ずどれかのグループに属する |
| name_ja, name_en, display_order, note, created/updated/deleted_at | 論理削除。**数量が登録されている工場は消せない** |

### 3-3. 担当 `prtr_user_scopes`

| 列 | 内容 |
| --- | --- |
| user_id, site_id（任意）, group_id（任意） | 工場担当は site_id、グループ担当は group_id。**当面は 1 人 1 行** |

### 3-4. 方法 `prtr_methods`

| 列 | 内容 |
| --- | --- |
| site_id, fiscal_year | 一意 |
| method | MEASURED / BALANCE / FACTOR |

方法を変えると既存の入力の意味が変わるので、**変更時は入力を消すか残すかを確認する**。

### 3-5. 数量 `prtr_quantities`（物質収支・排出係数）

| 列 | 内容 |
| --- | --- |
| site_id, fiscal_year, product_id | 一意 |
| purchased_kg | 物質収支のとき。排出係数のときは空 |
| shipped_kg | 両方 |
| source, import_id, created/updated_at/by | 登録元と経路 |

### 3-6. 物質ごとの入力 `prtr_substance_inputs`（実測値・排出係数）

| 列 | 内容 |
| --- | --- |
| site_id, fiscal_year, statutory_substance_id | 一意 |
| measured_kg | 実測値のとき |
| factor_pct | 排出係数のとき（%） |
| source, import_id, created/updated_at/by | |

物質は**管理番号か本システムの物質コード**で指定できる。物質コードのときは、その物質の CAS が
結び付く化管法 第一種の法文物質名に当てる（当たらなければ「読めない」）。画面と保存は法文物質名。

### 3-7. 事業者 `prtr_registrants`、業種 `prtr_industries`、主務大臣 `prtr_ministers`

前回の計画のまま（届出フォームで使う。マスタは S22-1 で作る）。
事業者は組織マスタの 1 件に、名称かな・代表者・代理人・法人番号・前回の事業者名・住所とかな を添える。
業種は code（4 桁）・name・default_minister_id、主務大臣は name。既定データは手引きの一覧（`docs/prtr/PRTR届出の手引き.pdf` 64 ページ）。

### 3-8. 届出データ `prtr_reports`・別紙の付随項目 `prtr_sheet_details`（保留）

グループ × 年度で 1 件。提出日（必須・既定は当日）・事業者・主務大臣・届出先・業種・担当者・経路ごとの配分・
河川名などを持つ。**中身はフォームを作るときに決める。**

### 3-9. 管理番号 `prtr_control_numbers`

| 列 | 内容 |
| --- | --- |
| control_number | 3 桁（`001`〜） |
| statutory_substance_id | 化管法 第一種（`C1`）または特定第一種（`SC1`）の法文物質名 |
| name | 届出に載せる名称 |

経産省の「化管法管理番号リスト」（`docs/prtr/化管法管理番号リスト_METI_20211015.pdf`）から
`scripts/seed-prtr-control-numbers.ts` で入れる。政令番号（`1-010`）を `令別表第1の10` に当てる。作ったあと 515 件を目で照合する。

### 3-10. システム設定に足すもの

| 鍵 | 内容 | 既定 |
| --- | --- | --- |
| `prtr.thresholdKg` | 第一種の届出要否の閾値 | 1000 |
| `prtr.thresholdSpecificKg` | 特定第一種の届出要否の閾値 | 500 |
| `prtr.defaultRegistrantOrganisationId` | 既定の事業者 | 未設定 |

## 4. 計算

集計は保存しない。画面を開くたびに計算する。製品の判定が「要再計算」なら、集計画面にもその印を出す。

### 4-1. 該当物質と含有率

1. その工場・年度に数量がある製品を集める
2. 各製品の**化管法の判定結果**（現在の版）から、第一種・特定第一種で「該当」の法文物質名を取る。
   裾切値未満の製品と、不純物種別で除外した物質はここで落ちる
3. その法文物質名に当たる CAS の含有率を製品の展開結果から取る。金属化合物は金属換算済みの値

### 4-2. 工場ごと（物質ごと）

```
取扱量 = Σ 購入数量 × 含有率           （物質収支のとき。実測値・排出係数のときは出せない）
出荷量 = Σ 出荷数量 × 含有率           （物質収支・排出係数のとき）
排出量 = 方法ごとの式（第 2 章の表）
```

### 4-3. グループと会社

- グループ: 属する工場の 取扱量・出荷量・排出量 を物質ごとに足す。**届出要否はグループの取扱量で判定**
  （実測値の工場は取扱量が無いので、取扱量の合計にはその工場を含めず、その旨を出す）
- 会社: グループを足す。行を展開するとグループ → 工場の内訳が出る

丸めは届出書の決まり（有効数字 2 桁、1 kg 未満は小数第 2 位以下を四捨五入）。画面には丸める前の値も出す。

## 5. 画面

左ペインに「PRTR」。見える範囲は権限で決まる（工場担当は自分の工場、グループ担当は自分のグループの工場）。

### 5-1. PRTR > グループ・工場（PRTR 管理者）

- どちらも一覧は `components/data-table`。コードのリンクで詳細へ。**表示のみ → 編集** の型
- 工場の詳細でグループを選ぶ。利用者への担当の割り当ては **管理 > 利用者** で行う

### 5-2. PRTR > 業種・主務大臣・事業者（PRTR 管理者）

前回の計画のまま。業種と主務大臣は一覧の上のフォームで足す型。事業者は組織を選んで項目を編集する。

### 5-3. PRTR > 入力

- 上に 工場（グループ担当・管理者だけ選べる）・年度・**方法**（その工場・年度の方法）
- 方法で表が変わる
  - 実測値: 物質ごと 1 行。管理番号・名称・実測値（kg）
  - 物質収支: 製品ごと 1 行。製品コード（閲覧権限があればリンク）・製品名・購入数量・出荷数量
  - 排出係数: 製品ごとの表（製品コード・製品名・出荷数量）と、物質ごとの表（管理番号・名称・排出係数 %）の 2 つ
- どの表も data-table。行末の鉛筆で編集、先頭のチェックでまとめて削除、上に「取り込み」と「1 件登録」（年度を含む）

### 5-4. PRTR > 集計

- 上に グループ・工場・年度 の絞り込み（見える範囲の中で）
- **工場担当**: 自分の工場の物質ごとの表。管理番号・名称・区分・取扱量・出荷量・排出量・入力の登録元
- **グループ担当**: 上に工場ごとの表（工場 × 物質）、下にグループで合算した表（物質ごと、届出要否つき）。
  下の行を展開すると工場の内訳（kg）
- **PRTR 管理者**: 上にグループ × 物質の表（工場で絞り込める）、下に会社で合算した表。
  下の行を展開するとグループ → 工場の内訳（kg）
- 届出要否なのに入力が無い物質は「未入力」と目立たせる

### 5-5. PRTR > 届出（保留）

グループ × 年度の届出フォーム、別紙の付随項目、経路への配分、XML。作るときに決める。

## 6. 取り込み

既存の取り込み画面（下見 → 適用）に種類を足す。CSV / TSV（UTF-8 / Shift_JIS）と Excel（.xlsx）。
**工場と年度は画面で選ぶ**（ファイルに工場コード・年度の列があればそれを優先）。
方法に合わない種類は取り込めない（先に方法を選ばせる）。

| 種類 | 列 | 重ね方 |
| --- | --- | --- |
| PRTR 数量（物質収支） | 製品コード・購入数量・出荷数量（製品名は任意。違えば警告） | 取り込み時に選ぶ: 上書き＋追加 / 全部入れ替え |
| PRTR 数量（排出係数） | 製品コード・出荷数量 | 同上 |
| PRTR 実測値 | 物質コード（または管理番号）・実測値 kg | 既に値がある行は「上書きしますか」 |
| PRTR 排出係数 | 物質コード（または管理番号）・排出係数 % | 同上 |

製品は製品コードで当てる。無いコード・負や空の数量は「読めない」。
書き出しは一覧の TSV で、取り込みと同じ列にする。

## 7. 届出用 XML（保留）

見本（`docs/prtr/届出見本1.xml`・`届出見本2.xml`）と同じ形で出す。UTF-16（BOM 付き）、LF、任意項目は空要素、
選択項目は `1`/`2`、別紙は管理番号順。最終確認は NITE の届出システムの「ファイル読込み」。

## 8. 権限

| 権限 | できること |
| --- | --- |
| `PRTR_SITE` | 自分の工場の入力（数量・方法・値）の登録・参照、自分の工場の集計 |
| `PRTR_GROUP` | 自分のグループに属する全工場について同じこと。グループの集計。届出データの作成と XML（保留）。`PRTR_SITE` を含む |
| `PRTR_ADMIN` | 全グループについて同じこと。会社の集計。グループ・工場・業種・主務大臣・事業者のマスタ。`PRTR_GROUP` を含む |

- 担当の割り当ては `ADMIN`（利用者の画面）。閾値と既定の事業者は `ADMIN`（システム設定）
- **行単位の権限は本システムで初めて。**`lib/authz.ts` に `requirePrtrScope(actor, siteId | groupId)` を足し、
  PRTR の API 全部で `requirePermission` の後に通す。範囲外は 404
- 呼び忘れは `authz-coverage.test.ts` で検出（PRTR の API は `requirePrtrScope` も必須にする）
- デプロイ時、管理者に `PRTR_ADMIN` を付ける移行を入れる

## 9. マニュアル

`apps/web/app/spec/prtr/` を新設。手順の順: グループ・工場・業種・主務大臣・事業者の登録 → 担当の割り当て →
方法の選択 → 入力（画面・取り込み） → 集計の見かた。届出は作ったときに足す。翻訳キーは各画面と一緒に。

## 10. 使いやすさのための決め

- 年度の既定は「前年度」。年度を変えたら、その画面の中だけ変わる
- 新しい年度を初めて開いたとき、前年度の方法と排出係数を写すか尋ねる（数量・実測値は写さない）
- 集計の一覧で、届出要否の物質を上に、それ以外を下にまとめる
- 業種を選ぶと、その業種の既定の届出先（主務大臣）が入る（届出フォームを作るとき）

## 11. 対象外（今回はやらない）

- 経路への配分、届出フォーム、XML（保留。S22-4）
- 実測値の元データ（濃度 × 流量）からの換算
- 製品ごとの排出係数、工程ごとの係数
- 在庫の増減（購入数量に 期首在庫 − 期末在庫 を含めて登録してもらう）
- ダイオキシン類、燃料小売業の算出、変更届・取下げ
- 複数の工場・グループの担当（表は用意する。画面は 1 つ）
- 従業員数や業種による事業者要件の判定
