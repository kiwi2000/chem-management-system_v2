# グループ（お知らせの分類 / 組織の所属）

確定日: 2026-08-15

## 何のためのものか

用途が2つある。**どちらも1人につき1つ**、階層は持たない（並列に作って表示順で並べる）。

| 用途 | 使い道 |
|---|---|
| **お知らせの分類**（NEWS） | ホームのお知らせを見出しで区切る |
| **組織の所属**（ORG） | ○○部 などの所属を表す |

ホームはこう出る（見出しの順序はグループの表示順）。

```
システム管理チームからのお知らせ
  投稿1
  投稿2
化学物質管理チームからのお知らせ
  投稿3
その他のお知らせ        ← 分類なしの投稿。最後にまとめる
  ...
```

## 決めたこと

1. **表を分けず種別（`kind`）で持つ**。管理画面と操作をひとつにまとめられるため
2. **お知らせの分類は投稿時に写し取る**（`news.group_id`）。
   投稿者が異動しても、過去の投稿が別の見出しへ移らないようにするため
3. **お知らせの分類を持てるのは「お知らせを投稿できる」人だけ**。
   権限を外したら分類も外れる（投稿できないのに見出しだけ割り当たった状態を作らない）。
   画面ではプルダウンを無効にし、**サーバー側でも null に落とす**
4. **用途が違うIDは 400**。画面からは来ないが、APIを直接叩かれても弾く
5. **使用中のグループは削除できない（409）**。所属や投稿を勝手に外すと、
   誰がどこに居たか分からなくなるため、先に外してもらう
6. **割り当て済みのグループは用途を変更できない**。変えると所属の意味が変わるので据え置く
   （拡張属性の「値が入っていると種類を変えられない」と同じ考え方）
7. 使わない設定（`active_flag = false`）のグループは選択肢に出さない。
   ただし**その人に既に割り当たっている場合だけは残す**。消えると「未選択」に見えて、保存した瞬間に外れてしまうため

## データ構造

### Group
| 列 | 型 | 備考 |
|---|---|---|
| `id` | cuid | |
| `kind` | enum `NEWS` / `ORG` | 用途 |
| `name_ja` / `name_en` | varchar(100) | 英語は任意。未入力なら英語表示でも日本語を出す |
| `display_order` | int | 小さいほど先。お知らせの見出しの順序にもなる |
| `active_flag` | bool | |
| `created_at` `updated_at` `deleted_at` | | 論理削除 |

`users.org_group_id` / `users.news_group_id`（どちらも null 可・FK は `ON DELETE SET NULL`）、
`news.group_id`（投稿時の写し）。

## 画面

- **`/admin/groups` グループ管理** … サイドバーの「システム」の**先頭**（ユーザー管理の上）。ADMIN のみ。
  上に入力フォーム、下に共通テーブル（並べ替え・絞り込み・ページング・チェックボックス一括削除・ダブルクリックで編集）
- **ユーザーの新規作成 / 編集** … 基本情報に「所属グループ」、権限カードの中に「お知らせの分類」
- **ホーム** … 分類ごとの見出しで区切って表示（最大30件）

## API

| メソッド | パス | 権限 |
|---|---|---|
| GET / POST | `/api/admin/groups` | ADMIN |
| PUT / DELETE | `/api/admin/groups/[id]` | ADMIN |

ユーザー側は `POST/PUT /api/admin/users[/id]` が `orgGroupId` / `newsGroupId` を受け取る。

## 検証結果（実測）

- グループ4件を作成（お知らせ2・組織2）→ 201。**名前が空だと 400**
- サイドバーの並びが「グループ管理 → ユーザー管理 → 物質の拡張属性 → システム設定」になっている
- 一覧の表示: 用途・グループ名（日/英）・表示順・所属人数・状態アイコン。所属人数は用途に応じた数
  （お知らせ＝お知らせ分類の人数 / 組織＝所属の人数）
- ユーザーへの割り当て: admin=品質保証部＋システム管理チーム、editor=製造部＋化学物質管理チーム
- **用途違いのIDを送ると 400**（お知らせ用グループを所属欄に入れた場合）
- **投稿権限が無い人にお知らせ分類を送っても、保存後は null**（viewer で確認）
- 投稿すると分類が写し取られ、ホームが見出しで区切られる:
  ```
  システム管理チーム / 投稿1〜4
  化学物質管理チーム / 投稿5
  (なし) / 以前からの投稿2件
  ```
- **分類を移してから投稿すると、新しい投稿だけが新しい見出しに入る**（過去の投稿は動かない）
- 削除: 使用中 → `409 使用中のグループは削除できません。先に所属を外してください` / 未使用 → 200
- ユーザー編集画面で、投稿権限が無い人は「お知らせの分類」が無効になり、
  説明が「「お知らせを投稿できる」を付けると指定できます」に変わる
- 認可の呼び忘れ検出テストが新しい2ルートを検出して通過（テスト83件すべて通過）
- typecheck / lint / prettier 通過

## 今後

  データの見える範囲を所属で絞る場合は、判定を `lib/authz.ts` に足す（S12以降で検討）
- 階層が必要になったら `parent_id` を足す。並列で作ってあるので、既存データは親なしのまま動く
