# 共通テーブル（一覧の並べ替え・絞り込み・ページング）

確定日: 2026-08-14

すべての一覧画面で使う共通部品。設計の理由は `docs/decisions/0006` を参照。

## 使い方

1. サーバー側の列定義を書く（例: `apps/web/lib/substance-columns.ts`）
   Prisma のフィールド名・種類・正規化の有無を指定する
2. API で `parseTableState` → `buildWhere` / `buildOrderBy` を通す（例: `app/api/substances/route.ts`）
3. 画面側の列定義を書き、`useTableState` と `<DataTable>` を組み合わせる（例: `app/substances/page.tsx`）

**キーを両方で一致させること。** 一致していない列は黙って無視される。

`<DataTable>` には `storageKey`（画面ごとに一意）を渡す。列幅と絞り込みパネルの開閉を
端末に覚えるのに使う。列の既定幅は列定義の `width`（px）で指定する。

## 動作の決めごと

1. 見出しクリックで 昇順 → 降順 → 解除。**Shift＋クリックで並べ替えのキーを追加**し、優先順位を数字で出す
2. **絞り込み条件は表の外（上のパネル）**。ボタンで開閉でき、開閉の状態は端末に覚える。
   表の中に入れると列幅に引きずられて入力欄の幅がばらつくため（日付欄が極端に広くなっていた）
3. 列の種類で入力が変わる（文字列・数値・日付は「条件＋値」、選択肢はチェックボックス）
4. 複数列の条件は AND
5. **コード・CAS番号は正規化してから突合**（全角で入力しても引ける）。名称・備考は大文字小文字を区別しない
6. 日付の「以前」「範囲」は**終わりの日いっぱい**を含む
7. 解釈できない条件は無視する（数値欄に文字を入れても一覧が空にならない）
8. 1ページ 25 / 50 / 100 / 200 件。既定50件
9. 並べ替えの最後に一意な列を足し、ページをまたいでも順序がぶれないようにする
10. 条件は **URL に載る**（戻る・共有ができる）
11. 条件なしで開いたら**前回の条件を復元**する
12. **絞り込み中はパネルに明示**し、「条件をクリア」で全件に戻す（URLと記憶の両方を消す）。
    パネルを閉じていても絞り込み中であることは分かる
13. 既定の並びのままなら「絞り込み中」は出さない
14. **列の区切りに薄い罫線**を引く
15. **見出しの右端をドラッグして列幅を変えられる**。幅は端末に覚え、「列幅を戻す」で既定に戻せる。
    キーボードでも矢印キー（Shiftで大きく）で変えられる。最小60px
16. 列幅は固定（`table-fixed`）で、はみ出す文字は省略記号にする。表全体は枠内で横スクロールする
17. 1セルに複数行を出したい列は `multiline: true`（省略記号で切らず行の高さを伸ばす）
18. **行ごとの操作ボタンは置かない。** 代わりに次の2つ。
    - **編集権限があるときだけ、先頭にチェックボックスの列**（見出しのチェックでそのページを全選択）
    - **表の上の削除ボタン**（アイコンのみ）。チェックした行をまとめて消す。押すと件数入りの確認が出る
    - **行をダブルクリックすると詳細**。別画面を持たない一覧（金属換算係数・項目定義）は
      上のフォームに読み込んで先頭までスクロールする
19. 読み直すと選択は解除する（見えていない行を消してしまわないように）
20. 子テーブルの項目で絞り込む列は `relation` を指定する（「1件でも合えば該当」）。並べ替えはできない
21. はい/いいえ の列は `booleanEnum: true` を指定する（選択肢の "true"/"false" を真偽値に直す）

## 物質一覧の列

物質コード / CAS番号 / 日本語名 / 英語名 / 状態（選択肢）/ 備考 / 更新日（日付）。
既定はコード昇順。

## 検証結果（実測）

- 「日本語名」見出しをクリック → `?sort=nameJa:asc`、並びが日本語名順に変わる
- Shift＋クリックで「状態」を追加 → `?sort=nameJa:asc,status:asc`、見出しに `1` `2` の優先順位
- 物質コードに `PB` を入力 → `f.code=contains:PB`、pb-001 と PB-002 の2件（**小文字も引ける**）
- 状態で「廃番」をチェック → `f.status=in:DISCONTINUED`、1件に絞られる
- 帯の表示: 「絞り込み中 条件 2 件 ・ 並べ替え 2 列」
- 別画面（お知らせ）へ行って戻る → **条件が復元される**。`localStorage` に保存されていることを確認
- 「条件をクリア」→ URL が空・保存も消え・全4件に戻る・帯も消える
- 件数を25件に変更 → `?size=25`
- 既定の並び（コード昇順）のときは帯が出ないことを確認
- 英語表示に切り替えると、演算子（contains / starts with …）や「Filtered」「Clear filters」も英語
- モバイル幅375px で横スクロールなし（表は枠内でスクロール）
- 単体テスト22件を追加（URL往復・壊れたURLの無視・Prisma条件の組み立て）。全77件通過

## 前提として直したこと

主名称を子テーブル（`substance_names`）から `substances` の列へ移した。
Prisma は1対多の子テーブルの項目で並べ替えできず、**名称でソートできなかった**ため。
子テーブルは別名専用の `substance_aliases` になり、「主名称は1件」をアプリ層で担保する必要も無くなった。

## 見た目の調整（2026-08-14 追加）

実際に使ってみて出た3点を直した。共通部品なので全一覧に効く。

- **列の区切りが分かりにくい** → 薄い罫線を引いた
- **列幅を変えられない** → 見出しの右端をドラッグして変えられるようにし、端末に記憶
- **絞り込み欄の幅が列に引きずられてばらついていた**（特に更新日が極端に広い）
  → 表の外の折りたたみパネルへ移動。3列のグリッドに並べ、どの項目も同じ幅になった

## この部品を使っている一覧

物質マスタ / 金属換算係数 / お知らせ / ユーザー管理 / 拡張属性の項目定義。
**新しく一覧を作るときも必ずこれを使う。**サーバー側の列定義は `apps/web/lib/list-columns.ts` にまとめてある。

## まだやっていないこと

- 列の表示・非表示の切り替え、列の並び順の変更
- 条件を「名前を付けて保存」する機能
- 一覧からの一括操作（チェックボックス選択）

必要になったら足す。今は要望が出ていないので入れていない。
