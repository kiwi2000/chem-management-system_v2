# S8 — 組成エディタ

確定日: 2026-08-16

## これは何か

製品に「何がどれだけ入っているか」を1段だけ登録する。構成要素は**物質**か**他の製品（原材料）**の
どちらか一方。多段の掛け算で物質まで下ろす展開は S11、判定は S12 なので、ここは**入力と検証**まで。

## データ項目（`composition_lines`）

| 項目 | 型 | 必須 | 備考 |
|---|---|---|---|
| 親製品 | FK | ○ | 親を消すと一緒に消える（CASCADE） |
| 物質 / 子製品 | FK | ○ | **どちらか一方だけ**（CHECK制約）。参照先は物理削除させない（RESTRICT） |
| 含有率(wt%) | Decimal(9,6) | △ | `0 < x ≤ 100`。残部の行だけ null（CHECK制約） |
| 残部（balance） | bool | ○ | オンだと `100 − 既知合計` を自動で当てる |
| 備考 | text | − | 「この値は暫定」などのメモ |
| 表示順 | int | ○ | 画面の上下ボタンで入れ替える |

**1製品あたり100行まで。** 含有率は単一値のみ（範囲は持たない）。
情報源（どのSDSに基づくか）は情報源マスタ（S10）ができてから紐づける。

## 含有率合計の検証（システム設定で切り替え）

| モード | 100%未満 | 100%超 |
|---|---|---|
| STRICT | エラー | エラー |
| STANDARD（既定） | 警告 | エラー |
| LENIENT | 何もしない | 警告 |

許容誤差の既定は 0.01%、残部の行は既定で許可。管理者が `/admin/settings` で変えられる。

判定そのものは `packages/shared/src/composition.ts` の `validateCompositionSum()` に置き、
**画面とサーバーの両方から同じ関数を呼ぶ**（同じ規則を2か所に書かないため）。
入力中の合計と残部の値がその場で更新されるのはこのため。

小数は `packages/shared/src/decimal.ts` で **100万倍した bigint** として扱う。
`0.1 × 3 = 0.30000000000000004` のような誤差を避けるためで、DB の `Decimal(9,6)` と桁を揃えてある。

## 保存を止めるもの / 通すもの

**止める（1件でもあれば保存しない。エラーは全件まとめて返す）**

- 同じ物質・同じ原材料が複数行にある
- 構成要素が両方指定されている／どちらも空
- 含有率が範囲外、残部の行に含有率が入っている、残部が2件以上
- 参照先が見つからない（削除済み・廃番）／原材料利用可がオフの製品を入れた
- **循環参照**（自己参照も、A→B→A の多段も。子製品からBFSで親に行き着くか見る）
- 合計がモードに照らして不正

**通すが伝える**: 合計が100%未満（STANDARD）、組成が空

## 権限

| 操作 | 必要な権限 |
|---|---|
| 組成を見る | `PRODUCT_VIEW` ＋ `COMPOSITION_VIEW` |
| 非開示の組成を見る | ＋ `COMPOSITION_VIEW_PRIVATE` |
| 組成を編集する | `PRODUCT_EDIT` ＋ 上の閲覧条件 |
| 構成要素の候補検索 | `PRODUCT_EDIT` |

- 製品自体が見えない（非公開）→ **404**。製品は見えるが組成が非開示 → **403**
  （本体が見えている以上、存在を隠す意味がないため）
- 詳細画面では、非開示なら組成の節ごと出さない
- 候補検索を `PRODUCT_EDIT` にしたのは、組成を組む以上は構成要素の名前が見えないと作業にならないため。
  返すのはコードと名称だけに絞っている

## 画面

製品詳細（`/products/[id]`）の下に「原組成」の節を置き、**製品本体とは別に保存する**。
行数が多くなるので、名称を触っていないのに全部保存し直すのを避けた。

- 種別（物質／原材料）を選び、コードか名称で検索して候補から選ぶ（入力が落ち着いてから引く）
- 既に入っている構成要素は候補で選べない
- 行の並べ替えは上下ボタン
- 合計と残部は入力しながら更新される

## S7 から持ち越した分（ここで入れた）

- **原材料利用可をオフに戻すときの警告**（既に N 件から参照されている）。保存は通す
- **削除時の参照チェック**。製品・物質とも、組成から参照されていれば **409 で断る**
  （v1 は `?force=true` で強行できたが、参照が壊れるので用意しなかった）

## 検証結果（実測）

権限×エンドポイントは curl（PowerShell から `curl.exe`）で実測。検証用に製品を3件作って消している。

- 行の検証: 同一物質の重複 / 含有率0 / 100超 / 構成要素の両方指定・未指定 / 原材料フラグオフ /
  101行 → すべて 400。文言に対象のコードが入る
- 合計（STANDARD）: 110% → 400、90% → 200＋警告、99.995% → 200（許容誤差の内側）
- 残部: `0.5 + 40 + 残部` → `totalPct=40.5 / balancePct=59.5`
- 循環: 自己参照も A→B→A も 400「循環参照になるため登録できません」
- 参照チェック: 使われている製品の削除 → 409、使われている物質の削除 → 409、
  原材料利用可をオフ → 200＋「1 件の組成から原材料として参照されています」
- 権限: editor は公開組成を 200 で読めるが、非開示は GET 403・PUT 403。
  非公開製品は 404。viewer は組成も候補検索も 403
- 設定連動: STRICT に切り替えると 90% が 400、残部を禁止すると残部の行が 400。
  許容誤差 20 は 400（0〜10 の範囲外）
- 画面: 物質・原材料・残部を混ぜて登録・保存・再表示。英語表示、モバイル幅375pxで
  ページは横に溢れず、広い表だけがその枠内で横スクロールする
- typecheck / lint / prettier / build / テスト104件すべて通過

## 検証スクリプトの注意（はまったこと）

Windows PowerShell 5.1 は **BOM の無い .ps1 を CP932 として読む**。
日本語コメントの末尾バイトが改行を巻き込み、**次の1行が黙って無効になる**。
検証スクリプトは UTF-8 BOM 付きで保存すること（`git` 管理下のファイルではなく作業用スクリプトの話）。
