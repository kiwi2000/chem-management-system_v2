# LOLI データの気づき（継続記録）

LOLI を取り込むたびに気づいた**間違い・癖・落とし穴**を、ここに足していく。
消さない。同じことに何度もつまずかないための記録なので、
「直った」ものも「いつ直ったか」を書き添えて残す。

書きかたは1件につき次の3つ。**何が起きるか**が分からない記録は役に立たない。

- **何が** … 実際のデータでどうなっているか（具体例つき）
- **どうなるか** … そのまま使うと判定や表示がどう狂うか
- **どうしたか** … こちらでどう扱っているか

## 分子式（CasNames.Formula）

### 塩を「酸.金属」の形で書く

**何が**：クロム酸鉛（CAS 7758-97-6）の分子式が `CrH2O4.Pb`。
これは「クロム酸（H2CrO4）＋ 鉛」という書きかたで、**実際の塩 PbCrO4 には水素が無い**。

**どうなるか**：書かれたとおりに数えると、水素のぶん分子量が大きくなり、
金属の割合が**小さく**出る。

```
書かれたとおり（CrH2O4.Pb）  Pb 63.71％
実際の PbCrO4                Pb 64.11％
```

**小さく出るのは、該当を見落とす向きの誤り。**差は 0.4 ポイントほどで、
閾値のちょうど境目にある製品だけが影響を受ける。

**どうしたか**：書かれたとおりに数えている。直すには塩の価数を知る必要があり、
当て推量になるため。**大事なものは人が実測値を入れて上書きできる**
（`metal_conversion_factors.note` が「LOLIの分子式から計算」以外のものは、
スクリプトが上書きしない）。

2026-08-25 記録。

### 分数で書く

**何が**：`AsO2.1/2Zn`、`Al.2/9BO3.7/5O` のように、成分の個数が分数になる。
`1/2Zn` は「Zn が半分」＝ Zn(AsO2)2 のこと。

**どうなるか**：素直に読もうとすると失敗する。放っておくと 495 種類の分子式が
読めず、その CAS の換算係数が作れない。

**どうしたか**：分数を読めるようにした（`scripts/lib/formula.ts`）。
個数が整数でなくなるが、重さを出すだけなので差し支えない。

2026-08-25 対応済み。

### 分子式が入っていないものがある

**何が**：`CasNames` 652,671 件のうち、分子式があるのは 309,388 件（47%）。
`Unspecified` と書かれているものもある。

**どうなるか**：換算係数を作れない。**係数が無いものは 0 として数える**ので、
判定は実際より少なく出る（見落とす向き）。そのぶん必ず要確認の印が立つ。

**どうしたか**：作れなかったものを件数で出すようにしてある
（`scripts/seed-metal-factors.ts` の「分子式がLOLIに無い」）。

2026-08-25 記録。要る CAS のうち 2,803 件が該当。

### 数が決まらない書きかたがある（x・n・幅）

**何が**：水和水の数を `x` と書く（`Cl2Zn.xH2O`）。重合度を `n` と書く（`(C2H4O)n`）。
組成に幅を持たせる（`Pb0.49-0.51Mo0.49-0.51O1.98-2.02`）。

**どうなるか**：そのままでは計算できない。

**どうしたか**：
- **水和物の `x` は、無水として計算する**（301件）。水のぶん分母が小さくなるので、
  金属の割合は**実際より大きく**出る。多めに出るのは拾いすぎる向きの誤りなので、
  0 にして見落とすよりはよい。**`note` に「（概算）」と付けて後から直せるようにした**
- 重合度の `n` と幅は、そのまま計算できないので係数を作らない

2026-08-25 対応。

### 「.」が区切りにも小数点にもなる

**何が**：`CrH2O4.Pb` の「.」は成分の区切りだが、`PbF2.01`・`Co0.2LiNi0.8O2` の
「.」は小数点。`AsO2.1/2Zn` の「.1/2」は 0.1 ではなく「2分の1」。

**どうなるか**：素直に「.」で区切ると、小数を持つ分子式が全部読めなくなる。

**どうしたか**：**前後がどちらも数字なら小数点**、それ以外は区切り。
ただし数字のあとに「/」が続くときは分数の始まりなので区切りとして扱う。
（`scripts/lib/formula.ts`。試験で固定してある）

2026-08-25 対応。

### 分子式の欄に CAS 番号が入っている

**何が**：`Formula` に `168267-99-0` と書かれている行がある。分子式ではない。

**どうなるか**：読めないものとして落ちるだけで実害は無いが、**LOLI 側の入力誤り**。

2026-08-25 記録。1件。

### 錯体の分子式に、金属が書かれていない

**何が**：コバルト錯体の CAS に、**配位子だけの分子式**が入っている。
たとえば `34523-71-2` は「コバルト及びその化合物」に紐づいているのに、
分子式は `C10H16N2O8`（EDTA）で **Co が無い**。銀・クロムでも同じことが起きている。

**どうなるか**：換算係数を計算できない。**紐づけの誤りとも見分けが付かない**。

**どうしたか**：整合性チェックで拾えるようにした（`scripts/check-integrity.ts`）。
134件。1件ずつ見て、紐づけが正しいなら係数を手で入れる必要がある。

2026-08-25 記録。

## 換算係数のリスト（ListID 9533）

LOLI には**金属換算係数そのものの一覧**がある。分子式から計算しなくてよい。

```
ListID 9533
Japan - Pollutant Release Transfer Register (PRTR)
  - Class 1 Substances - Metal Conversion Factors (2021 Amendment)
```

`ListData.Data` の形はこう。

```
Class 1 Control No. 31 >=1 % [0.507] (as Sb, Ordinance No. 48, [Antimony and its compounds]);
Class 1 Control No. 242 >=1 % [0.493] (as Se, Ordinance No. 277, [Selenium and its compounds])
```

角括弧の数字が係数（割合）、`(as ○○` が換算先。読みかたは
`scripts/lib/loli-metal-list.ts`、投入は `scripts/seed-metal-factors-list.ts`。

### 1行に複数の金属が入る／角括弧が3つの意味を持つ

**何が**：上の例のように `;` で複数の金属が並ぶ。
そして角括弧は**係数**（`[0.507]`）、**物質名**（`[Antimony and its compounds]`）、
**参照先のCAS**（`[1315-05-5]`）の3つに使われる。

**どうなるか**：素直に角括弧を拾うと、物質名や CAS を係数として読んでしまう。

**どうしたか**：**直後に `(as 元素,` が続く角括弧だけ**を係数とみなす。
これで3つを取り違えない。試験で固定してある。

2026-08-26 対応。

### 換算先だけ書いてあって、係数が空欄のものが大量にある

**何が**：`102242-60-4` は `(as Co, ...)` と換算先が書いてあるのに、
係数の角括弧が無い。**LOLI 自身が値を持っていない。**

```
102242-60-4  Class 1 Control No. 132 >=1 % (as Co, Ordinance No. 156, [Cobalt and its compounds])
                                           ↑ [係数] が無い
```

**どうなるか**：組成が分かっていても、金属としての含有率を出せない。
判定はその CAS を 0 として数えるので、実際より少なく出る（見落とす向き）。

**どうしたか**：数を把握できるようにした。2026-08-26 時点で、
換算係数が無い「CAS × 金属等」4,351件のうち **4,260件がこれ**。
残る 91件は PRTR の表そのものに無いもの（Tl・Be・U など、他の法令の金属）。
**LOLI からは埋まらない。**分子式からも計算できなかったものなので、
人が入れるしかない。

2026-08-26 記録。

### 係数のリストと、分子式から計算した値が食い違う（396件）

**何が**：同じ CAS・同じ金属で、リストの係数と分子式から計算した値がずれる。
0.5ポイント以上ずれたものが 396件。**どちらが正しいかは一定しない。**

手で7件あたった結果:

| CAS | 物質 | 分子式の欄 | 手計算 | リストの値 | 正しいのは |
|---|---|---|---|---|---|
| 12228-91-0 | B₄MnO₇ | `B.Mn.O` **壊れている** | Mn 26.1% | 26.1% | **リスト** |
| 74434-12-1 | B₁₂C | `C.B` **壊れている** | B 91.5% | 91.5% | **リスト** |
| 130917-47-4 | Cd₃As₂ | `As12Cd3H18` **壊れている** | Cd 69.2% | 69.2% | **リスト** |
| 13464-28-3 | Hg₃(PO₄)₂ | `H3O4P.3/2Hg` 正常 | Hg 75.4% | 24.0% **＝残りの割合** | 分子式 |
| 12012-17-8 | V₂C | `CV2` 正常 | V 89.5% | 41.0% | 分子式 |
| 12052-62-9 | Co₃Y | `Co3Y` 正常 | Co 66.5% | 22.2% **＝3で割っている** | 分子式 |
| 12017-86-6 | 塩基性クロム酸鉛 | 正常 | — | Pb 37.7%＋Cr 48.1% **酸素があるのに合計85%超** | 分子式 |

つまり、**分子式の欄が壊れているときはリストが正しく、
分子式の欄がまともなときはリストのほうが間違っている**、という並びになる。
LOLI は分子式が読めた物質については独自に計算しており、
その計算に取りこぼしがある。

**どうなるか**：片方を機械的に採ると、396件のどこかで必ず誤る。
含有率が半分になったり倍になったりするので、閾値の判定が反転しうる。

**どうしたか**：**リストの値を採ったうえで、備考に分子式からの値も残す。**

```
LOLIの換算係数リスト（化管法）【分子式からの計算と食い違い: 89.454%】
```

食い違いの一覧は `--diff-out` で書き出せる。1件ずつ人が見て決める必要がある。
リストを本命にしたのは、**分子式の欄が壊れている件数のほうが多い**（1,884件が
そもそも読めない）ため。

2026-08-26 対応。**396件は未確認のまま。**

### 換算先に `CN`（シアン）が出てくる

**何が**：`143-33-9`（シアン化ナトリウム）の換算先が `CN`。元素記号ではない。

**どうなるか**：換算先を「大文字＋小文字」に限っていると、投入時に弾かれる
（実際に `metal_conversion_factors_element_format` 制約で止まった）。

**どうしたか**：制約を元素マスタと同じ `^[A-Z][A-Za-z]{0,2}$` にそろえた
（`prisma/migrations/20260826000000_metal_factor_element_allow_cn`）。
化管法の「無機シアン化合物」を**シアンとして**数えるのは、こちらの設計と同じ
（`docs/judgment-engine.md`）。**LOLI もそう扱っている**ことの裏付けになった。

2026-08-26 対応。

## こちら側のデータの誤り（LOLI とは別だが、同じ場面で見つけたもの）

### 金属換算係数の見本データが誤っていた

**何が**：`1314-41-6`（四酸化三鉛 Pb3O4）に **92.83%** が入っていた。
92.83% は **PbO（1317-36-8）の値**で、CAS を取り違えている。
`1333-82-0`（CrO3）も 52.5% と入っていたが、正しくは 52.0%。

**どうなるか**：鉛丹を含む製品で、鉛の量を 2 ポイント多く見積もる。

**どうしたか**：2026-08-25 時点では**手つかず**。分子式から計算した値で
上書きすると「人が入れた値」を消してしまうため、スクリプトは触っていない。
**見本データなので消してよいはず。確認のうえ直す。**

### （誤りではなかった）元素マスタの `CN`

`elements` に `CN`（シアン）が入っているのは**意図した設計**。
化管法の「無機シアン化合物」は**シアンとして**数えると決めてあり、
金属等の選択肢として要る。元素番号を持たないので 900 番台を振ってある。

`docs/judgment-engine.md` の 65行目・109行目に決定として書かれている。
2026-08-25 に私が誤って「誤り」として挙げたが、記録のほうが正しかった。

なお元素マスタは**元素記号を手で入れるときの選択肢を出すための一覧**であって、
計算用の表ではない。だから原子量は持たない（計算側の
`scripts/lib/atomic-weights.ts` に置いてある）。

### 番号は `Data` ではなく `XML` 欄にある（2026-08-26）

**何が**：土壌汚染対策法・有機溶剤・特別管理物質・化学兵器禁止法の一覧を
「LOLI に番号が無い」と判断していたが、**誤りだった**。

`ListData.Data` は表示用に文章化したもので、番号が落ちている一覧がある。
欄別の元データは `ListData.XML` にあり、そちらには番号が入っている。

```
Data  Present (listed under Cyanide compounds)
XML   <root><row><value>Present</value><refno>05</refno>
                 <listedunder>Cyanide compounds</listedunder></row></root>
```

**どうなるか**：番号で結べるものを「番号なし」と見なし、対応表を手で作っていた。
有機溶剤は名前で突き合わせていたため 4件が取り残されていた。

**どうしたか**：取り出しを `XML` 欄からに作り替えた（`scripts/loli-dump.sh`）。
日本のCASリンクが 95,069件 → 170,284件、リンクの無い法文物質名が 392件 → 92件になった。
手作業の対応表 `scripts/data/isha-org-map.tsv` は不要になった。

`Data` は「表示のための文章」、`XML` は「元のデータ」。**突合には必ず XML を使う。**

### `Data` から切り出すと、区分をまたいで取り違える（2026-08-26）

**何が**：毒劇法（一覧 1015）で、1つのCASが毒物と劇物の両方に載ることがある。

```
12037-82-0
  Deleterious > 0%   [Order Article 2-1-103]   （硫化燐を含有する製剤 → 劇物）
  Poisonous  = 100%  [Law Table 1-27]          （硫化燐そのもの → 毒物）
```

`Data` は両方を `;` でつないだ1本の文字列なので、「Poisonous を含む行の
最初の `[Order Article ...]`」を拾うと、**劇物の号を毒物に付けてしまう**。

**どうなるか**：毒物に劇物の号が20件ほど混ざっていた。

**どうしたか**：`XML` は `<row>` が区分ごとに分かれているので、行単位で
`<category>` を見て絞るようにした。取り違えは消えた。

### 令別表第九の枝番と、則別表第2の枝番を持っていない（2026-08-26）

**何が**：安衛法の表示・通知で、近年の改正で足された枝番の号が LOLI に無い。

```
こちら           LOLI
令別表第9の4-2    無し（9-01〜9-33 まで）
則別表第2の778-2  無し（2-0778 はある）
```

27件が該当する。

**どうなるか**：これらの物質にCASが付かない。判定で漏れる。

**どうしたか**：2026-08-26 時点では**手つかず**。LOLI の更新待ち。
枝番は「元の号から除いたもの」を切り出したものが多いので、
元の号のCASをそのまま引くと**広く取りすぎる**（例：`則別表第2の782-2
１，２－ジクロロエチレン` は `782 １，１－ジクロロエチレン` とは別物）。
**自動では補わない。**

### 有機溶剤・特別管理物質で、1つの欄に号が2つ入る（2026-08-26）

**何が**：`refno` にカンマ区切りで複数の号が入っている行がある。

```
有機溶剤       49, 51          （コールタールナフサ／石油ナフサ）
特別管理物質   2-23-3, 2-27-2
```

**どうなるか**：そのまま鍵にすると、どちらの号にも結び付かない。

**どうしたか**：カンマで分けて両方に結ぶようにした（`scripts/seed-cas-links.ts` の `toKeys`）。

### 製造許可物質の一覧に、令第17条が混ざる（2026-08-26）

**何が**：一覧 1818（安衛法 製造許可物質）に、`code` が `17` で
`addinfo` が `Cabinet Order - Article` の行がある。これは**令別表第三第一号ではなく
令第17条**（石綿の分析用試料等）。

**どうなるか**：`3-1-` の前置きが付かないので突合から外れるだけだが、
「番号が合わない」と警告が出続ける。

**どうしたか**：`addinfo = 'Cabinet Order - Attached Table'` で絞るようにした。

### 中国も `Data` から切り出していたので、同じ穴が空いていた（2026-08-27）

**何が**：`scripts/loli-dump-china.sh` は `Cas` と `Data` の2列を落とし、
取り込む側（`scripts/lib/china-list.ts`）で文章を解析していた。
日本でやめたのと同じ作りで、**穴も同じだった**。

| 穴 | 実測 |
| --- | --- |
| **1つのCASに複数の行があると先頭しか読めない** | 9一覧で 14,392行のうち **1,604行が落ちていた** |
| 番号が `Data` に出ない一覧がある | 易制爆（5380）は序号 `7.11` を持っているのに使えていなかった |
| 1つの欄に序号が2つ入る | 危険化学品目録に7か所（`0102, 1489` など） |

**どうしたか**：`ListData.XML` から取るようにした（`scripts/seed-china-links.ts`）。
中国のCASリンクが 12,717件 → 12,881件になった。

**7つの一覧に序号が入っていた。**`refno` を見る。

```

5380 易制爆         7.11        7583 优先控制（一批） PC001
8535 优先控制（二批） PC023       9637 重点管控新污染物 01

```

番号が無いのは易制毒（2171）と监控（988）だけ。この2つは総称の親（`As … [鍵]`）で結ぶ。

### 総称の親を取るとき、名前の中の角括弧を拾ってしまう（2026-08-27）

**何が**：`As 1-(methylamino)ethyl … [RR-…]` のような remark で、
**最初の `[` から切り出す**と名前の途中を鍵にしてしまう。

**どうしたか**：**一番うしろの `[` から `]` まで**を鍵にした。
角括弧が無い行は行のCAS自身を鍵にする（1項目1CAS）。

### 危険化学品目録（2015版）の序号に誤植が3か所（2026-08-27）

**何が**：番号が1つ飛んで、次の番号が2回出る。

| 抜け | 重複 | 誤植された品目 | LOLI |
| --- | --- | --- | --- |
| 717 | 718 が2回 | 二正丙基过氧重碳酸酯 | **0717 で正しく持っている** |
| 1951 | 1851 が2回 | 十八烷基乙酰胺（1950と1952の間にある） | **1951 で正しく持っている** |
| 2008 | 2009 が2回 | 双过氧化壬二酸 | 2008 は無く、2009 に両方入れている |

**どうなるか**：番号が重なると、突合で先に見つかったほうにCASが付く。
実際、718 の CAS（111-92-2 二正丁胺）が別の品目に付いていた。

**どうしたか**：`scripts/build-china-data.ts` の `fixHazNumbers` で、
**「直前の番号+1 が目録のどこにも無く、印字された番号が他の行と重なる」**ものだけ直す。
3か所とも並び順から番号が確定する。2か所は LOLI も同じ直しをしている。

2008（双过氧化壬二酸）は LOLI が誤植のままなので、**CASリンクが付かない**。
原文が載せている CAS（1941-79-3）は法文物質名の側に入っている。

### 优先控制化学品名录（第二批）は `pdftotext -layout` で読めない（2026-08-27）

**何が**：PDF の CAS の欄が**1行ずれて**出る。

```
pdftotext -layout                    座標で読む（正しい）
  （空行）        75-35-4              PC023  1,1-二氯乙烯  75-35-4
  PC023 1,1-二氯乙烯  78-87-5          PC024  1,2-二氯丙烷  78-87-5
```

**どうなるか**：18品目すべての CAS が1つずれていた。
法文物質名は「CAS 品名」の形で持っているので、**画面に出る名前が間違っていた**。

```
誤  PC027 205-99-2 苯          （205-99-2 は苯并[b]荧蒽）
正  PC027 71-43-2 苯
```

**どうしたか**：`scripts/lib/pdf-rows.ts` を作り、**座標で読む**ようにした。
直したあと、18品目すべての原文CASが LOLI にも在ることを確かめた（18/18）。

### 日本語名の取り出しは `sqlcmd -u` が要る（2026-08-27）

**何が**：`sqlcmd` は既定で**コンソールの文字コード（Shift-JIS）**で書き出す。
日本語名を含む取り出しをそのままTSVにすると、全部化ける。

```
化け  100-00-5  1-\x83N\x83\x8d\x83\x8d-4-...
正    100-00-5  1-クロロ-4-ニトロベンゼン
```

**どうなるか**：物質マスタに化けた名前が入る。画面で読めなくなる。
実際に 7,902件を壊した（気づいて消し、入れ直した）。

**どうしたか**：`-u`（UTF-16LE で出す）を付け、`iconv` で UTF-8 に直す。

```bash
sqlcmd ... -u -i scripts/sql/cas-names.sql -o .cache/cas-names.u16
iconv -f UTF-16LE -t UTF-8 .cache/cas-names.u16 | tr -d '\r' | grep -P '^[0-9]' > scripts/data/cas-names.tsv
```

**鍵とCASだけのTSVは影響しない**（ASCIIしか出てこない）。
`-f 65001` では直らなかった。

### SQLファイルの改行はCRLFにする（2026-08-27）

**何が**：`scripts/sql/*.sql` を LF だけにすると、日本語のコメントがある行で
構文エラーになる。`sqlcmd` が Shift-JIS として読み、日本語の最後のバイトが
次の改行を「2バイト文字の後半」として飲み込むため、コメントが次の行まで伸びる。

**どうしたか**：SQLファイルは CRLF で保存する。
（改行の直前が `\r` なら、飲み込まれるのは `\r` で済み、`\n` が残る）

### REACH 附属書XVII の枝の書き方が一定でない（2026-08-27）

**何が**：LOLI は項番号を `addinfo` に入れるが、枝の書き方が2通りある。

```
50a[b]   項 50a の枝 (b)      → 項は 50a
18[a]    項 18a（水銀）        → 項は 18a。項18の枝ではない
```

REACH 附属書XVII は項18が「水銀化合物」、項18aが「水銀」で**別の項**。
LOLI は項18aを `18[a]` と書いている。

**どうなるか**：一律に角括弧を落とすと、**水銀（7439-97-6）が水銀化合物の項に付く。**
実際に付いていた（項18に537件、項18aは0件）。

**どうしたか**：`18[a]` は**まず `18a` として当て、無ければ `18`** とする
（`scripts/seed-cas-links.ts` の `resolveKey`、ジョブの `bracketAlt`）。
直したあと、水銀は項18a に付き、項18からは外れた。

**取り出しでは括弧を落とさない。**枝の意味は取り込む側で決める。
