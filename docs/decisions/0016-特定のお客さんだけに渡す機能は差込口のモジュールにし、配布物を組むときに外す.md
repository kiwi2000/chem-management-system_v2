# 0016 特定のお客さんだけに渡す機能は差込口のモジュールにし、配布物を組むときに外す

日付: 2026-09-26
状態: 決定

## 背景

SDS 作成機能を、契約したお客さんにだけ渡すオプションにしたい。渡さないお客さんには、
機能が使えないだけでなく、**モジュールのコードそのものを渡さず**、画面（メニュー・システム設定・権限・
マニュアル・変更履歴）のどこにも SDS 作成の存在を出さない。別のオプションがあることも教えない。
一方で、ソースに差込口の名前や DB の表・権限の型が残るのは構わない（2026-09-25 の利用者の判断）。
開発は 1 つのリポジトリ・1 本のブランチのまま行い、別々には開発しない。

## 決定

1. **オプションの機能は `apps/web/modules/<id>/` の 1 フォルダに置く。** 本体はそのフォルダを直接 import しない
   （ESLint の `no-restricted-imports` で止める）。結び目は `scripts/gen-modules.mjs` が作る 2 つの一覧
   （クライアントでも読む `registry.generated.ts` と、サーバーだけの `registry.server.generated.ts`）だけ。
   一覧は dev・build・typecheck・test の前に作り、git には入れない。
2. **有効にするモジュールは組み立てるときに決める。** 環境変数 `CHEM_MODULES`（Railway のサービス変数、
   Dockerfile の `ARG`）か、配布物に同梱する `apps/web/modules/enabled.json`。どちらも無ければ空で、
   **空のときはモジュールのコードがビルドに一切入らない**（一覧が何も import しないため）。
   開発サーバー・typecheck・test は見つかったモジュールを全部有効にする（`gen-modules.mjs all`）。
3. **配布物を組むスクリプトは既定で全モジュールを外す。** `package-release.sh --with sds` /
   `build-install-set.ps1 -With sds` と明示したときだけ入れ、入れた版はファイル名に `-sds` が付き、
   `manifest.json` に `modules` が入る。**入れていない版には版の印を付けない**（付けると他の版の存在が分かる）。
   組んだあと、外したモジュールがソースにも組み立て後（`.next`）にも残っていないことを機械で確かめ、
   残っていれば配布物を作らない。
4. **画面に出るものはすべてモジュールが差込口から足す。** メニューの項目（「ドキュメント」の見出しの直後）、
   画面（`app/[module]/[[...path]]` が `/<id>/…` をモジュールに渡す）、文言（モジュールが両言語を持ち、
   本体の辞書には入れない）。本体が共通の並びから機械的に出すもの（権限・対象の種類・差込項目・列・
   マニュアルの目次・検索・変更履歴）にモジュールの項目を本体側で足さない。
5. **本体のマニュアル・変更履歴・保留事項・お知らせ・導入手順書・文書一式に、モジュールのことを書かない。**
   モジュールの説明と変更履歴はモジュールのフォルダに置き、SDS あり版でだけ目次に差し込む。

## 理由

- 「オンにできない」は、設定やライセンスキーではなく**コードが無いこと**で保証する。設定で止める作りは、
  DB の 1 行を書き換えれば動いてしまう。
- 別リポジトリにしなかったのは、開発を分けたくないという要件のため。1 フォルダ＋生成した一覧なら、
  本体とモジュールをまたぐ変更も 1 つのコミットで済み、typecheck・test も 1 回で通る。
- 一覧を生成する形にしたのは、Next.js が静的な import しか追えないため。フォルダが無い配布物でも、
  一覧が空ならビルドが通る。
- 宣言を 2 つ（manifest / server）に分けたのは、メニューがクライアント側で描かれるため。
  サーバーだけのもの（DB・`next/headers`）がクライアントの束に混ざると壊れる。

## 影響

- 最初のモジュール `sds` は、メニューの項目「SDS 作成」と入口の仮の画面だけ（2026-09-26）。
- 置き場所: SDS なし版は chem.ca-japan.jp（Railway のサービス `chem-management-system_v2`）と評価機、
  SDS あり版は sds.ca-japan.jp（Railway のサービス `sds` ＋ `Postgres-3z1K`。本番の写しから始めた）。
- 本体に無い道筋（`/なんとか`）は `app/[module]` を通ってから 404 になる。状態は 404 のままで変わらない。
- 権限・システム設定の欄・マニュアルの目次・変更履歴の節をモジュールから差し込む口は、SDS 本体を作るときに足す。
