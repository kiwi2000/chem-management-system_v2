# 0013. 物質名での検索は、当たった一覧を渡し直さず、ビューで条件のまま DB に渡す

日付: 2026-09-18 / 状態: 採用

## 背景

「結び付いた物質の名前」で法文物質名・区分・規制対象CASを探す機能は、リンク（`statutory_cas_links`）と
登録物質（`substances`）を CAS番号の文字列で突き合わせる。Prisma は一意でない列（`cas_normalized`）で
関連を張れないので、当初は **先に物質を探して当たった CAS（または法文物質名の id）を全部取り出し、
その一覧を `IN (...)` の条件として付け直す** 2段階で作っていた。

これには上限が付いて回る。PostgreSQL が1回の問い合わせに受け取れる値は **32,767 個**まで（65,535 ではない）。
最初は 2,000 件で黙って切り詰めており、次に 50,000 件で断る形にしたが、50,000 は DB の上限より大きく、
32,767〜50,000 件のあいだ（LOLI の規制対象CASを「m」や「y」で探すと該当する）では
問い合わせそのものが失敗して 500 になっていた。利用者の指摘:
「ID を件数分送るやり方はやめたはずでは。条件だけを送るようにはできないのか」。

## 決定

- **DB にビューを置き、突き合わせを DB の側で済ませる。**
  `statutory_cas_link_names`（リンク × 同じ CAS の登録物質の名前。主名称と別名で1行ずつ）と、
  差分の行に付けた `statutory_cas_link_diff_names`。定義は
  `prisma/migrations/20260918120000_statutory_cas_link_names_view/migration.sql`
- Prisma には `view` として登録し（`previewFeatures = ["views"]`）、リンク側から `names` の関連でたどる。
  ビューはリンクの一意な `id` を参照するので関連が張れる
- アプリは **条件だけ**を組む（`lib/list-columns.ts` の `linkNameCondition`）。
  Prisma が `IN (SELECT ...)` の副問い合わせにするので、当たった件数に上限は無い。
  生の SQL で一覧を引き直す必要も無く、一覧の問い合わせは ORM のまま
- 断る文言（「多すぎます」）と、その上限の定数は全部消す

## 見ておくこと

- 一意でない列で突き合わせたい場面が今後も出たら、同じくビューで解く。id の一覧を渡し直す形に戻さない
- ビューは `prisma migrate` が面倒を見ない。定義を変えるときは `DROP VIEW` → `CREATE VIEW` の
  移行を手で書く
- ビューの列を足したら `schema.prisma` の `view` も合わせる（`prisma db pull` は使わない。
  ほかの表のコメントが消える）
