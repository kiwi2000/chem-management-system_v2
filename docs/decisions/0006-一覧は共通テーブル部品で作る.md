# 0006. 一覧は共通テーブル部品で作る

日付: 2026-08-14 / 状態: 採用

## 背景

物質・製品・法規制など一覧画面が多数できる。
「原則すべてのテーブルに高機能ソート・高機能フィルタ・ページングを設ける」という方針が出たため、
画面ごとに作り込むのではなく、共通部品を1つ用意して全画面で使い回す。

## 決定

### 部品の構成

| 置き場所 | 役割 |
|---|---|
| `packages/shared/src/table.ts` | 状態の型と URL の相互変換。**画面とサーバーで同じ解釈**にする |
| `apps/web/lib/table-query.ts` | 状態 → Prisma の `where` / `orderBy` |
| `apps/web/lib/use-table-state.ts` | URL と端末への保持 |
| `apps/web/components/data-table/` | 見た目（見出しの並べ替え・絞り込み行・ページング） |

各画面は「列の定義」を2つ書くだけでよい。
サーバー側（`QueryColumn`: Prisma のフィールド名・正規化の有無）と
画面側（`TableColumn`: 見出し・表示方法・選択肢）で、**キーを一致させる**こと。
物質の例は `lib/substance-columns.ts` と `app/substances/page.tsx`。

### 絞り込み

列の種類ごとに演算子を出し分ける。複数列の条件は AND で重ねる。

| 種類 | 演算子 |
|---|---|
| 文字列 | を含む / で始まる / で終わる / と一致 / 空白 / 空白でない |
| 数値 | ＝ / 以上 / 以下 / 範囲 / 空白 / 空白でない |
| 日付 | その日 / 以降 / 以前 / 範囲 / 空白 / 空白でない |
| 選択肢 | チェックボックスで複数選択（in） |

- **コード・CAS番号は正規化してから突合する**。全角で入力しても引ける
- 名称・備考は大文字小文字を区別しない
- 日付の「以前」「範囲」は**終わりの日いっぱい**を含む
- 解釈できない条件（数値欄に文字など）は**無視する**。一覧が理由もなく空になるのを防ぐため

### 並べ替え

見出しクリックで 昇順 → 降順 → 解除。**Shift＋クリックでキーを追加**し、見出しに優先順位の数字を出す。
最後に必ず一意な列（コードなど）を足して、ページをまたいでも順序がぶれないようにする。

### ページング

25 / 50 / 100 / 200 件から選べる。既定は50件。

### 条件の保持

- **URL に載せる** … 詳細から戻ったときに同じ一覧に戻れる。URLを人に送れる
- **端末にも覚える** … 条件を付けずに画面を開き直すと、前回の条件を復元する
- **絞り込み中は帯で明示する** … 「絞り込み中 / 条件 2 件 ・ 並べ替え 2 列」と出す
- **「条件をクリア」で全件に戻す** … URL と記憶の両方を消す

前回の条件を黙って復元すると「なぜか件数が少ない」と混乱するので、
**明示とリセットの2点を必ずセットにする**こと。既定の並びのままなら帯は出さない。

## 影響

一覧を作るときは必ずこの部品を使う。使わない一覧を作らないこと（CLAUDE.md にも書いた）。

**並べ替え・絞り込みに使う項目は、その表の列に持つ必要がある。**
Prisma は1対多の子テーブルの項目で並べ替えられないため。
物質の主名称を子テーブルから `substances` の列へ移したのはこのため（別名は子テーブルのまま）。
今後モデルを作るときも「一覧に出す項目は親の列に置く」を意識すること。
