# 0011. データの持ち込みは画面から行い、名前とコードで対応づける

日付: 2026-09-15 / 状態: 採用

## 背景

お客さんのサーバーに入れたあと、当方から渡すものは 3 種類ある。プログラム（不具合修正・機能追加・
基盤の更新）、データソースの新しい版（LOLI・CHRIP）、法規制の変更（区分の新設・閾値の変更・追加）。
このうちデータの 2 つは、いまは DB に直接つなぐ道具（`scripts/copy-to-prod.ts`）でしか運べず、
VPN か現地作業が要る。しかも `copy-to-prod.ts` は「本番に無い法律」しか送れないので、既存の法律の
区分追加や閾値の変更は運べない。ファイルで渡して管理者が取り込める仕組みが無いと、お客さんが増えるほど
当方の作業が増える（`docs/バージョンアップ作業の見積もり.md` §6）。

もう 1 つ、利用者が自分で作ったリスト（社内規制、顧客要求物質リスト）を判定に使いたい要望がある。
利用者は内部の ID もコードも知らないので、法律・区分・番号・法文物質名・CAS といった読める項目だけで
行を書ける必要がある。

なお「LOLI 由来のデータは配布物に入れない」は、プログラムの配布物（誰にでも同じ zip）に同梱しないという
意味であって、**LOLI を契約しているお客さんには LOLI のデータを渡す（渡さなければならない）**。
データはお客さんごとに、契約しているデータソースの分だけを別のセットで渡す。

## 決定

### 1. 取り込みと書き出しは管理画面「データ入出力」から行う

- ファイルをアップロードし、**先に種類と読み取り結果（行数・何が増えるか・食い違い）を見せ、利用者が
  「取り込む」を押してから**書き込む。取り込みは裏で走らせ、進み具合と記録を画面に出す
- 受け取ったファイル・下見の結果・記録は DB に置く（このシステムはファイルを DB に置く方針。
  バックアップに含まれる）
- 書き出しも同じ画面から。取り込めるのと同じ形で出す（控え、当方への事前チェック用、環境の移し替え）
- 取り込み後は「要再計算」が出るので、判定し直しは管理画面の「全製品を判定し直す」を押してもらう
  （自動では走らせない。管理者が時期を選べる）

### 2. 入れ物の形は 2 つ、取り込みの中身は 1 本

| | 利用者の表 | 当方のデータセット |
| --- | --- | --- |
| 形 | 1 表の TSV（Excel で作る。1 行 = 法文物質名 1 つ × CAS 1 つ） | JSON（機械が作る。法律 → 区分 → 分類 → 法文物質名の木を 1 回だけ書き、リンクはコード＋CAS の短い行） |
| 大きさ | 数十〜数百行 | LOLI の 1 版で 63 万リンク、圧縮して 5〜8 MB |
| 対応づけ | 名前と番号（コードは任意） | コード |
| 規則 | 足す・更新（データソース USER） | 足す・更新。お客さんが直した名称・備考は残す（`tools/precheck` の規則） |

- 2 表方式（法文物質名の表と、内部キーで結ぶ CAS の表）は採らない。利用者にキーの管理をさせると
  Excel でいちばん間違えやすい。同じ法律・区分・分類・番号・法文物質名の行はシステムがまとめる
- 表記ゆれ（前後の空白・全角半角）は正規化して同一視し、「似ているが別扱いになる行」は下見で並べて見せる
- 当方の 1 表 TSV で運ばない理由: 法律名・区分名・法文物質名を毎行繰り返すと 150 MB を超える
- 版は足すだけ（[[0010]]）。LOLI の新しい版は、その版のリンクと変わった分の木だけを送る

### 3. 鍵は 3 段。内部 ID はファイルに出さない

| 鍵 | 誰が使うか | 役目 |
| --- | --- | --- |
| 名前・番号 | 利用者の TSV | 初めて取り込むときの対応づけ |
| コード（業務キー） | 当方の JSON は必ず。TSV は任意（書き出しには入る） | 名前を直しても同じものとして更新する。当方の法律に利用者が行を足すときの結び付け |
| 内部 ID（cuid） | システムだけ | 環境ごとに違う。ファイルには出さない |

- 利用者の TSV でコードが空なら名前と番号で探し、無ければ作ってコードを付ける（書き出しに入る）。
  コードがあればコードで探し、名前は更新する
- 番号は区分内で一意でなくてよい（[[chem-statutory-number-not-unique]]）ので、番号だけでは同定しない。
  番号＋法文物質名の組で見る

### 4. ファイルの種類は拡張子で一次判別し、中身でも確かめる

- `.json`（`.zip` の中の `.json` を含む）→ 当方のデータセット。中の形式の印（`"format": "chem-data-set/1"`）が
  無ければ止める
- `.tsv` / `.txt` / `.csv` → 利用者の表。1 行目の列名で「規制リスト／製品と組成／物質」を見分ける。
  列名は日本語・英語どちらでも受け付ける（書き出したファイルの列名と同じ）
- 判別結果と読み取った行数を下見の先頭に出す。判別できない・必須の列が無いときは、足りない列名を示して止める

### 5. 消さない

- 取り込みは足す・更新だけ。行を消さない。古い区分や古い版を消すと判定結果と人の確認結果が連鎖して消える
  （[[chem-regulation-change-by-category]]）ので、規制の変更は「新しい区分を足し、古い区分に終了日を付ける」で運ぶ

## 影響

- 新規: `import_jobs` 表、`apps/web/app/import-export/*` の画面、`apps/web/app/api/admin/import*`・`export*`、
  `apps/web/lib/import/*`（形式の判別・読み取り・突き合わせ・書き込み・裏の実行）、当方側の
  `scripts/build-data-set.ts`（データセットの書き出し）
- `tools/precheck` の突き合わせ（`compare.ts`）を取り込みの下見で使い回す（[[chem-tools-keep-in-sync]]）
- 手順書: 導入手順書の「更新のしかた」を 4 つの場合（プログラム更新の表の変更なし／あり、データソースの更新、
  法規制の変更）に分けて書く。`docs/バージョンアップ作業の見積もり.md` §6 の「未実装」を更新する
