# 0015 判定は判定対象日を持ち、施行前・適用終了は印付きの非該当にする

日付: 2026-09-22
状態: 決定

## 背景

保存する判定は日付で絞らずに計算していた。適用終了日を過ぎた法文物質名にも「該当」と出て、
画面には「施行前」の印しか無かった（適用終了の印は無い）。判定対象日を指定してその場で計算する
仕組みはあったが、保存しないので確認・修正ができず、合算表・帳票・集計は保存判定を見るため、
同じ画面の上下で別のものを見ることになっていた。

PRTR の届出のように「その年度の規制で判定した結果」が要る場面と、法規制の側で
区分を丸ごと新しく作って古い区分も残す運用（0009 / 2026-09-08）が重なり、
「いつの規制で見た判定か」を判定そのものに持たせる必要が出た。

## 決定

1. **判定は必ず判定対象日を持つ。** 組成の保存などの自動の判定は今日、「再計算」は人が日付を選ぶ
   （既定は今日）。日付は判定の行と、製品ごとの「判定を実行した記録」（`ProductJudgementRun`）に残る。
   判定対象日の欄は見出しに読み取りだけで出す。その場で計算して保存しない仕組みは廃止した。
2. **施行前・適用終了の法文物質名・区分は、該当に数えない非該当として印付きで残す。**
   該非（`verdict`）は含有率で決めたまま持ち、`effective`（IN_FORCE / NOT_YET / EXPIRED）で見分ける。
   読む側（判定表・合算表・逆引き・一覧の件数・帳票・PRTR 集計・ポップアップウィンドウ）は
   `effective` が IN_FORCE でないものを該当に数えない。要確認と理由は付けない。
3. **区分が効いていなければ、中の法文物質名も効かない。** 印は区分の行に 1 つ付ける。
4. **人の判断は消さず、効かせないだけ。** 効いていない法文物質名には判断を当てはめず、
   `ProductDecision` はそのまま残す。再び効くようになったとき、前提が同じなら生き返る。
   `premise` に日付や施行状態は入れない（施行日の前後で判断が外れないように）。
5. **要再計算の印に「施行日・適用終了日を跨いだ」を加える。** 判定に付けた印が今日で見ると変わる
   判定があれば、左メニューの印と製品の画面の注意に出す。
6. **帳票・PRTR 集計には施行前・適用終了のものを載せない。**（適用しないものを通知してはいけない）
7. 判定対象日が今日でない判定は、見出しに赤字で断る。帳票にもその判定が載るため。

## 理由

- 該非を変えずに印で分けるのは、人の判断の引き継ぎ（0010）が `systemVerdict` を比べるため。
  施行前を非該当に倒すと、施行日を跨ぐたびに判断が外れる。
- その場で計算する仕組みを残すと「空＝保存判定」の分岐が画面と API の 11 か所に散り、
  確認・修正の口が消えるなどの副作用の元になっていた。動きを 1 つにした。
- 判定行が 0 件の製品（どの法規制にも関わらない）でも日付が要るので、実行の記録を製品ごとに持つ。
  展開結果の `judgedVersionId / judgedAt / judgedAsOf` は最新の記録の写し（一覧・集計が素早く引くため）。

## 影響

- 移行 `20260922230000_judgement_as_of`。既存の判定には計算日を判定対象日として埋め、
  実行の記録を 1 件ずつ起こした。印は付けていない（次の再計算で付く。それまでは要再計算の境目判定が拾う）。
- PRTR の「年度ごとの判定の組」はこの上に載せる（次の設計）。
