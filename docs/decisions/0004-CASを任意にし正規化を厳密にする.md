# 0004. CAS番号を任意にし、正規化を厳密にする

日付: 2026-08-14 / 状態: 採用

## 背景

v1 では CAS番号を必須にしていた。しかし実務では次のものに CAS が付かない。

- ポリマー、UVCB（組成が一定しない物質）
- 組成不明の購入品
- 取引先が企業秘密として開示しない成分

必須のままだと、これらを登録するために暗黙の偽番号（`POLY-0001` など）を入れる運用になり、
「本物の CAS」と「その場しのぎの番号」が同じ列に混在して見分けがつかなくなる。

もう一つの問題として、v1 の正規化は `trim + 大文字化` だけだった。
**法規制リンクと金属換算係数は物質IDではなく CAS で突合する**ため、
全角で入力された `７４３９－９２－１` は `7439-92-1` と別物になり、突合から漏れる。
これは画面上では気づけず、規制の見落としに直結する。

## 決定

1. **CAS番号を任意にする。** 空欄で登録でき、CAS が無い物質は法規制の自動判定の対象外になる
   （判定結果に「キーなし」の警告を出すのは S12/S13 で実装）。
   ただし運用によっては厳密に管理したいので、**必須にするか・形を強制するかはシステム設定で切り替える**
   （既定はどちらもオフ。`docs/steps/S16_システム設定.md`）
2. **正規化を厳密にする。** `normalizeCas()` を新設し、
   全角→半角 → 各種ハイフン（U+2010〜U+2015 / U+2212 / U+30FC / U+FF0D 等）を `-` に統一 →
   空白（全角含む）を除去 → 大文字化
3. **CAS番号は表示用の値も正規化後に揃える。** CAS は表記が一つに決まる識別子なので、
   原文を残しても情報が増えない。一覧で全角と半角が混在するほうが害が大きい。
   一方、物質コードはユーザーが決める業務キーなので原文（大小文字）を残す
4. **形が CAS らしくない場合は警告のみ**にして保存は通す。暫定番号の運用を止めないため
5. **物質コードの正規化にも全角→半角を追加**する

## 結果

- 表記ゆれの吸収を単体テスト20件で固定した。6種類のハイフンと全角数字・全角スペースを検証している
- v1 で `POLY-0001` のような値を CAS 欄に入れていた運用は、CAS を空欄にして
  備考や拡張属性へ移せるようになった

## 影響

CAS が任意になったことで、CAS を前提にする処理（法規制リンクの突合・金属換算）は
**null を必ず考慮する**必要がある。S10 以降で実装するときに漏らさないこと。
