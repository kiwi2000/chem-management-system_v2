# 0007. 非開示の情報は結論だけ見せて中身は隠す

日付: 2026-08-16 / 状態: 採用

## 背景

製品には「非公開（存在ごと隠す）」と「組成非開示（本体は見えるが中身は隠す）」の2段階がある。
この2つは**展開結果と判定結果から漏れる**。S7 でフラグを作る前に、漏れ方の方針を決めておく必要があった。

具体的には、v1 の設計で答えが決まっていなかった2点。

- **Q-G10**: 組成を公開している製品Xの中に、非開示の原材料Yが入っている。
  Xの展開結果に、Yに由来する物質の行を出してよいか
- **Q-A4(b)**: 組成が非開示の製品Zについて、規制該当の判定結果を見せてよいか

## 決定

**Q-G10 — 中身も隠す。** Xの展開結果から、Yに由来する行をすべて落とす。

Yの組成が非開示である以上、「Yに何が入っているか」は隠したい情報そのものである。
Xの展開結果に出してしまえば、Yを直接開かなくても中身が読めてしまい、非開示の意味が無くなる。
「Xの中にYが入っている」という事実まで隠すかどうかは、Yの `private_flag` の側で決まる。

**Q-A4(b) — 結論だけ見せる。** 該当する規制区分は読めるが、根拠は見せない。

判定結果（どの区分に該当するか）は業務上どうしても必要で、これを隠すと
非開示の製品は一切扱えなくなる。一方、根拠（どの物質が何パーセント含まれるから該当）は
組成そのものなので隠す。`COMPOSITION_VIEW_PRIVATE` を持つ人にだけ根拠を出す。

## 前提となる実装（S7 で入れたもの）

- 非公開の製品は、権限が無ければ**一覧から除外し、件数にも入れず、詳細は 404**（403 ではない）。
  403 だと「その ID の製品は在る」と分かってしまう
- 除外はすべて**サーバー側**で行う。画面で隠すだけにはしない
- 機密のフラグは、対応する閲覧権限を持つ人しか**変更できない**。
  自分が見られない区分を切り替えられるのはおかしいため

## 影響

実装するのは組成・展開・判定を作る段階になる。

- S8（組成エディタ）: 原材料の候補に非公開の製品を出さない
- S11（展開・逆引き）: 非開示の原材料に由来する行を落とす（Q-G10）
- S13（判定UI）: 根拠の表示を `COMPOSITION_VIEW_PRIVATE` で出し分ける（Q-A4(b)）
- S15（TSV出力）: 出力にも同じ除外を掛ける。持ち出しは最も漏れやすい経路なので忘れないこと
