# 0007. 非開示の情報は結論だけ見せて中身は隠す

日付: 2026-08-16 / 状態: 採用

## 背景

製品には「非公開（存在ごと隠す）」と「組成非開示（本体は見えるが中身は隠す）」の2段階がある。
この2つは**展開結果と判定結果から漏れる**。S7 でフラグを作る前に、漏れ方の方針を決めておく必要があった。

具体的には、v1 の設計で答えが決まっていなかった2点。

- **Q-G10**: 組成を公開している製品Xの中に、非開示の原材料Yが入っている。
  Xの展開結果に、Yに由来する物質の行を出してよいか
- **Q-A4(b)**: 組成が非開示の製品Zについて、規制該当の判定結果を見せてよいか

## 決定

**Q-G10 — 中身も隠す。** Xの展開結果から、Yに由来する行をすべて落とす。

Yの組成が非開示である以上、「Yに何が入っているか」は隠したい情報そのものである。
Xの展開結果に出してしまえば、Yを直接開かなくても中身が読めてしまい、非開示の意味が無くなる。
「Xの中にYが入っている」という事実まで隠すかどうかは、Yの `private_flag` の側で決まる。

**Q-A4(b) — 結論だけ見せる。** 該当する規制区分は読めるが、根拠は見せない。

判定結果（どの区分に該当するか）は業務上どうしても必要で、これを隠すと
非開示の製品は一切扱えなくなる。一方、根拠（どの物質が何パーセント含まれるから該当）は
組成そのものなので隠す。`COMPOSITION_VIEW_PRIVATE` を持つ人にだけ根拠を出す。

## 前提となる実装（S7 で入れたもの）

- 非公開の製品は、権限が無ければ**一覧から除外し、件数にも入れず、詳細は 404**（403 ではない）。
  403 だと「その ID の製品は在る」と分かってしまう
- 除外はすべて**サーバー側**で行う。画面で隠すだけにはしない
- 機密のフラグは、対応する閲覧権限を持つ人しか**変更できない**。
  自分が見られない区分を切り替えられるのはおかしいため

## 影響

実装するのは組成・展開・判定を作る段階になる。

- S8（組成エディタ）: 原材料の候補に非公開の製品を出さない
- S11（展開・逆引き）: 非開示の原材料に由来する行を落とす（Q-G10）
- S13（判定UI）: 根拠の表示を `COMPOSITION_VIEW_PRIVATE` で出し分ける（Q-A4(b)）
- S15（TSV出力）: 出力にも同じ除外を掛ける。持ち出しは最も漏れやすい経路なので忘れないこと

## 追記（2026-09-13）— 組成が漏れる経路の総点検

`COMPOSITION_VIEW` を持たない利用者（`PRODUCT_VIEW` などは持つ）で、組成に触れるすべての
経路を実際に叩いて調べた（`.cache/probe-comp.ts`。製品の CAS・物質コード・含有率・原材料コードが
応答に載るかを見る）。次の 4 つが漏れており、同日に塞いだ。

| 経路 | 何が漏れていたか | 直しかた |
| --- | --- | --- |
| `GET /api/products?f.casNumbers=…` `f.substanceNames=…` | 「この CAS（物質名）を含む製品」を一覧で探せた。製品を開かなくても組成が分かる | 組成をたどる列は `productColumns(versionId, withComposition)` で見られる人にだけ付ける。無い人からの条件は黙って捨てる。画面の絞り込み欄も出さない |
| `GET /api/statutory-cas-links/cell?…&productId=` | 「当たり」「含有率不足」がその製品の含有率から決まる。閾値の違う号を並べれば含有率まで絞れる | 製品を指定した問い合わせは `COMPOSITION_VIEW` 必須（403）。製品なしなら法律側のデータだけなので誰でもよい |
| 帳票の「法規制判定」の表 | 当たった法文物質名が号ごとに並び、「その物質が入っている」と分かった。中国の目録のように名前に CAS が入るものもある | `toJudgementDtos(…, withHits)` を `canViewComposition` で渡す。見られない人は区分ごとの該非だけ（番号・法文物質名は空） |
| `/documents/[templateId]/[targetId]`・`/batch` の画面 | 権限の確認が無く、ログインしていれば誰でも帳票を作れた。未公開の製品も対象にできた | `DOCUMENT_CREATE` を要求（保存した帳票の画面と同じ）。製品は `visibilityWhere(actor)` で絞る |

あわせて、根拠を伏せる相手には**根拠を DB からも引かない**ようにした（`loadJudgementRows`）。
引いてから捨てる作りだと、開発サーバーのサーバー部品のデバッグ出力（React の非同期デバッグ情報）に
Prisma の生の行が載り、DTO を通らずに含有率まで出ていた。本番ビルドでは出ないが、
そもそも引かなければ経路が無い。

権限の含意（製品を編集できる → 組成を見られる）は保存時に閉じていたが、読むときにも
`expandPermissions` で閉じるようにした。直接書き込まれた行でも同じ答えになる。

**漏れではないと判断したもの**

- 法律の側からの逆引き（この区分に当たる製品の一覧）… 区分ごとの該非は見せてよい。根拠は伏せている
- 物質の画面・API … 物質マスタの CAS と名前。どの製品に入っているかは出していない
- 物質の削除で返す「N 件の製品で使われています」… 件数だけで製品は分からない。低い
- アクセス記録（管理者のみ）… 組成を見た記録に行数が載る。記録そのものが目的
