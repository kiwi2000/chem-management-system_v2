# 第1部 — 前回デプロイ時点の仕様

初回デプロイ（`97614a3`）で公開した内容。S0〜S8 と S16 系までが入っている。

## 1. 全体の作り

| | |
|---|---|
| 構成 | Next.js 15（App Router）＋ Prisma 6 ＋ PostgreSQL のモノレポ |
| ワークスペース | `apps/web`（画面とAPI）、`packages/shared`（型・検証・文言）、`packages/domain`（枠のみ） |
| 認証 | **完全に自前**。外部サービスに一切依存しない |
| 多言語 | 日本語が正本。ソース内の辞書で管理し、英語のキー漏れはビルドで落ちる |
| 数値 | 含有率・係数は Decimal（Float 禁止） |

## 2. ログインとユーザー

- メールアドレス＋パスワード。MFA を有効にした人は6桁コードの欄が出る
- パスワードは Argon2id。Cookie には推測不能なトークンだけを入れ、DB にはその SHA-256 を保存
- 連続失敗でロックアウト。パスワード変更で他端末のセッションを全失効
- 初期パスワードは管理用スクリプト（`scripts/set-password.ts`）で発行する
- 個人設定で表示名・言語・テーマ・背景を変更できる

## 3. 権限

**役割ではなく権限そのものを持たせる**（`docs/decisions/0003`）。13種類。

| グループ | 権限 |
|---|---|
| 製品 / 原材料 | 製品を見られる／非公開の製品も見られる／製品を編集できる |
| 組成 | 組成を見られる／非公開の組成も見られる |
| 物質 | 物質を見られる／物質を編集できる |
| 法規制 | 法規制を見られる／法規制を編集できる |
| データ | データを出力できる |
| お知らせ | お知らせを投稿できる／他人のお知らせも編集・削除できる |
| システム | システム管理 |

「編集できるが見られない」は成立しないので、付与時に含意を自動で展開して保存する。

## 4. 物質マスタ

| 項目 | 内容 |
|---|---|
| 物質コード | 20文字。正規化（全角→半角・大文字化）して一意 |
| CAS番号 | 既定は任意。必須にするか・形を強制するかはシステム設定で切替 |
| 状態 | 有効 / 無効 |
| 主名称 | 日本語（必須）・英語（任意） |
| 別名 | 日本語名＋英語名の組を複数 |
| 官報公示整理番号 | 区分（化審法・安衛法・その他）付きで複数 |
| 拡張属性 | 管理者が定義した項目（数値／テキスト） |

削除は論理削除。正規化コードを退避するので、**同じコードを再登録できる**。

## 5. 製品 / 原材料マスタ

**製品と原材料は同じもの**で、`usable_as_material` が立っているものだけ他製品の組成に入れられる。

| 項目 | 内容 |
|---|---|
| 製品コード | 20文字。物質と同じ扱い |
| 名称 | 日本語（必須）・英語（任意） |
| 状態 | 使用中 / 廃番 |
| 別名 | 日本語名＋英語名の組を複数 |
| 原材料として使える | チェックボックス |
| 非公開 | オンだと権限が無い人には**存在ごと**見えない |
| 組成公開 | オフだと本体は見えるが組成は非開示 |
| 拡張属性 | 物質と共通の仕組み |

## 6. 組成

製品に「何がどれだけ入っているか」を**1段だけ**登録する。構成要素は物質か他製品のどちらか。

- 含有率は重量%。残部（balance）の行を1件だけ置ける
- 合計の検証はシステム設定で厳しさを切り替える（厳格／標準／緩和・許容誤差）
- 循環参照（自分を原材料にする、たどると自分に戻る）は保存時に弾く
- 無効な物質・製品は候補に出さない
- 多段の展開（S11）と判定（S12）は未実装

## 7. 一覧（共通テーブル）

すべての一覧は同じ部品を使う（`docs/decisions/0006`）。

- 列ごとの絞り込み・複数列の並べ替え・ページング
- 条件は URL に載るので、詳細から戻ると同じ一覧に戻れる。端末にも記憶する
- 列幅はドラッグで変更でき、端末に記憶する
- 行はダブルクリックで詳細。チェックして上のボタンでまとめて削除

## 8. その他

- **お知らせ** … 下書き／公開、掲載期間、固定表示。ホームでグループ別に見出しを分けて表示
- **金属換算係数** … CAS番号と金属元素の組で重量%を登録
- **グループ管理** … お知らせの分類と組織の所属
- **拡張属性の管理** … 物質用・製品用の項目定義
- **システム設定** … CAS の扱い、組成の検証ポリシー

## 9. まだ無いもの

法規制マスタ、リンク、組成の展開、規制該当の判定、逆引き検索、TSV取込／出力、ドキュメント生成。
サイドバーに項目はあるが画面は未実装。

# 第2部 — 前回デプロイ以降の変更

2026-08-20 の作業分。実画面を見ながら出た指摘を反映した。
**この内容はまだデプロイしていない。**

## 1. 可視性の考え方を入れ替えた

### 1.1 製品ごとの公開フラグを廃止

`private_flag`（非公開）と `composition_public_flag`（組成公開）を**列ごと削除**した。
誰に何を見せるかは、製品ごとのフラグではなく**ユーザーの権限**で決める。

### 1.2 「ドラフト」を追加

入力の途中で、まだ他の人に使わせたくない状態を表すフラグ（`draft_flag`）を物質・製品に追加した。
**有効／無効とは別の軸**で、廃番（無効）と入力途中（ドラフト）を区別できるようにしたもの。

- **新規登録は必ずドラフトから始まる**
- 保存（PUT）ではこのフラグは動かない。**完成にするのは意識的な操作だけ**
- 詳細画面の「完成にする」／「ドラフトに戻す」ボタンで切り替える
- 一覧で行を選んで「選択した行を完成にする」で一括変更。権限が足りない行は飛ばし、件数の差を知らせる
- ドラフトであることを見落とすと未完成のデータが他の人に渡ってしまうので、
  バッジは琥珀色で大きく、「完成にする」は塗りつぶしのボタンにして目立たせている

### 1.3 見せる範囲

| 対象 | 一覧・詳細 | 組成の候補 | 組成の中の名前 |
|---|---|---|---|
| 物質・無効 | 誰でも見える | 出ない | **出る** |
| 物質・ドラフト | 作成者と権限者のみ | 出ない | **出る** |
| 製品・無効 | 作成者と権限者のみ | 出ない | **出る** |
| 製品・ドラフト | 作成者と権限者のみ | 出ない | **出る** |

**組成の中の名前は必ず出す。** ここまで隠すと、無効な物質を含む製品の組成が読めなくなるため。
一覧・詳細から隠すのと、参照先の名前を出すのは、別の話として切り分けている。

物質の無効を隠さないのは、廃番品の問い合わせ対応・法規制の遡及調査が
「無効になったものを調べる」作業そのものだから。

権限が無い人が無効な製品の詳細を開くと **404**（403 だと「その ID の製品は在る」と分かってしまう）。

### 1.4 権限の入れ替え

使われなくなった2つを削除し、代わりに2つ追加した。**総数は13のまま**。

| 削除 | 追加 |
|---|---|
| `PRODUCT_VIEW_PRIVATE` | `INACTIVE_VIEW`（無効・ドラフトのデータも見られる） |
| `COMPOSITION_VIEW_PRIVATE` | `INACTIVE_EDIT`（無効・ドラフトのデータも編集できる） |

`INACTIVE_EDIT` は `INACTIVE_VIEW` を含意する。**作成者は権限に関係なく自分のデータを扱える。**

## 2. 項目の変更

### 2.1 別名を日本語・英語で分けた

日英の件数は一致しない（1対1にならない）ため、**別々の一覧**にした。1行1名称。
`name_ja` を NULL 許容にし、「どちらか一方が入っていればよい」に変えている。物質・製品の両方。

### 2.2 製品に「型式」「用途」を追加

拡張属性で代用していた型式を専用の項目にした。

| 項目 | 形 | 保存先 |
|---|---|---|
| 型式 | 単一選択 | `products.model_value` |
| 用途 | 複数選択 | `product_uses`（子テーブル） |

選べる値は**システム設定**で管理する。1行1件で入力し、**並べた順がそのまま表示順**。
設定から選択肢を消しても、既に選ばれている値は選択肢に残す（過去の記録を勝手に変えない）。

### 2.3 状態の表記

「使用中 / 廃番」→ **「有効 / 無効」**（物質側に合わせた）。プルダウンをやめてチェックボックスにし、
「状態」というラベルは出さず、チェックの状態そのもの（有効／無効）を見出しに出す。

## 3. 一覧のフィルター

### 3.1 保存と読込

一覧のある画面**すべてで共通**に、フィルターを保存・読込できるようにした。

- 保存時に名前を付ける。同じ画面・同じ名前なら上書き
- 「全員が使えるようにする」で共有できる。共有分は作成者名が付く
- 削除できるのは作った本人と管理者
- 保存先は DB（`saved_filters`）。端末が変わっても使える
- 条件はクエリ文字列で持つので、後で列構成が変わっても読めるものだけが効く

### 3.2 組成情報（CAS番号）で絞り込む

製品一覧に「組成情報」の節を追加し、組成に含まれる物質の CAS 番号で絞り込めるようにした。

- 複数行の入力欄。**数字とハイフン以外はすべて区切り**（改行・カンマ・空白・日本語が混ざってよい）
- 照合は**完全一致**（正規化して突合）。部分一致しない
- 「いずれか」＝ OR ／「すべて」＝ 値ごとの条件を AND

**制限**: その製品に直接ぶら下がる組成行だけを見る。原材料の中身（孫）はたどらない（S11 の範囲）。

### 3.3 型式・用途で絞り込む

どちらも複数選択。**未選択なら全件**、選んだ場合は**そのいずれかを含むもの**。両方指定すると AND。

### 3.4 その他

- 選択肢が2つの列（有効／無効、原材料／原材料以外）は、開かずにその場にチェックボックスを並べる。**既定は両方 ON**
- 必ず値が入る列では「空白」「空白でない」を出さない
- 製品一覧は並びを指定した。「基本情報」「組成情報」の節に分かれる

```
基本情報
  製品コード [____] を含む   □有効 □無効   □ドラフト □完成   □原材料 □原材料以外
  日本語名称 [________________________________]
  英語名称   [________________________________]
  型式 [▼すべて]   用途 [▼すべて]
  更新日 [__/__/__] 指定日      備考 [____] を含む

組成情報
  CAS番号   [複数行入力]  いずれか／すべて
```

## 9. 承認の流れ（S10）

物質・製品を公開するのに承認を通すかどうかを、**システム設定で種類ごとに切り替え**られるようにした。
`draft_flag`（真偽値）では4つの状態を表せないため、`publish_state` に置き換えている。

```
新規登録 ──▶ 作成中
              │
    承認必要 ─┼─ 申請 ──▶ 承認待ち ─ 承認 ──▶ 公開済
              │              └─ 却下 ──▶ 却下 ─ 再申請 ─▶ 承認待ち
    承認不要 ─┴─ 発行 ────────────────────▶ 公開済

公開済 ── 作成中に戻す（参照チェックあり）──▶ 作成中
```

- **新規登録は必ず作成中**。保存してもこの状態は動かない
- **承認待ちは編集できない**。直すときは「申請を取り下げ」で作成中に戻す
- 却下されたものを**編集して保存すると、作成中に戻る**。
  直したのに却下のまま並んでいると、対応が済んだのか分からなくなるため。
  履歴には「却下されたものを直したため」として残る
- 却下には理由を添えられる（任意）
- 自己承認は許す。誰が承認したかは履歴に残る

### 公開を取り消すときの参照チェック

**公開済の組成から参照されている間は、公開を取り消せない。**
取り消すと、公開済の製品が使えない構成要素を含む状態になるため。

409 で断り、対象の製品コードを挙げて「先にその製品を作成中に戻してください」と伝える。

### 履歴

申請・承認・却下・取り下げ・公開取消を `approval_events` に残す。
物質と製品で共通に使うため、監査ログと同じく entity + entityId で対象を指し、物理FKは張らない。
詳細画面の下に新しい順で並べ、編集できる人と承認できる人にだけ見せる。

### 一覧を上下2つに分けた

| | 中身 | 見出し | 出る条件 |
|---|---|---|---|
| 上 | 公開済 | 無し（画面の見出しがそのまま） | 閲覧権限があれば誰でも |
| 下 | 作成中・承認待ち・却下 | 「作業中」 | `INACTIVE_VIEW` か編集権限か `APPROVE` を持つ人 |

グループ管理と同じ作り（`useTableState` の `paramPrefix` で URL のクエリを節ごとに分ける）。
状態を変えると下から上へ移るので、**両方を読み直す**。
下の表には一括操作（承認が要るなら「選択した行を申請」、不要なら「選択した行を発行」）を置いた。
上の表には「公開の状態」の列を出さない（全部同じ値になるため）。節の見出しも付けない。公開済が既定の一覧であり、そこに名前を付けると
かえって「別のもの」に見えるため。下の表が出ない人には、普通の一覧がそのまま見える。

### 権限

`APPROVE`（承認できる）を追加して14種類にした。含意は無く、承認だけできる人がいてよい。

### 設定を切り替えたとき

- 「不要 → 必要」… 公開済はそのまま。再承認は求めない
- 「必要 → 不要」… **承認待ちのものが残っていると保存できない。**
  承認する人がいなくなるため、保存時に件数を出して「公開する」か「作成中に戻す」かを選んでもらう。
  どちらを選んでも履歴に「承認を不要に切り替えたため」として残る

## 11. デプロイ後にすること

**権限の付け直しが必要。** マイグレーションで `PRODUCT_VIEW_PRIVATE` と
`COMPOSITION_VIEW_PRIVATE` が付与済みユーザーから削除されるので、
ユーザー管理画面から `INACTIVE_VIEW` / `INACTIVE_EDIT` / `APPROVE` を必要な人に付ける。
付けないと、無効・ドラフトのデータが自分の作成分しか見えない。

また、**新規登録は必ずドラフトで始まる**。他の人に使わせるには、詳細画面の「完成にする」か、
一覧で選んでの一括変更が必要になる。
