# 法規制データの作り方

法規制のデータをどこから、どうやって作るかの仕様書。
**次に作る人が、同じものを同じ手順で作れる**ようにするためのもの。

作業の記録（何件入ったか）は `docs/LOLI取り込み記録*.md` に分けてある。
ここには**手順と決めごと**だけを書く。

---

## 0. 原則

**法律の情報と、CAS番号は、別のところから取る。**

| 何を | どこから | なぜ |
| --- | --- | --- |
| 法律・規制区分・**法文物質名**・番号 | **法令の一次資料**（e-Gov 法令API、J-CHECK など） | 法律が決めるもの。外部データベースに依存してはいけない |
| **法文物質名に該当するCAS** | **外部データベース**（LOLI など） | 「この法文物質名にどのCASが当たるか」の判断が難しく、面倒だから買っている |

この順序は逆にできない。**法文物質名を外部データベースから作ってはいけない。**
LOLI が「この法文物質名だと思っているもの」が、条文のどの項目にあたるかは、
LOLI 側の解釈であって、法律そのものではない。

## 1. 全体の流れ

```
① 一次資料から  法律 → 規制区分 → 法文物質名（＋番号）を作る
② LOLI を読み   法文物質名 ↔ CAS のリンクを作る（statutory_cas_links）
③ 突合できなかったものを一覧に出し、人が結びつける
④ ③の結びつけを保存し、次回の取り込みで再利用する
```

②で**何を鍵に突き合わせるか**が、規制区分ごとの設定になる（第4章）。

## 2. 一次資料の取り方

### 2-1. e-Gov 法令API（条文に一覧が載っている法令）

画面は JavaScript で描くので `WebFetch` では中身が取れない。**API を使う。**

```bash
curl -s -o egov.xml "https://laws.e-gov.go.jp/api/1/lawdata/<法令ID>"
```

返る XML の構造。**条（`Article`）の下に号（`Item`）が並ぶ。**

```xml
<Article>
  <ArticleTitle>第一条</ArticleTitle>
  <ArticleCaption>（第一種特定化学物質）</ArticleCaption>
  <Item>
    <ItemTitle>一</ItemTitle>
    <ItemSentence>ポリ塩化ビフェニル</ItemSentence>
  </Item>
  ...
</Article>
```

取り出し方（`ItemTitle` は漢数字なので算用数字に直す）。

```python
import xml.etree.ElementTree as ET
r = ET.parse('egov.xml').getroot()
for art in r.iter('Article'):
    cap = art.findtext('ArticleCaption') or ''
    if '第一種特定化学物質' not in cap:
        continue
    for it in art.iter('Item'):
        num  = it.findtext('ItemTitle')                       # 「一」「二十三」
        name = ''.join(it.find('ItemSentence').itertext())    # 物質名
```

**法令IDの調べ方。**全法令の一覧を1回引いて、法令名で探す。

```bash
curl -s -o lawlist.xml "https://laws.e-gov.go.jp/api/1/lawlists/1"   # 約2.8MB
# <LawNameListInfo> の <LawName> / <LawId> / <LawNo>
```

化審法の監視化学物質・優先評価化学物質・特定一般化学物質は**政令に載っていない**。

### 2-3. 使ってはいけないもの

- **経済産業省のページ（`meti.go.jp`）は 403 を返す。**API も無い。件数の確認には使えない
- 民間のまとめサイト。更新が遅れていることがあり、一次資料にならない

## 3. 名前の表記の決めごと

**官報どおりではなく、NITE / CHRIP と同じ書き方にする。**

| | 官報（e-Gov） | このシステム |
| --- | --- | --- |
| 数字 | 漢数字「一・二・三・四・十・十―」 | **算用数字**「１，２，３，４，１０，１０－」 |
| 参照句 | 「（別名マイレックス。第七条の表九の項において「マイレックス」という。）」 | **「（別名マイレックス）」** |
| 記号 | 「Ｎ・Ｎ′」 | 「Ｎ，Ｎ’」 |
| tert- | ターシャリ | **ターシャリ**（統一する） |

理由。画面で読むもので、CHRIP を見ながら照合する場面が多い。
官報どおりにすると化学名の中が漢数字になり、実用に耐えない。

**照合するときは、この違いを吸収してから比べる**（第6章）。

## 4. LOLI との対応

### 4-1. LOLI のデータの形

`ListData` の **1行 ＝ 1つのCAS × 1つの一覧（ListID）**。
その行の `Data` に「そのCASが、その法令のどの項目に載っているか」が文字列で入る。

```
ListID 1015（毒劇法）
  Cas  : 10022-68-1
  Data : Deleterious =, 100% [Order Article 2-1-22] (listed under Cadmium compounds, except ...)
                              ~~~~~~~~~~~~~~~~~~~~              ~~~~~~~~~~~~~~~~~~
                              指定令2条1項22号                   項目の名前（英語）
```

**やることは、こちらの法文物質名の番号と、この番号を突き合わせること。**
一致した行の `Cas` が、その法文物質名に付くCAS。1つの法文物質名に何十〜何百件付くのが普通。

**`Control No.` を使ってはいけない。**化管法には番号が2種類あり、

```
Specific class 1 Control No. 406 ... (Ordinance No. 459, [Polychlorinated biphenyls])
                            ↑LOLI独自の管理番号        ↑政令番号（こちらと同じもの）
```

`Control No.` は LOLI 独自のもので、政令番号とは別物。
ポリ塩化ビフェニルで確かめたところ、政令番号459番がPCBで、`Control No. 406` は
無関係の物質だった。**必ず `Ordinance No.` を使う。**

### 4-3. 番号の突き合わせかた

**2段階で当てて、どちらで付いたかを記録する。**

1. **そのまま一致**（無加工）
2. 付かなければ **正規化して一致**

正規化の規則。

```
① 全角→半角          ７４３９ → 7439
② 空白を落とす
③ ハイフン類を統一     ‐ ‑ – — − → -
④ 「の」→ -           9の4 → 9-4
⑤ 括弧を落とす        (5)-3714 → 5-3714
⑥ 数字ごとに先頭ゼロを落とす   0486 → 486、05-01 → 5-1
⑦ 英字を大文字に
```

**区切りは落とさず、統一だけする。**落とすと `1-10` が `110` になり、
本物の `110` とぶつかる。**取り違えは、突合できないことよりずっと悪い。**

**正規化でしか付かなかったものは、人が見て確かめられるようにする。**
黙って正規化すると、⑥のような規則が悪さをしたときに気づけない。

### 4-4. 番号が無い一覧

LOLI 側に番号が無く、**項目の名前しか無い**一覧がある。実測した規模は次のとおり。

| 法令 / 区分 | LOLI の項目数 | こちらの法文物質名 |
| --- | ---: | ---: |
| 安衛法 有機溶剤 | 47種 | 44件 |
| 土壌汚染対策法 特定有害物質 | 26種 | （未登録） |
| 安衛法 鉛 | 15種 | （未登録） |
| 化学兵器禁止法（6区分） | 1〜15種 | （未登録） |

**どれも数十件。対応表を1回作れば終わる規模。**
文字列の完全一致を狙わない（「カドミウム化合物」と「カドミウム及びその化合物」は
規則を書くほど別のところで誤る）。**候補を出して人が確定し、結果を保存する。**

### 4-5. 番号も項目名も無い一覧

ダイオキシン類対策特別措置法（7783）は `present` のみ。
区分が1つなので、**一覧の全CASをその1件に付ける**で済む。

## 5. 突合できないものの扱い

| 型 | 対処 |
| --- | --- |
| こちら側に番号が無い | 番号以外の鍵を区分の設定で選ぶ |
| LOLI 側に番号が無い | 4-4 の対応表 |
| 番号体系が違う | 4-4 の対応表 |
| **1つの号に法文物質名が複数ある** | 番号だけでは1対1にならない。対応表で分ける |

最後のものは実在する。毒劇法 劇物の号16に「クロルエチル」と
「塩化水素を含有する製剤」の2件がある。

## 6. 照合のしかた（作ったあとの確認）

**件数 → 番号 → 名前**の順に見る。

1. **件数**が一次資料と合うか（J-CHECK の「〜件中」、e-Gov の `Item` の数）
2. **番号**が飛んでいないか、余分が無いか
3. **名前**が合うか。第3章の表記の違いを吸収してから比べる

**名前は `name_original` に入っている。**`name_ja` は空のことが多いので、
照合も更新も `coalesce(name_ja, name_original)` で扱う。
片方だけ直すと、画面に出る名前が変わらない。

名前を比べる前の正規化（照合のためだけのもの。保存する名前は変えない）。

```
・NFKC 正規化（全角英数を半角に）
・括弧書き（別名・参照句）を落とす
・中黒「・」読点「，」を落とす
・ハイフン類を落とす
・空白を落とす
・化学名の中の漢数字を算用数字に
・小文字化
```
