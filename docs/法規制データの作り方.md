# 法規制データの作り方

法規制のデータをどこから、どうやって作るかの仕様書。
**次に作る人が、同じものを同じ手順で作れる**ようにするためのもの。

作業の記録（何件入ったか）は `docs/LOLI取り込み記録*.md` に分けてある。
ここには**手順と決めごと**だけを書く。

---

## 0. 原則

**法律の情報と、CAS番号は、別のところから取る。**

| 何を | どこから | なぜ |
| --- | --- | --- |
| 法律・規制区分・**法文物質名**・番号 | **法令の一次資料**（e-Gov 法令API、J-CHECK など） | 法律が決めるもの。外部データベースに依存してはいけない |
| **法文物質名に該当するCAS** | **外部データベース**（LOLI など） | 「この法文物質名にどのCASが当たるか」の判断が難しく、面倒だから買っている |

この順序は逆にできない。**法文物質名を外部データベースから作ってはいけない。**
LOLI が「この法文物質名だと思っているもの」が、条文のどの項目にあたるかは、
LOLI 側の解釈であって、法律そのものではない。

## 0-2. CAS の持ち方（2026-08-26 決定）

法規制には**2つの型**がある。

```
A型「名称で規定」… 法令に物質名しか無い。CASの割り当ては外部データベースに頼る
B型「CASで規定」… 法令が CAS を併記している
```

実測すると、**日本はすべてA型**（使っている法令9本すべて CAS が1件も無い）、
**米国・EU・中国はB型**だった。

### 判定に使う CAS は LOLI だけから取る

B型でも、**判定に使う CASリンクは LOLI に一本化する。**

| | |
| --- | --- |
| なぜ | **出どころが2つあると、どちらで判定したのか分からなくなる** |
| 根拠 | 中国で実測したところ、LOLI は**原文の CAS を1件も取りこぼさず**、2.66倍に増やしていた |

```
中国 危険化学品目録（1序号1CASできっちり規定されている型）
  原文が載せる CAS   2,685件
  LOLI が結んだ CAS  7,132件（2.66倍）
  原文にあって LOLI に無い CAS   0件
```

足しているのは**同じ物質を指す別の CAS**（異性体・水和物・重合度違い）。
たとえば `甲基环己醇`（原文 25639-42-3）に 2-・3-・4- の異性体が付く。
**原文だけで結ぶと、これらを取り逃す。**

### 法律が示す CAS は法文物質名の側に持つ

捨てるのではなく、**判定とは別の場所に残す**。

| 番号の欄 | どうするか | 例 |
| --- | --- | --- |
| **空いている** | そこに CAS を書く | 米国 TRI `71751-41-2` / `Abamectin` |
| **埋まっている** | 名前を「CAS 名称」にする | EU CLP `001-001-00-9` / `1333-74-0 hydrogen` |

名前に入れるのは**表の「CAS No.」欄の代表1つだけ**。
総称は構成物質を何十件も持つので、全部入れると名前が壊れる。

### データソースは、それぞれ単独で成り立たせる（2026-09-02 決定）

**片方を作るときに、もう片方を見ない。**LOLI から作るときは CHRIP を見ない。
CHRIP から作るときは LOLI を見ない。

| | |
| --- | --- |
| なぜ | **お客様によっては、片方しか契約していない。**CHRIP だけのお客様の環境で、LOLI を見て決めた区分や法文物質名が出てくると、そのお客様には根拠のないデータになる |
| したがって | 区分・法文物質名・閾値・CASリンクのどれも、**そのデータソースの中だけで組み立てられること**を確かめてから作る |

**突き合わせて確かめるのはよい。**両方から同じものが作れるかを検証するのは、
作りかたの妥当性を見るためであって、片方の中身を借りるのとは別のこと。
ただし**検証で分かったことを、取り込みの判断に使ってはいけない**
（「LOLI ではこの区分だから、CHRIP のこれもそこへ入れる」は不可）。

例。韓国の有害化学物質は、LOLI が3つの一覧に分け、CHRIP は
`Acutely: / Chronically: / Environment:` の接頭辞で分けている。
**どちらも単独で3区分に分けられる**ので、3区分にしてよい。
一方、CHRIP 側で接頭辞を持たない記載（`>=1` の形）は、
**CHRIP だけでは区分を決められない**ので、LOLI を見て埋めてはいけない。

### LOLI で取れないものを、他のもので埋めない

**取れないものは空けておく。**
別の資料（CHRIP など）で埋めると、どの資料がどこまで言っているのかが混ざる。

いま LOLI に無いもの。

| 区分 | 件数 | LOLI の状態 |
| --- | ---: | --- |
| 毒劇法 特定毒物 | 20 | 一覧 1015 に**1件しか無い** |
| 安衛法 特別管理物質 | 44 | 一覧 4534 はあるが**鍵が無い**（`>1 % weight` のみ） |
| 化学兵器禁止法 3区分 | 65 | 一覧6本あるが**番号が無い**（項目名のみ） |
| 土壌汚染対策法 | 26 | 4021。**番号が無い** |
| 大気汚染防止法 特定粉じん | 1 | 3070。`Present` のみ |

## 0-2b. 閾値が複数あるとき（2026-09-02 決定）

1つの法文物質名に**閾値が何通りか書かれている**ことがある。
韓国の有害化学物質は `Acutely:1%, Chronically:0.3%, Environment:25%` のように、
急性・慢性・環境で別々の値を持つ。

**いちばん広く当たる値を採る**（＝下限がいちばん小さいもの）。そのうえで
**適用条件に元の書き方をそのまま書く**ので、当たったときは必ず要確認になる。

    Acutely:1%, Chronically:0.3%, Environment:25%
      → 閾値 0.3 ≦ x        （いちばん小さい 0.3 を採る）
      → 適用条件「Acutely:1%, Chronically:0.3%, Environment:25%」

**狭く採ると見落とす。**どの値が効くかは用途や排出先で決まり、こちらでは判断できない。
広く当てて人に確かめてもらうほうが、取りこぼしよりも害が小さい。

**毒劇法には当てはまらない。**除外の割合は号ごとに1つだけで、複数書かれた例は0件だった。

## 0-3. 番号の書き方（2026-08-26 決定）

### 番号だけでは足りない

**1つの規制区分の物質が、法律・政令・省令の別々の表から来ることが普通にある。**
表ごとに1から番号が振られるので、番号だけでは区別できない。

```
毒劇法 毒物   法別表第一の1号        エチルパラニトロフエニル…
              毒物及び劇物指定令 1条1号  オクタメチルピロホスホルアミド
安衛法 表示   安衛則別表第2の1項      アクリルアミド
              施行令別表第9の1号      アリール水銀化合物
              施行令別表第3第1号の1    ジクロルベンジジン及びその塩
```

同じ区分に「1」が3つある状態で、**放っておくと241種の番号がぶつかっていた。**
突合のときは先に見つかったほうに付いてしまい、後のものにCASが付かない。

### 決めたこと

**番号に出典を含める。**書き方は NITE の CHRIP に合わせる。

| 出典 | 書き方 | 例 |
| --- | --- | --- |
| 法律の別表 | `法別表第N のM` | `法別表第1の1` |
| 政令の条 | `令第N条第M号` | `令第1条第17号` |
| 政令の条（項あり） | `令第N条第P項第M号` | `令第16条第1項第4号` |
| 政令の別表 | `令別表第N のM` | `令別表第1の1` |
| 政令の別表の細目 | `令別表第N第I号のM` | `令別表第3第1号の6` |
| 政令の別表の欄 | `令別表第N欄(M)` | `令別表第3欄(1)` |
| 省令の別表 | `則別表第N のM` | `則別表第2の1552` |
| 出典が1つだけ | そのまま | `1662`（官報公示整理番号） |

**数字は算用数字にそろえる**（第3章と同じ方針）。化学兵器禁止法の別表は
原文が `(一)` だが `(1)` と書く。

**日本の法令だけに使う。**中国の序号・EU の Index No・米国の CAS は
それ自体で一意なので、そのまま持つ。

### 作る場所は1か所

`scripts/lib/statutory-number.ts` の `statutoryNumber(spec, num)`。
**投入側（`seed-*.ts`）と突合側（`seed-cas-links.ts`）で同じ関数を使う。**
別々に書くと、片方だけ直したときに黙って外れる。

```ts
statutoryNumber({ kind: "orderTableItem", table: "3", item: "1" }, "6");
// => 令別表第3第1号の6
```

### 結果

| | 前 | 後 |
| --- | ---: | ---: |
| 日本の法文物質名で番号がぶつかる組 | 241種 | **0種** |

途中、安衛法の特別管理物質だけ3種残った。第1類と第2類の両方から来るためで、
元データの `from` 欄（`1` / `2`）を使って
`令別表第3第1号の4` と `令別表第3第2号の4` に分けて解消した。

### 検討して採らなかった案

| 案 | 内容 | 採らなかった理由 |
| --- | --- | --- |
| 案2 | 規制区分を出典ごとに細分化する | 画面の区分が増える。利用者から見れば「表示対象物質」は1つ |
| 案3 | 階層をもう1段増やす | 表の構造が法令ごとに違い、階層に収まらない |

### LOLI 式の番号を別に持つか

**持たない。**LOLI の `2-1552` とこちらの `則別表第2の1552` は1対1で機械変換できる。
二重に持つと、片方だけ直したときにずれる。

**ただし番号を持たない物質は別。**大気汚染防止法の特定粉じん（石綿）だけは
LOLI 側にも番号が無く、人が確定した対応の保存先が要る。
外部データベースごとの鍵を持つ表（`statutory_substance_keys`）は、そこで検討する。

## 1. 全体の流れ

```
① 一次資料から  法律 → 規制区分 → 法文物質名（＋番号）を作る
② LOLI を読み   法文物質名 ↔ CAS のリンクを作る（statutory_cas_links）
③ 突合できなかったものを一覧に出し、人が結びつける
④ ③の結びつけを保存し、次回の取り込みで再利用する
```

②で**何を鍵に突き合わせるか**が、規制区分ごとの設定になる（第4章）。

## 2. 一次資料の取り方

### 2-1. e-Gov 法令API（条文に一覧が載っている法令）

画面は JavaScript で描くので `WebFetch` では中身が取れない。**API を使う。**

```bash
curl -s -o egov.xml "https://laws.e-gov.go.jp/api/1/lawdata/<法令ID>"
```

返る XML の構造。**条（`Article`）の下に号（`Item`）が並ぶ。**

```xml
<Article>
  <ArticleTitle>第一条</ArticleTitle>
  <ArticleCaption>（第一種特定化学物質）</ArticleCaption>
  <Item>
    <ItemTitle>一</ItemTitle>
    <ItemSentence>ポリ塩化ビフェニル</ItemSentence>
  </Item>
  ...
</Article>
```

取り出し方（`ItemTitle` は漢数字なので算用数字に直す）。

```python
import xml.etree.ElementTree as ET
r = ET.parse('egov.xml').getroot()
for art in r.iter('Article'):
    cap = art.findtext('ArticleCaption') or ''
    if '第一種特定化学物質' not in cap:
        continue
    for it in art.iter('Item'):
        num  = it.findtext('ItemTitle')                       # 「一」「二十三」
        name = ''.join(it.find('ItemSentence').itertext())    # 物質名
```

**法令IDの調べ方。**全法令の一覧を1回引いて、法令名で探す。

```bash
curl -s -o lawlist.xml "https://laws.e-gov.go.jp/api/1/lawlists/1"   # 約2.8MB
# <LawNameListInfo> の <LawName> / <LawId> / <LawNo>
```

### 2-5. 米国の一次資料（2026-08-26 実地に確認）

**eCFR（連邦規則集）は機械で読める。**日付を指定すれば、いつでも同じものが取れる。

```
https://www.ecfr.gov/api/renderer/v1/content/enhanced/<日付>/title-40?part=372&section=372.65
```

**APIは2つあり、使えるのは renderer のほう。**

| 経路 | 結果 |
| --- | --- |
| `/api/versioner/v1/full/…` | **503 を返す。**部が大きいと通らない |
| `/api/renderer/v1/content/enhanced/…` | 通る。HTML が返る |
| `/api/versioner/v1/structure/<日付>/title-40.json` | 部の在りかを調べるのに使う |

**日付を固定して取る。**省くと結果が日によって変わり、照合できない。
取得日は `.cache/us/DATE` に控える。

| 規則 | 中身 | 件数 |
| --- | --- | ---: |
| 40 CFR 372.65 | EPCRA 第313条（SARA 313 / TRI）の対象物質 | 813 |
| 40 CFR 751 | TSCA 第6条で製造・使用等が規制される物質 | 11 |

**CFR は法文物質名と CAS を同じ表に載せている。**日本や中国と違い、
CASリンクまで原文から作れる（第8章 8-7）。

#### 取れないもの — 40 CFR 372.65(c)

**同意は利用者が押す。**こちらからは押さない（同意は本人の行為）。

## 3. 名前の表記の決めごと

### **法令の原文が最も正しい。**

J-CHECK も CHRIP も、NITE が読みやすく書き直した**二次資料**。
実際に、化審法の第1種特定化学物質で次の食い違いが見つかった。

| 号 | 原文（施行令） | J-CHECK | どちらが正しいか |
| --- | --- | --- | --- |
| 16 | ジ―**ターシャリ**―ブチルフェノール | ジ－**ｔｅｒｔ**－ブチルフェノール | 原文 |
| 20 | 別名**アルファ**―ヘキサクロロ… | 別名**α**－… | 原文 |
| 22 | 別名**ガンマ**―ヘキサクロロシクロヘキサン | 別名γ－…**又はリンデン** | 原文（**「リンデン」は原文に0件**） |

**J-CHECK は件数の確認と参考に使う。名前の典拠にはしない。**

### 表記の変換は `scripts/lib/law-name.ts` にある

`toDisplayName(原文)` が、この章の決めごとをまとめて当てる。
**手で直さない。**中身と、なぜそうするかは第10-2章。

### 直してよいのは書式だけ

| | 原文 | このシステム | 理由 |
| --- | --- | --- | --- |
| **数字** | 漢数字「一・二・三・四・十・十―」 | **算用数字**「１，２，３，４，１０，１０－」 | 縦書き法令の書式であって、名前の一部ではない。行政の公表一覧も算用数字に直している |
| **参照句** | 「（別名マイレックス。第七条の表九の項において「マイレックス」という。）」 | 「（別名マイレックス）」 | 条文内の参照であって、名前の一部ではない |
| **区切り** | 「・」 | 「，」（並列）／「．」（von Baeyer 命名の位置） | 下記 |
| **語そのもの** | ターシャリ／アルファ | **そのまま** | 名前の中身。**書き換えない** |

漢数字の変換は `scripts/lib/law-name.ts`（`convertNumerals`）。規則は第12章 12-1。
**後ろに何が来るかで、位置番号か語の一部かを見分ける。**

```
後ろが区切りか英字   → 位置番号。直す（二― → 2―、二Ｈ → 2Ｈ、四・六 → 4・6）
後ろがかな・漢字     → 語の一部。直さない（四塩化炭素・二硫化炭素・四アルキル鉛）
```

### 区切りの「・」は2通りに割れる

原文はどちらも「・」だが、意味が違うので書き分ける。

```
一・二・三―ベンゾトリアゾール      並列 → １，２，３－ベンゾトリアゾール
ビシクロ［二・二・一］ヘプタン      von Baeyer の位置 → ビシクロ［２．２．１］ヘプタン
```

後者は世界共通の命名法（bicyclo[2.2.1]heptane）でピリオドを使う。
**原文の「・」はそれを縦書きで書いたもの**なので、ピリオドに戻すのが正しい。

### ギリシャ文字はカタカナのまま（2026-08-26 調査）

「α」と「アルファ」のどちらが世の中で使われているかを調べた結果、
**ギリシャ文字が主流とは言えなかった**ので、原文どおりカタカナにする。

| 出典 | 表記 |
| --- | --- |
| 化審法施行令の原文 | **カタカナ**（α 0件／アルファ・ベータ・ガンマ 各1件） |
| 厚労省 職場のあんぜんサイト（安衛法） | **カタカナ**「アルファ-メチルスチレン」 |
| 厚労省 GHSモデルSDS | **両方併記**（「アルファ-メチルスチレン (alpha-Methyl styrene)」と「α-メチルスチレン」） |
| NITE J-CHECK（化審法） | ギリシャ文字 α・β・γ |

**照合するときは、この違いを吸収してから比べる**（第6章）。

### 3-4. 区分の名前に、どの規則のものかを入れる（2026-09-01 決定）

**法律の専門家の指摘。**区分名だけでは、どの規則のものか読み分けられない。
「第1類」は消防法にも毒劇法にもあり、安衛法の中でも有機則に「第1種有機溶剤」がある。
判定結果や帳票に区分名だけが出る場面で取り違える。

| 区分コード | 前 | いま |
|---|---|---|
| `JP-ISHA/SPEC1` | 第1類物質 | 特化則 第1類物質 |
| `JP-ISHA/SPEC2` | 第2類物質 | 特化則 第2類物質 |
| `JP-ISHA/SPEC3` | 第3類物質 | 特化則 第3類物質 |
| `JP-ISHA/SPEC_MGMT` | 特別管理物質 | 特化則 特別管理物質 |
| `JP-ISHA/ORG` | 有機溶剤 | 有機則 有機溶剤 |

**「物質」は落とさない。**特化則第2条が定める言葉は「第一類物質」で、そこが法令の名称にあたる。

**ほかの法令には広げない。**「特定物質」が大気・化兵法・オゾン層保護法の3つに、
「有害物質」が大気・水質の2つにあるが、**どれもその法令自身が使っている名称**で、
頭を付けるのは造語になる。画面はどこでも「法律 › 区分」の形で出している。

**数字は算用数字にそろえる**（同じ日の決定）。日本の区分だけ漢数字が残っており、
外国の区分（韓国「第1類」、米国「第313条」、中国「第1次」）と混ざっていた。

| 区分コード | 前 | いま |
|---|---|---|
| `JP-CSCL/C1` `C2` | 第一種／第二種特定化学物質 | 第1種／第2種特定化学物質 |
| `JP-PRTR/C1` `SC1` `C2` | 第一種／特定第一種／第二種指定化学物質 | 第1種／特定第1種／第2種指定化学物質 |
| `JP-CWCA/DESIG1` `DESIG2` | 第一種／第二種指定物質 | 第1種／第2種指定物質 |

**出どころの示し方は、意味で使い分ける。**
「特化則の第一類物質」は実務で普通の言い方なので**前に置く**。
附属書や条の番号は注記なので**後ろに括弧**（`制限物質（附属書XVII）`）。
無理にそろえると、かえって読みにくくなる。

**条文を読む側のコードは、漢数字のままにする。**
`scripts/build-jp-env-data.ts` の `CW_SECTIONS` や `scripts/chrip-import.ts` の `LAW_OF` は、
**相手の文字列と突き合わせる鍵**なので、こちらの表記に合わせてはいけない。

付け替えは `scripts/rename-jp-categories.ts`。**入れ直しはしない**（CASリンクと判定がぶら下がる）。
探すのは区分コードなので、何度流しても結果は同じ。

## 4. LOLI との対応

### 4-0. LOLI のデータ構造（Datafeed 説明書より）

ChemADVISOR（LOLI）の Datafeed には仕様書が付いている。
`ChemADVISOR Datafeed File Layout` と `Generic Links`。**取り出しを書く前に必ず読む。**

表の名前は接頭辞で役割が分かれている。

| 接頭辞 | 役割 | 例 |
| --- | --- | --- |
| `ListNames` | 一覧そのもの（法令・表の単位） | `ListNames`, `ListNames_Control` |
| `ListData` | 一覧の中身（CASごとの規制情報） | `ListData`, `ListData_Enfielded` |
| `Cas` | 物質側の情報 | `CasNames`, `CasSyns`, `CasLinks` |
| 末尾 `_History` | 変更履歴 | `ListData_History` |
| 支援表 | 種別の一覧 | `DataKeyTypes`, `ListDataTypes` |

**この章で使うのは `ListData` と `ListNames_Control`、それに `CasNames` / `CasLinks`。**

#### `ListData.Data` と `ListData.XML` の違い

`ListData` の **1行 ＝ 1つのCAS × 1つの一覧（ListID）**。同じ行の中に、
同じ内容が**2つの形**で入っている。

| 欄 | 中身 |
| --- | --- |
| `Data` | **表示用に文章化したもの。**複数の値を `;` でつないである |
| `XML` | **欄別の元データ。**`root` の下に `row` が並ぶ |

```
Data  Present (listed under Cyanide compounds)
XML   <root><row><value>Present</value><refno>05</refno>
                 <listedunder>Cyanide compounds</listedunder></row></root>
```

**`Data` は番号を落とすことがある。**上の土壌汚染対策法の例では、`Data` に
番号が無いのに `XML` の `refno` には `05`（令第1条第5号）が入っている。

**突合には必ず `XML` を使う。**理由は2つ。

1. **番号が落ちない。**「LOLI に番号が無い」と見えていた9つの一覧すべてに番号があった
2. **区分をまたいで取り違えない。**`Data` は複数の規制をつないだ1本の文字列なので、
   「Poisonous を含む行の最初の角括弧」のような切り出しをすると、
   劇物の号を毒物に付けてしまう。`XML` は `row` が規制ごとに分かれている

`XML` の欄の意味は**一覧ごとに違う**。定義は `ListNames_Control.XML_Admin` と
`ListNames_Control.XML_XSD` にある。よく出る欄は次のとおり。

| 欄 | 意味 | 例 |
| --- | --- | --- |
| `code` | 番号（出典付きのことが多い） | `Order Article 2-1-28-9`, `2-1552`, `3-1-6` |
| `refno` | 番号、または項目の名前。**一覧によって役割が違う** | `05`, `1-01`, `p-Nitrochlorobenzene` |
| `value` | 値または区分 | `Class I`, `314`, `Present` |
| `note` | 補助の番号 | 化管法の政令番号 `358` |
| `type` | 値の種類 | `Cabinet Order Number`, `cut-off value` |
| `category` / `group` | 区分 | `Poisonous`, `Group 2` |
| `addinfo` | 出典の種類 | `Attached table`, `Cabinet Order - Article` |
| `listedunder` | 親の総称の名前 | `Cyanide compounds` |
| `remark` | 但し書き | `except Arsine and Gallium arsenide` |

**`code` と `refno` のどちらが番号かは一覧ごとに確かめる。**思い込みで決めない。
確かめかたは 4-1a。

#### `DataKey` は使えない

説明書には「別の並べ替え用。一部の一覧だけ」とある。
日本の一覧では**全行 NULL**だった。番号は入っていない。

#### `ListData_Enfielded` は数値の分解用

説明書に「ListData から計算で作った表。ListData を直接使うことを勧める」とある。
中身は `Operator` / `nValue` / `Unit` / `Type` など**濃度や限度値の分解**で、
番号は入っていない。**この章の目的には使わない。**

#### `RR-` で始まるCAS（Generic Links）

`RR-00625-7` のような番号は CAS ではなく、**総称（chemical family）に振った擬似CAS**。
説明書 `Generic Links` に定義がある。総称にひもづけることで、
個々の物質に法規制情報を配る仕組み。

1つの物質は複数の総称にぶら下がる。ヒ酸塩の例。

```
RR-00625-7  Arsenic compounds, n.o.s.      ← 広い
RR-00065-7  Arsenic, inorganic compounds
RR-00586-7  Arsenic, soluble compounds
RR-02086-0  Arsenic (V) acid salts         ← 狭い
7440-38-2   Arsenic                        （元素そのもの）
```

親子の関係は `CasLinks` 表（`Cas` から `LinkCas` へ、条件付きなら `Condition`）に
**データとして入っている**。`listed under …` の文字列を解析する必要はない。

説明書は**優先順位**にも触れている。

- 物質そのものに評価があれば、総称から来た情報より優先する
- 総称どうしなら、**狭いほうが優先**（`Arsenic (V) acid salts` が `Arsenic compounds, n.o.s.` に優先）
- 総称の中身は LOLI の判断であって、法律が決めたものではない

**この優先順位は判定の設計にそのまま効く。**いまは取り込んでいないが、
「どの総称から来たCASか」を持てば、多めに出たCASを絞り込める。

CAS の形をした番号だけを採り、`RR-` と `UN` は落とす（`scripts/seed-cas-links.ts` の `CAS_SHAPE`）。

#### コンパクト版と展開版（2026-09-01 確認）

### 4-1. 突合のやりかた

**やることは、こちらの法文物質名の番号と、LOLI の番号を突き合わせること。**
一致した行の `Cas` が、その法文物質名に付くCAS。
1つの法文物質名に何十から何百件付くのが普通。

こちらの番号は**出典を含む**（第0-3章）。LOLI 側は枝番しか持たないことが多いので、
**LOLI の鍵をこちらと同じ形に組み立ててから当てる。**

```
LOLI  2-1552                こちら  則別表第2の1552
LOLI  Order Article 1-17    こちら  令第1条第17号
LOLI  05（土対法）           こちら  令第1条第5号
```

組み立ては `scripts/lib/statutory-number.ts` の `statutoryNumber` 1か所に集めてある。
投入側（`seed-*.ts`）と突合側（`seed-cas-links.ts`）で**同じ関数を使う**。
別々に書くと、片方だけ直したときに黙って外れる。

### 4-1a. 新しい一覧を足すときの確かめかた

**思い込みで欄を決めない。**次の順に確かめる。

1. **一覧を探す。**`ListNames.ListName` を法令名の英語で当たる

   ```sql
   SELECT ListID, ListSize, ListName FROM ListNames WHERE ListName LIKE '%Soil%'
   ```

2. **`XML` を数行見る。**どの欄に番号が入っているかを目で確かめる

   ```sql
   SELECT TOP 3 Cas, Data, XML FROM ListData WHERE ListID = 4021
   ```

3. **その欄の値を全部数える。**種類と件数を出し、**こちらの法文物質名の数と突き合わせる**

   ```sql
   SET QUOTED_IDENTIFIER ON;
   WITH x AS (SELECT CAST(XML AS xml) AS d FROM ListData WHERE ListID = 4021),
        y AS (SELECT CAST(r.value('(refno)[1]','varchar(60)') AS varchar(60)) AS k
              FROM x CROSS APPLY d.nodes('/root/row') t(r))
   SELECT k, COUNT(*) FROM y GROUP BY k ORDER BY k
   ```

   化学兵器禁止法はこれで**件数が一致した**（第三欄29件・第四欄5件など）。
   一致すれば、欄の読み方が合っている裏づけになる。

4. **取り込んで「結び付いた数」を見る。**`44/44` のように全部付けば良い。
   付かないものは番号を1件ずつ確かめる

**`SET QUOTED_IDENTIFIER ON` を忘れない。**XML のメソッドが使えず落ちる。

#### 附属書XVII の枝の書き方が一定でない

LOLI は項番号を `addinfo` に入れるが、枝の書き方が2通りある。

```
50a[b]   項 50a の枝 (b)      → 項は 50a
18[a]    項 18a（水銀）        → 項は 18a。項18（水銀化合物）の枝ではない
```

一律に角括弧を落とすと、**水銀が水銀化合物の項に付く**（実際に付いていた）。
そこで `18[a]` は**まず `18a` として当て、無ければ `18`** とする
（`resolveKey`、ジョブの `bracketAlt`）。**取り出しでは括弧を落とさない。**

#### CLP 附属書VI だけ `ListData` から取れない

LOLI は CLP 附属書VI を**危険有害性の分類ごとに一覧を分けている**
（急性毒性・皮膚腐食性・発がん性…で40本以上）。
どの一覧にも Index番号が入っていない。

**物質側の別名の番号を持つ表がある。**`CasKeys`（Datafeed 説明書 4.2）。

```sql
SELECT DataKey, Cas FROM CasKeys WHERE DataKeyType = 'Annex'
-- 001-001-00-9  1333-74-0
-- 001-002-00-4  16853-85-3
```

`DataKeyTypes` に種類の意味が書いてある。

| 種類 | 意味 | 件数 |
| --- | --- | ---: |
| `Annex` | **EU 附属書VI の Index番号** | 4,876 |
| `EC` | EC番号 | 128,039 |
| `ENCS` | 化審法の官報公示整理番号 | 71,459 |
| `ISHL` | 安衛法の番号 | 20,305 |
| `KE` / `TECI` / `AICS` / `HSNO` | 韓国・タイ・豪州・NZ の名簿番号 | |
| `Formula` | 分子式 | 270,488 |

**Index番号は 4,443種**で、こちらの 4,441件とほぼ一致した。
取り出しは `scripts/sql/loli-caskey.sql`、呼び出しは `dump_key`。

**`ENCS` と `ISHL` は、いまは使っていない。**化審法・安衛法は条文の番号で結べている。
新しい国（韓国・台湾・豪州）を足すときに効く。

TRI も TSCA 第6条も、法令が CAS で規定しているので**番号の欄が無い**。

LOLI の**総称の親のCAS**と突き合わせる。

```
LOLI  71751-41-2 （総称なし）                          → 鍵 71751-41-2
```

総称の擬似CAS（`RR-…`）はこちらに無いので当たらない。
**当たるのは、こちらが挙げている CAS と同じものだけ。**
そこから LOLI が広げた個々の物質が付く（アバメクチン1件に3件、など）。

TSCA 第6条は、こちらが**同じ物質を規制の枝ごとに分けて**持っている
（`B-75-09-2` `D-79-01-6`）。接頭辞を落としてから当てる（`stripPrefixRe`）。

### 4-3. 番号の突き合わせかた

**LOLI の鍵をこちらの形に組み立ててから、そのまま一致させる。**
あいまい一致はしない。組み立ての手順は次のとおり（`seed-cas-links.ts` の `toKeys`）。

```
① カンマで分ける      49, 51 → 49 と 51（1つの欄に号が2つ入ることがある）
② 前置きを落とす      Order Article 1-17 → 1-17 →（strip 1-）→ 17
③ 枝を落とす          01-001 → 01     （head。化兵法だけ）
④ 0埋めを外す         0305 → 305、05-01 → 5-1
⑤ 出典を付ける        17 → 令第1条第17号
```

**区切りは落とさず、統一だけする。**落とすと `1-10` が `110` になり、
本物の `110` とぶつかる。**取り違えは、突合できないことよりずっと悪い。**

**付かなかった番号は必ず出す。**`seed-cas-links.ts` は区分ごとに
「結び付いた法文物質名の数 / 全体」と「合わなかった番号」を出す。
10種以下なら中身も出る。ここを読まずに次へ進まない。

### 4-3a. 条件つきのリンク（誤検出のもと）

**LOLI は総称から個々の異性体へ広げ、但し書きを付けることがある。**

```
108-68-9（3,5-キシレノール）の row
  <remark>Should meet the conditions stipulated by the Cabinet Order name</remark>
  <remark>As Xylenol [1300-71-6]</remark>
  <note>101</note><refno>2,4-Xylenol</refno>
```

政令の名称が「2,4-キシレノール」と絞っているのに、
**総称のキシレノールから3,5-体まで結び付けている。**
「政令の名称が定める条件に合致すること」という但し書きが、その合図。

そのまま該当にすると誤検出になる。実例。

```
令別表第1の315  1-ドデカノール          ← 2-ノナノール（628-99-9）が付く
令別表第1の94   1-オクタノール          ← トリデカン-2-オール（1653-31-2）が付く
令別表第1の34   アルカノール（炭素数10）  ← 同上
```

**出るのは化管法だけ。**ほかの19一覧では0件だった。

| 一覧 | 但し書きのある行 / 全row | 影響する号 |
| --- | --- | ---: |
| 化管法 第1種（9013） | 6,098 / 27,334 | **48** |
| 化管法 第2種（9014） | 1 / 411 | 1 |

48号はどれも**炭素数や置換位置で絞られた号**（`1-ドデカノール`、
`アルカノール（炭素数が10のものに限る。）`、`ポリ（オキシエチレン）アルキルエーテル
（アルキル基の炭素数が12〜15のものに限る。）` など）。

#### どう扱っているか

**消さない。印を付ける。**`scripts/loli-dump.sh` が条件つきの組だけを
別のTSV（`loli-prtr-c1-cond.tsv`）に落とし、`seed-cas-links.ts` が
リンクの備考に次の文字列を入れる。

```
LOLI: 政令の名称が定める条件に合うかは要確認
```

消すと**見落とし**が出る（総称からしか結べない物質がある）。
そのまま該当にすると**誤検出**が出る。どちらもデータの側では決められないので、
**情報を残したうえで、判定の側で扱いを決める。**

いま印が付いているのは 3,280件（第1種3,276・特定第1種3・第2種1）。

#### 判定での扱いはシステム設定で切り替える

`judgment.conditional_link_mode`（管理 → システム設定 → 法規制の判定）。

| 値 | 動き |
| --- | --- |
| `hit` | 条件が無いものとして該非を確定し、**警告を出す** |
| `review` | **要確認にして**警告を出す（既定） |

**どちらでも警告は出る。**違いは、人の確認を必須にするかどうか。

仕組みは3段。

```
scripts/seed-cas-links.ts   リンクの備考に「政令の名称が定める条件に合うかは要確認」と書く
apps/web/lib/judge-store.ts 備考を見て、法文物質名ごとに「条件つきのCAS」を集める
apps/web/lib/judge-calc.ts  当たったCASが条件つきなら警告。要確認にするかは設定で決める
```

**警告（`reasons`）と要確認（`needsReview`）を別に持っている。**
`hit` のときは `conditionalLink` だけを要確認の判断から外す。
ほかの理由（中身が分からない、換算係数が無いなど）はそのまま要確認になる。

いま印が付いているのは3,280件、法文物質名で50件。

## 6. 照合のしかた（作ったあとの確認）

**`scripts/verify-jp-laws.ts` が自動でやる。**

```
npx tsx scripts/verify-jp-laws.ts                  全部
npx tsx scripts/verify-jp-laws.ts JP-PRTR          法律を絞る
npx tsx scripts/verify-jp-laws.ts --tsv out.tsv    食い違いを書き出す
```

原文は e-Gov 法令API から取って `.cache/laws/` に置く。2回目からはそこを読む。
どの区分をどこと比べるかは、スクリプトの `SOURCES` に書いてある（第8章の表と同じ）。

**区分を足したら `SOURCES` にも足す。**足さないと照合の網から漏れる。

**件数 → 番号 → 名前**の順に見る。

1. **件数**が一次資料と合うか（J-CHECK の「〜件中」、e-Gov の `Item` の数）
2. **番号**が飛んでいないか、余分が無いか
3. **名前**が合うか。第3章の表記の違いを吸収してから比べる

**名前は `name_original` に入っている。**`name_ja` は空のことが多いので、
照合も更新も `coalesce(name_ja, name_original)` で扱う。
片方だけ直すと、画面に出る名前が変わらない。

名前を比べる前の正規化（照合のためだけのもの。保存する名前は変えない）。
`verify-jp-laws.ts` の `normalize` が同じことをする。

```
・NFKC 正規化（全角英数を半角に）
・括弧書き（別名・参照句）を落とす
・中黒「・」読点「，」を落とす
・ハイフン類を落とす
・空白を落とす
・化学名の中の漢数字を算用数字に
・小文字化
```

## 8. 規制区分ごとの取得の仕方

**この章が、どの区分をどこから作るかの一覧。**
区分を足すとき・作り直すときは、まずここを見る。

区分ごとに書いてあるのは4つ。

| 欄 | 意味 |
| --- | --- |
| 定める条文 | その区分が「どの条文で決まるか」。**ここが典拠** |
| 法文物質名 | 名前の一覧が載っている場所。番号もここで決まる |
| 閾値 | 裾切値と、それが書いてある条文。**閾値も条文で決まる** |
| 取り出し | e-Gov の XML から機械的に取るときの当たりどころ |

**番号は「並び順」ではなく「法令が付けた番号」。**改正で `3の2` のような枝番が入るので、
文字列で持ち、番号順の並べ替えには使わない（`statutory_substances.official_number`）。

### 8-3. 毒劇法（`JP-PDSCA`）

法令ID `325AC0000000303`（法本体）／`340CO0000000002`（毒物及び劇物指定令）

**番号が2か所に分かれている。**法本体の別表と、指定令の条。合わせて1つの区分になる。

| 区分 | 法本体 | 指定令 | 合計 | 閾値 |
| --- | --- | --- | ---: | --- |
| 毒物 `TOX` | **別表第一** 28号 | **第1条** 106号 | 134 | 品目ごと。指定令の各号の括弧書きに書いてある |
| 劇物 `DEL` | **別表第二** 94号 | **第2条** 340号 | 434 | 同上 |
| 特定毒物 `SPT` | **別表第三** 10号 | **第3条** 10号 | 20 | 同上 |

法本体の別表は「無機シアン化合物」のような古くからの品目、指定令はその後に足されたもの。
**片方だけ取ると6〜8割が欠ける。**

閾値は一律ではない。「〜を含有する製剤。ただし〜％以下を含有するものを除く」という
書き方で号ごとに違う（`docs/毒劇法の閾値構造化.md`）。

#### 除外の割合を閾値に入れた（2026-09-02）

**144件**の「ただし〜％以下を含有するものを除く」を、閾値の下限にした
（`scripts/fix-pdsca-thresholds.ts`）。それまでは備考に文章として置くだけで、
判定は「0を超えれば該当」のまま、つまり**法令より厳しく当てていた**。

    令第1条第1号  アジ化ナトリウム及びこれを含有する製剤
      前   0 < x ≦ 100      備考「ただし〇・一％以下を含有するものを除く」
      いま 0.1 < x ≦ 100

**過剰な該当は安全側とは限らない**（利用者の判断、2026-09-02）。
0.1%以下のときに**別の区分へ当たることがあり**、そこでこちらにも当ててしまうと、
どの規制が効いているのかが読めなくなる。

読み取りの決まり。

- 対象は「ただし … 〇％以下 … 除く」の形で、**1つの備考に％が1つだけ**のものに限る
- 数字は位取りの漢数字（`一〇` は 10、`〇・〇〇五` は 0.005）。
  **`十` `百` が出てきたら読まない**（位取りと混ざると桁を取り違える）
- 読めなかったものは触らずに一覧へ出す

144件すべてが同じ言い回しで、**読めなかったものは0件**。`未満`・範囲・複数値も0件だった。

#### 化学兵器禁止法の別表は形が違う

**1つのセルの中に `（一）（二）…` と物質が並ぶ。**

**該当すると規制される側ではない**ので、区分にすると意味が逆になる。

(d)/(e) も同じ関係（PFAS）。**(a) と (d) だけを採る。**
見分けは1列目で付く（1列目が CAS の表は写し）。

#### 取れていないもの

**40 CFR 372.65(c) の chemical categories は eCFR では画像。**
`Antimony compounds` のような総称が約30件あるが、テキストが無い（第2章 2-5）。
**推測で書かない。**別の出どころが決まるまで空けてある。

#### TSCA 第6条は条文の中に CAS がある

40 CFR 751 は表ではなく、**物質ごとの subpart に分かれた条文**。
subpart の見出し（`Subpart B—Methylene Chloride`）と、
その範囲に出てくる CAS を結ぶ。

### 8-8g. 韓国の毒性物質（2026-09-02 登録）

韓国の毒性物質（유독물질）を、**有害性の種類ごとに3つの区分**として足した。
**LOLI と CHRIP のどちらからでも、それだけで作れる。**

| 区分コード | 区分名 | 号 |
|---|---|---:|
| `TOXIC_ACUTE` | 急性毒性物質（人の健康） | 992 |
| `TOXIC_CHRONIC` | 慢性毒性物質（人の健康） | 247 |
| `TOXIC_ECO` | 生態毒性物質 | 675 |

#### なぜ3つに分けるのか

**1つの号に、有害性の種類ごとの閾値が並ぶ。**

```
97-1-339   Acutely:1%, Environment:25%
2020-1-989 Acutely:25%, Chronically:0.1%, Environment:25%
```

1つの区分にまとめると閾値を1つしか持てず、**いちばん小さい値に丸めるしかない。**
区分を分ければ号ごとに正しい閾値を持てる。0-2b の「いちばん広く当たる値を採る」は、
**同じ区分の中に値が2つ以上あるとき**の決めごとであって、種類の違いを潰すためのものではない。

#### 出どころ（それぞれ単独で成り立つ）

| | 何を読むか | スクリプト |
|---|---|---|
| LOLI | 一覧 `10266` / `10267` / `10268`、鍵は `refno` | `loli-dump-korea.sh` → `seed-korea-laws.ts` → `seed-korea-links.ts` |
| CHRIP | 詳細ページの「カテゴリ」と「対象となる範囲（％）」の頭に付く語 | `build-chrip-korea-data.ts` → `seed-chrip-korea.ts` |

CHRIP は `Toxic Substances` という1つのカテゴリで持ち、**頭に付く語**で種類が分かれる。

| 頭に付く語 | 区分 |
|---|---|
| `Acutely:` | `TOXIC_ACUTE` |
| `Chronically:` | `TOXIC_CHRONIC` |
| `Environment:` | `TOXIC_ECO` |

CHRIP のほうは**韓国の7区分すべてを単独で作れる。**CHRIP しか契約していない
お客様の環境でも、法令・区分・法文物質名が揃う（第0章 0-2）。

#### 両方を入れているとき

`seed-chrip-korea.ts` は**すでにあるものを書き換えない。**足りない号を作り、
自分のCASリンクを足すだけ。先に入れたほうの名前と閾値が残る。

**号の書き方の違いは吸収する。**同じ号を CHRIP は `1`・`97-1-119(1)`、
LOLI は `001`・`97-1-119 (1)` と書く。桁と空白をそろえて見比べる（`numberKey`）。
**ここを見落として 273 件の重複を作り、消して入れ直した。**

#### 区分を置いた法律は化管法（`KR-CCA`）

**毒性物質（유독물질）を指定するのは化管法。**環境部長官の指定告示で決まる。

| 区分 | 指定する法律 |
|---|---|
| 禁止物質・制限物質 | 化評法（K-REACH）第27条 |
| 許可物質 | 化評法 第25条 |
| 重点管理物質 | 化評法 第2条 |
| **毒性物質** | **化管法** |
| 事故備え物質 | **化管法** |

化管法は「有害化学物質」を毒性物質・許可物質・制限物質・禁止物質・事故備え物質の
総称として定義するが、**制限物質と禁止物質については化評法の指定を引いているだけ。**
化管法そのものが指定するのは毒性物質と事故備え物質の2つなので、
**禁止物質・制限物質・重点管理物質は K-REACH のままでよい。**

**はじめ K-REACH の下に作って、あとで移した。**移すときに
法文物質名の業務キー（`KR-KREACH-TOXIC_ACUTE-…`）が法令コードを含んでいることを
見落とし、**号が二重にできた。**区分ごと消して種から作り直した。

## 10-2. 原文から作り直して分かったこと（2026-08-26）

`scripts/build-law-data.ts` を作り、**投入用の JSON を条文から作り直せるようにした。**
それまでは JSON だけが残っていて、**どう作ったかがどこにも無かった**。

作り直したものを、いま入っているものと突き合わせて2つ見つかった。

### 上付き添字が落ちていた（化管法 4件）

法令XMLは、**読み仮名と上付き添字を同じ `Ruby`/`Rt` で書いている。**

```
五弗<Ruby>素<Rt>ふつ</Rt></Ruby>化臭素                  読み仮名
ペンタシクロ［五・三・〇・<Ruby>〇<Rt>二・六</Rt></Ruby>］  上付き添字
```

`Rt` を一律に落とすと読み仮名は消せるが、**von Baeyer 名の位置番号まで消える。**
中身がかなだけなら読み仮名、数字が混じれば添字、で見分ける（`scripts/lib/egov-xml.ts`）。

| 号 | 前 | 後 |
| --- | --- | --- |
| C1 296 | …トリシクロ［三・三・一・一］デカン | …トリシクロ［三・三・一・**一（三・七）**］デカン |
| C1 310 | …トリシクロ［五・三・一・〇］ウンデカ… | …トリシクロ［五・三・一・**〇（一・五）**］ウンデカ… |
| C1 334 | トリシクロ［五・二・一・〇］デカ… | トリシクロ［五・二・一・**〇（二・六）**］デカ… |
| C1 349 | …一ラムダ―ピリジン… | …一ラム**ダ（五）**―ピリジン… |

349号だけは機械の読みでは直せない。原文が縦書きの都合で λ⁵ の 5 を
「ラ」と「ムダ」の間に置いているため、そのまま入れると `一ラ（五）ムダ` と語が割れる。
`build-law-data.ts` の `HAND_FIXES` に理由付きで例外を置いた。

### 但し書きが名前に混ざっていた（毒劇法 1件）

`ピクリン酸。ただし、爆発薬を除く` が名前になっていた。
但し書きは `note` に移す決まりなので、名前を `ピクリン酸` にし、
`note` を `毒物及び劇物取締法 別表 ただし、爆発薬を除く。` にした。

法の別表にも但し書きが付くのは、588件中この1件だけ。**指定令だけを見ていると取り逃がす。**

CASリンクが 1,089件付いているので、入れ直さず名前だけ差し替えた

### 表記を算用数字にそろえた（2026-08-26 決定）

それまでは、化審法だけが算用数字で、化管法・毒劇法は原文のままだった。
**取り込んだ資料が違ったため**（化審法は J-CHECK、他は e-Gov）で、決めた結果ではなかった。

**SDS で使う書き方に合わせる**ことにし、算用数字にそろえた。
変換は `scripts/lib/law-name.ts` の `toDisplayName`。

| 直すもの | 原文 | 登録 |
| --- | --- | --- |
| 位置番号の漢数字 | `一・二・三・四―` | `１，２，３，４－` |
| 数量の漢数字 | `炭素数が八の` `四十八パーセント` | `炭素数が８の` `４８パーセント` |
| 位置番号の区切り | `一・二` | `１，２` |
| 角括弧の中（von Baeyer） | `ビシクロ［二・二・一］` | `ビシクロ［２．２．１］` |
| ダッシュ | `―`（U+2015） | `－`（U+FF0D） |
| プライム | `′`（U+2032） | `’`（U+2019） |
| 条文の中だけの言い回し | `（別名アルドリン。第七条の表三の項において「アルドリン」という。）` | `（別名アルドリン）` |

**直すのは書式だけ。語は変えない**（`ターシャリ` を `tert` にはしない。第3章）。

#### 直してはいけないもの

数字に見えても**語の一部**なら直さない。ここがいちばん間違えやすい。

```
四アルキル鉛   → そのまま（「４アルキル鉛」は別のもの）
二硫化炭素     → そのまま
六価クロム化合物 → そのまま（「価」は慣用として漢数字）
エチレンジアミン四酢酸 → そのまま
```

見分けは**うしろの文字**で付く。漢字・カタカナが続けば語の一部。
ただし `以上` `以下` `パーセント` `又は` などが続くときは数量なので直す。
実データでは、化管法・毒劇法の1,237件中43件が漢数字のまま残った（すべて語の一部）。

#### 中黒には2つの役目がある

```
一・二・三―トリクロロ                          位置番号の区切り → 読点
アルキル＝アクリラート・メチル＝メタクリラート  並列の中黒       → そのまま
```

**両隣が数字か英字のときだけ**読点にする。

#### 角括弧の中が数字とは限らない

```
ビシクロ［二・二・一］   環の大きさ → ピリオド ［２．２．１］
ジベンゾ［ａ・ｅ］       縮環の位置 → 読点     ［ａ，ｅ］
ピラゾロ［一・五―ａ］   縮環の位置 → 読点     ［１，５－ａ］
```

**中身に英字が混じるならピリオドにしない。**

### 12-1. 一次資料を読む

#### `scripts/lib/egov-xml.ts` — 法令XMLの読み取り

外部の部品を足さず、必要なところだけを自前で読む。法令XMLは素直な作りで、
CDATA も名前空間も出てこない。

**要点は `Rt`（ルビ）の扱い。**法令XMLは縦書きの組版なので、
**読み仮名と上付き添字を同じ `Ruby`/`Rt` で書いている。**

```
五弗<Ruby>素<Rt>ふつ</Rt></Ruby>化臭素                    読み仮名 → 落とす
ペンタシクロ［五・三・〇・<Ruby>〇<Rt>二・六</Rt></Ruby>］   上付き添字 → 残す
```

見分けは中身で付く。**かなだけなら読み仮名**、数字が混じれば添字。
添字は `（二・六）` の形にして残す。

| 関数 | すること |
| --- | --- |
| `parseXml` | 文字列を木にする。閉じ忘れは投げる（黙って進むと照合が狂う） |
| `isReading` | `Rt` が読み仮名か上付き添字か |
| `nodeText` | 中の文字を取り出す。読み仮名を落とし、添字を `（）` に入れる |
| `findAll` / `childrenOf` | 深さ優先で全部 / 直下だけ |
| `textOf` | 最初に見つかった要素の文字 |

**`childrenOf` と `findAll` を取り違えない。**別表の号は入れ子になることがあり、
`findAll` で拾うと孫まで数えて件数が合わなくなる。

#### `scripts/lib/kanji-count.ts` — 号番号を読む

| 関数 | すること |
| --- | --- |
| `kanjiCount` | `百三十四` → `134`。位取りのある数を読む（1〜999） |
| `itemNumber` | 号の見出し（漢数字）→ `19-4`。**枝番は潰さない** |
| `subitemNumber` | 細目の見出し（算用数字 `３の２`）→ `3-2` |

**枝番を数に潰してはいけない。**`十九` と `十九の四` は別の号で、
潰すと突合が壊れる。号は漢数字、細目は算用数字と書き方が違うので、別の関数にする。

#### `scripts/lib/statutory-number.ts` — 番号を作る

第0-3章の書き方を1か所にまとめたもの。**投入側と突合側で同じ関数を使う。**

| 関数 | すること |
| --- | --- |
| `statutoryNumber(spec, num)` | 出典と枝番から番号を作る。`{kind:"ordinanceTable",table:"2"}, "1552"` → `則別表第2の1552` |
| `bareNumber(official)` | 番号から枝番だけを取り出す。照合や見直しに使う |

`kind` は7種類（`lawTable` / `orderArticle` / `orderTable` / `orderTableItem` /
`orderTableColumn` / `ordinanceTable` / `plain`）。対応する書き方は第0-3章の表。

**日本の法令だけに使う。**中国・EU・米国は番号がそれ自体で一意なのでそのまま持つ。

#### `scripts/lib/law-name.ts` — 表記を直す

`toDisplayName(原文)` が第3章の決めごとをまとめて当てる。規則の全文は第10-2章。
**直すのは書式だけで、語は変えない。**

処理の順番に意味がある。

```
① 例外を当てる（applyHandFixes）
② 条文の中だけの言い回しを落とす（dropReferences）
③ 角括弧の中を片づける（中身が数字だけならピリオド）
④ 漢数字を算用数字にする（convertNumerals）
⑤ 中黒・ダッシュ・プライムをそろえる
```

③を④より先にやる。逆にすると、角括弧の中が算用数字になったあとで
中黒の判断をすることになり、位置番号と縮環位置の見分けが付かなくなる。

`convertNumerals` の判断は**うしろの文字**で決まる。

| うしろ | 扱い | 例 |
| --- | --- | --- |
| 漢字・カタカナ | 語の一部。**直さない** | `四アルキル鉛` `六価クロム` |
| ただし `以上` `以下` `パーセント` `又は` など | 数量。直す | `炭素数が八の` → `８の` |
| ひらがな・記号・英数字 | 数量か位置番号。直す | `十から` → `１０から` |

`HAND_FIXES` は、機械の読みでは直せないものだけを置く例外表。
**理由を必ず書く。**いまは λ⁵ の上付き 5 が「ラ」と「ムダ」の間に入る1件だけ。

#### `scripts/build-law-data.ts` — 投入用JSONを作り直す

条文から `scripts/data/*.json` を作る。引数なしで見比べ、`--write` で書き込み。
何が作れて何が作れないかは第11章 ②。

**特定第一種（化管法）の取り出しかたが特殊。**独立した表が無く、
令第4条第1項第1号イの括弧の中に別表第一の号番号が23個並んでいるだけなので、
`特定第一種指定化学物質（別表第一` から `に掲げる第一種指定化学物質をいう` までを切り出し、
その中の `第◯号` を拾う。

**「〜を含有する製剤その他の物」は物質として数えない。**別表の最後の号は
たいてい裾切値の定めで、数に入れると1件多くなる。

### 12-3. 閾値を入れる

#### `scripts/lib/law-threshold.ts` — 但し書きから閾値を読む

毒劇法の但し書きは、ほとんどが
「ただし、**〈物質名〉〈濃度〉％以下**を含有するものを除く。」の形。
**その数字が判定の境目そのものなのに、文章の中にしか無い。**

`parseExclusion(note)` が5つに分ける。

| `kind` | 形 | 埋めるか |
| --- | --- | --- |
| `simple` | 濃度だけが条件 | **埋める** |
| `microcapsule` | 「マイクロカプセル製剤にあつては、〈別の値〉％」が付く | 埋める（主の値。別の値は `note` へ） |
| `conditional` | 濃度のほかに条件が付く（徐放性・着色・容器など） | 埋める（`【条件つき除外】` を付ける） |
| `list` | 「次に掲げるものを除く」＋列挙 | **埋めない** |
| `none` | 濃度の但し書きが無い | － |

読み取りの決まり。

- 漢数字は**1文字＝1桁**で読む（`〇・一` → 0.1、`四七・五` → 47.5）。
  **位取り（十・百・千）が出たら `null` を返して止める。**
  1文字ずつ読む方式では正しく扱えないので、黙って別の数にするより気づける形にする
- 名指しの手前に条件が前置きされることがある
  （`容量一リツトル以下の容器に収められたものであつて、亜セレン酸〇・…％以下を…`）。
  **`であつて、` で切って条件のほうへ回す。**そのまま名前として扱うと突合に失敗する
- 名前の末尾の `として` は濃度の言い回しで、名前の一部ではない

`sameSubstance` は、法文の名前と但し書きの名指しを突き合わせる。
法文は「〜及びこれを含有する製剤」、但し書きは物質そのものを指すので、
`normalizeName` で**実際に見つかった揺れだけ**を落としてから比べる
（括弧の字 `〔〕`/`［］`、`又は`/`及び`、末尾の定型句）。
**削りすぎると別の物質を同じと見なす。**

#### `scripts/seed-dokugeki-thresholds.ts`

上の読み取りを当てて、判定に使う欄へ入れる。既定は下見、`--write` で書き込み。

```
「〇・一％以下を除く」→ 下限 0.1（超える）〜 上限 100（含む）
```

**「以下を除く」なので境目そのものは該当しない。だから下限は EXCLUSIVE。**

埋めないもの。

- 但し書きが名指しする物質が、その法文物質名と違うもの
- 「次に掲げるものを除く」で別の物質が並ぶもの

どちらも1つの閾値では表せない。**間違った数字を入れるより入れないほうがよい。**
入れなければ「全部該当」の側に倒れるので、見落としにはならない。
埋めなかったものには `note` に `【閾値未設定】`、条件つきで埋めたものには
`【条件つき除外】` を付けて、あとから探せるようにする。

**既に人が手で入れたものは触らない**（下限が0でない、または上限が100でないもの）。

#### `scripts/seed-category-notes.ts`

規制区分の `note` に**その区分がどの条文で決まるか**を入れる。
中身は第8章の表と同じ。**片方だけ直さない。**

### 12-4. まとめかたを決める — `scripts/seed-aggregation.ts`

法令の閾値は「**その法文物質名として**何％含まれているか」に対して定められている。
1つの法文物質名に複数のCASが紐づくのは普通で（6,026件中3,484件）、
合計しないと**該当を見落とす**。

```
鉛 0.06％ ＋ 酸化鉛 0.06％
  CASごとに見れば、どちらも 0.1％ に届かず「非該当」
  合計すれば 0.12％ で「該当」
```

金属などの「〇〇及びその化合物」は、**その元素として**何％かが基準になる。
単純に足すのではなく、金属換算係数を掛けてから足す（`ELEMENT`）。

```
酸化鉛 0.06％ は、鉛としては 0.056％（鉛含有率 92.83％）
```

判定のしかた。

1. 名前に `化合物` を含むか。含まなければ `SUM`（そのまま合算）
2. 含んでも、`炭素` `水素` `酸素` `窒素` `硫黄` で始まるものは `SUM`。
   **有機化合物の総称は、元素の含有率で測るものではない**
3. 元素マスタの日本語名で先頭一致を見る。**長い名前から先に**
   （「アンチモン」が「アン…」で切れないように）
4. 拾えなければ、法文の書きかたの表（`ALIAS`）で補う

`ALIAS` は、法文と元素マスタで字が違うものを埋める表。

```
砒素 / ひ素 → As      弗素 / ふっ素 → F      すず → Sn
ほう素 / 硼素 → B     ニツケル → Ni
（六価|三価）?クロム → Cr     （無機|有機）?マンガン → Mn     （可溶性）?ウラン → U
```

**ここで拾えないと、元素として数えるべきものが単純合算になる**（多めに出るが正しくない）。
実際に法文へ出てきたものだけを並べる。**当て推量で広げると別物を拾う。**

元素記号は法文物質名の欄に書き込む。**書き込むのはここだけ**で、判定はその欄だけを見る
（名前を毎回読み直すと、判定のたびに結果が変わりうる）。

### 12-6. LOLI から CASリンクを取る

#### `scripts/loli-dump.sh` と `scripts/sql/loli-xml-cas.sql`

社内SQL Serverから「鍵 → CAS」を取り出して `scripts/data/loli-*.tsv` に落とす。
接続情報は `.env.loli`（**gitに載せない**）。

**取り出し元は `ListData.XML`**（第4章 4-0）。`Data` 欄の文章から切り出す作りは
2026-08-26 にやめた。理由は 4-2c。

SQLの雛形は1つだけ。差し替えるのは3か所。

| 印 | 何を入れるか |
| --- | --- |
| `{LIST_ID}` | 一覧ID |
| `{KEYEXPR}` | 鍵を作る式。`row` を `r` として `r.value('(code)[1]','varchar(200)')` の形で書く |
| `{FILTER}` | 絞り込み。要らなければ空 |

呼び出しは `dump <出力名> <ListID> <鍵の式> [絞り込み]`。

```
dump loli-prtr-c1     9013 "$NOTE"
dump loli-pdsca-tox   1015 "REPLACE($CODE,'Order Article ','')" "AND $CAT='Poisonous' AND $CODE LIKE 'Order Article%'"
dump loli-isha-spec1  2226 "$CODE" "AND $GRP = 'Group 1'"
dump loli-scca        4021 "$REFNO"
```

`dump_key <出力名> <DataKeyType>` は **`CasKeys`（物質側の別名の番号）から取る**。
一覧に番号が入っていない EU CLP附属書VI で使う（第4章 4-2d）。
雛形は `scripts/sql/loli-caskey.sql`。

`$CODE` `$REFNO` `$VALUE` `$NOTE` `$TYPE` `$CAT` `$GRP` `$ADD` `$PARENT` は
`V()` が組み立てる短縮形。どの一覧でどれを使うかは第4章 4-2 の表。

書くときの注意。

- **式は1行で書く。**改行を挟むと途中で切れて構文エラーになる（実際に起きた）
- **`SET QUOTED_IDENTIFIER ON` を外さない。**XML のメソッドが使えず落ちる
- 出力は `tr -d '\r'` で改行を直し、2列でない行と見出し行を落とす
- **0件でも止めない。**「一覧の書き方が変わった合図」として画面に出す。
  `set -e` で止めると、後ろの取り出しが全部飛ぶ

`CROSS APPLY ... nodes('/root/row')` で **`row` ごとに1行**に開く。
1つのCASが同じ一覧の複数の号に載ることがあり、行にしないと片方しか取れない。

#### `scripts/seed-cas-links.ts`

TSVを読んで `statutory_cas_links` に入れる。**突合の鍵は名前ではなく番号**（第4章 4-2）。

区分ごとの仕事を `JOBS` に並べる。1件が持つもの。

| 欄 | 意味 |
| --- | --- |
| `law` / `category` | こちら側の法令コードと区分コード |
| `tsv` | 読む取り出し |
| `matchBy` | `number`（番号）か `gazette`（官報公示整理番号。備考から拾う） |
| `strip` | LOLI 側の鍵から落とす前置き。合わない行は飛ばす |
| `head` | 最初の区切りまでを鍵にする（化兵法の `01-001` 対策） |
| `unpad` | 0埋めを外す |
| `spec` | **こちらの番号の作り方**（`statutoryNumber` に渡す） |

鍵の組み立ては `toKeys`。カンマ区切りで**1つの欄から複数の鍵**を返す
（有機溶剤の `49, 51`）。手順は第4章 4-3。

**同じ区分に取り出しが複数あることがある。**

```
JP-PDSCA TOX   … 指定令（loli-pdsca-tox）と法別表（loli-pdsca-tox-l）
JP-ISHA  LABEL … 則別表第2・令別表第9・令別表第3第1号 の3本
JP-ISHA  SPEC_MGMT … 第1類ぶんと第2類ぶんの2本
```

同じ版・同じデータソース・同じ区分への取り込みは**入れ替え**だが、
**2本目からは消さずに足す**（`append`）。消すと最後の1本しか残らない。

版と区分は引数で絞れる。データソースは `LOLI` 固定。

```bash
node --env-file=.env node_modules/tsx/dist/cli.mjs scripts/seed-cas-links.ts 2026Q3 LABEL
```

**出力を必ず読む。**区分ごとに「結び付いた法文物質名の数 / 全体」と
「合わなかった番号」が出る。10種以下なら中身も出る。

以前は有機溶剤だけ**名前で**引いていた（`runOrganicSolvents` と
`scripts/data/isha-org-map.tsv`）。`XML` の `refno` に号番号があると分かったので
2026-08-26 に廃止した。**名前での突合はもうどこにも無い。**

#### `scripts/seed-substances-from-links.ts`

リンクに出てきたCASを物質マスタに揃える。**これを飛ばすと、
画面にCAS番号だけが並んで何なのか分からず、組成から判定するときの相手もいない。**

名前は3つの資料を順に見る（`scripts/sql/cas-names.sql` で取り出す）。

```
1. CAJ   … 自社のデータベース。社内の呼び方にいちばん近い
2. CHRIP … NITE の化学物質総合情報提供システム
3. LOLI  … CasSyns の日本語（LangID=21）
```

どれにも日本語名が無いものは、**英語名を日本語名の欄にも入れる**
（日本語名は必須。空にすると一覧で名前が消える）。既にあるCASには触らない。

**インベントリの取り込みでは流さない**（第11章 ⑦）。

取り出しは **`scripts/loli-dump-names.sh`**。ここが要点。

```bash
sqlcmd ... -u -i scripts/sql/cas-names.sql -o .cache/cas-names.u16
iconv -f UTF-16LE -t UTF-8 .cache/cas-names.u16 | sed '1s/^ï»¿//' | tr -d '
' ...
```

- **`-u` を外さない。**付けないと sqlcmd がコンソールの文字コード（Shift-JIS）で
  書き出し、日本語名が全部化ける。2026-08-27 に 7,902件を壊した
- **BOM を落とす。**残すと先頭の1行が数字で始まらず、まるごと消える
- **`scripts/sql/*.sql` は CRLF で保存する。**LF だけにすると、日本語のコメントの
  最後のバイトが次の改行を飲み込み、コメントが次の行まで伸びて構文エラーになる
- 画面に「化けが N行」と出たら、`-u` が効いていない

**対象の一覧を増やし忘れない。**`cas-names.sql` の `ListID IN (...)` に、
取り込みに使う一覧を全部並べる。忘れると、新しく結んだCASに名前が付かず、
画面にCAS番号だけが並ぶ。**EU CLP附属書VI だけ一覧ではなく `CasKeys` から引く**ので
`UNION` で足してある。

名前を引くSQLは2つある。**取り出す一覧が違うだけで、名前の取りかたは同じ。**

| SQL | 対象 |
| --- | --- |
| `scripts/sql/cas-names.sql` | 日本の法令のリンクに出てくるCAS |
| `scripts/sql/cas-names-china.sql` | 中国の目録に出てくるCAS（34,782件中30,668件に日本語名が付いた） |

**中国語名は使わない。**この画面の利用者は日本語で読むので、
日本語が無ければ英語を入れる（中国語を入れても読めない）。

`scripts/sql/loli-cas-names.sql` は、同じことを LOLI 単体でやる版。
リンクの取り出しは**「鍵とCAS」だけ**にして、名前はここで別に引く。
名前を各ファイルに混ぜると、同じ名前が何度も並んでファイルが太る。
**取り込みに使う一覧に出てくるCASだけに絞る**（全部だと65万件になる）。

### 12-7. インベントリ

#### `packages/shared/src/extract-rule.ts` — 取り出しの決まり

資料ごとに読み方を書くと、資料が増えるたびにコードが増える。

| 欄 | 意味 |
| --- | --- |
| `pattern` | 行のどこを拾うか。**全件一致**なので1行から複数取れる |

#### `scripts/seed-inventories.ts`

### 12-8. 中国

#### `scripts/china-fetch.sh` — 原文を落とす

官庁のサイトから目録の原文を落とし、`.cache/china/` に置く。
2回目からはそこを読むので、繋がらなくても動く。URL は第2章 2-4。

**この2つを外すと取れない。**

```
--compressed        ページは gzip で返る
-A "Mozilla/5.0"    User-Agent が無いと 403 を返すサイトがある
```

危険化学品目録は**旧形式の .doc（OLE2・4MB・118ページ）**なので、
LibreOffice で HTML にしてから表を読む。

**PDF は `pdftotext` を使わない。**`scripts/lib/pdf-rows.ts` が座標で読む（次項）。

#### `scripts/lib/pdf-rows.ts` — PDF を「行 × 欄」で読む

`pdftotext -layout` は**縦位置がそろっていない表を組み直せない**。
優先控制化学品名録（第二批）では **CAS の欄が1行ずれて**出た。

```
pdftotext -layout                     座標で読む（正しい）
  （空行）        75-35-4              PC023  1,1-二氯乙烯  75-35-4
  PC023 1,1-二氯乙烯  78-87-5           PC024  1,2-二氯丙烷  78-87-5
```

`readPdfRows(path)` が **y座標で行にまとめ、x座標を残す**。
欄の切り分けは呼ぶ側が `column(row, from, to)` で決める（表ごとに欄の位置が違う）。

y のゆらぎを吸収する幅は 8。**3 では結合セルの中で1行が割れた。**

#### `scripts/build-china-data.ts` — 原文から `scripts/data/china.json` を作る

目録ごとに読み方が違う。**件数が公布値と合うかで確かめる。**

| 目録 | 形 | 読み方 | 件数 |
| --- | --- | --- | ---: |
| 危険化学品目録 | HTML の表 | 1列目が数字の行 | 2,828 |
| 劇毒化学品目録 | 同じ表 | **備考が `剧毒` の行**。別に取る必要が無い | 148 |
| 易製爆危険化学品名録 | HTML の表 | 序号が `1.1` の階層。番号のセルが無い行は直前にぶら下げる | 74 |
| 重点管控新汚染物清单 | HTML の表 | 番号は漢数字。**`十四` の下に10物質**がぶら下がる（`十四-1`…） | 23 |
| 優先管理化学品名録 第1次 | HTML の表 | 編号 `PCxxx` の行 | 22 |
| 優先管理化学品名録 第2次 | PDF | **座標で読む**（下記） | 18 |
| 中国厳格制限有毒化学品名録 | PDF | **9件だけ手で書く**（下記） | 9 |

**優先管理化学品名録（第二批）の読み方。**

```
x=142 … 序号ごとの項目          多环芳烃类物质，包括：
x=163 … その下にぶら下がる物質    苯并[a]蒽 / 苯并[a]菲 / …
```

序号（`PC028`）は結合セルの**まん中**に来るので、行の並びだけでは決まらない。
**左端の位置で項目の切れ目を見る。**

CAS だけの行は、結合セルが品名の行をまたぐため**上にも下にも伸びる**
（PC038 は上に2行・下に2行）。**直前の項目に付ける。間に切れ目
（CAS も品名も無い行）があれば、直後の項目に付ける。**

確かめ方は2つ。**序号が `PC023` から連番で並ぶこと**（崩れたら例外を投げる）と、
**18品目すべての原文CASが LOLI にも在ること**（18/18 で一致した）。

**厳格制限名録だけは手で書く。**PDF のセル結合が激しく、
1つの序号に品名が何行も分かれて入るため（`全氟辛基` `磺酸及其` `盐类和全` …）、
機械で読むと語が割れる。9件しかないので PDF を読んで書き写した。

**`fixHazNumbers` — 危険化学品目録の序号の誤植を直す。**

原文には「番号が1つ飛んで、次の番号が2回出る」箇所が3つある（717・1951・2008）。
並び順は正しいので、抜けている番号がそのまま入る。

直すのは**「直前の番号+1 が目録のどこにも無く、かつ印字された番号が他の行と重なる」**
ものだけ。条件を満たさないずれは触らない（本当に欠番のことがあるため）。
3か所とも LOLI と突き合わせて確かめてある。中身は `docs/LOLIデータの気づき.md`。

**NFKC をかけない。**`[含量＞20%]` の `＞` が半角になり、原文と変わる（第8章 8-6）。
BMP の外の文字が混じっていないかも見る。混じっていれば取り出しがどこかで壊れている。

#### `scripts/loli-dump-china.sh` — LOLI から取り出す

日本の `loli-dump.sh` と同じ作りで、**取り出し元は `ListData.XML`**（第4章 4-0）。
2種類のものを落とす。

| 出力 | 中身 | 使う先 |
| --- | --- | --- |
| `china-<区分>.tsv` | **鍵とCAS**（序号、または総称の親） | `seed-china-links.ts` |
| `china-<ListID>.tsv` | `Cas` と `Data` をそのまま | `seed-china.ts`（受け皿づくり） |

**7つの一覧に序号がある。**残る易制毒（2171）と监控（988）だけ、
総称の親（`As … [鍵]`）を鍵にする。

```
1945 剧毒化学品      refno = 0649       2579 危险化学品      refno = 1546
5380 易制爆         refno = 7.11       7583 优先控制（一批）  refno = PC001
8535 优先控制（二批） refno = PC023      9637 重点管控新污染物  refno = 01
3683 严格限制        refno = 1-01
```

**総称の親は、一番うしろの `[` から `]` まで。**名前の中にも角括弧が出てくる
（`As 1-(methylamino)ethyl … [RR-…]`）ので、最初の `[` から切ると壊れる。
角括弧が無い行は行のCAS自身を鍵にする（1項目1CAS）。

#### `scripts/seed-china.ts` — 受け皿を作る

法令・区分・分類を作り、**原文をまだ取れていない易製毒と監控の法文物質名**を
LOLI から作る。読むのは `china-<ListID>.tsv`（`Cas` と `Data`）。

**何度流しても結果は同じ。**既にあるものは書き換えず、無いものだけ足す。

#### `scripts/lib/china-list.ts` — `Data` を読む

`parseChinaRow(cas, data)` が受け皿づくり用に `Data` を読む。

```
"Present ([0486])" As Brucine [357-57-3]
 ~~~~~~~~~~~~~~~~     ~~~~~~~  ~~~~~~~~~
 状態と番号            代表の名前 代表の鍵
```

**突合には使わない。**`Data` は複数の行を `;` でつないだ文章なので、
1つのCASが複数の号に載っていると先頭しか読めない（9一覧で1,604行が落ちていた）。
突合は `XML` から（第4章 4-2c）。

#### `scripts/seed-china-laws.ts` — 原文の法文物質名を入れる

`china.json` を読んで、7区分の法文物質名を入れ替える。**CASリンクは作らない。**

**区分ごとに1つのトランザクションで入れ替える。**
途中で落ちると、消したあと入れ直せていない状態が残る（実際に起きた）。

**法律が示す CAS は法文物質名の側に持つ。**中国の目録は序号が必ず入っているので、

原文をまだ取れていない区分（易製毒・監控）は触らない。

#### `scripts/seed-china-links.ts` — CASリンクを入れる

日本の `seed-cas-links.ts` と同じ考え方。区分ごとの仕事を `JOBS` に並べる。

| 欄 | 意味 |
| --- | --- |
| `category` | 規制区分のコード |
| `tsv` | 読む取り出し |
| `by` | `number`（序号）か `code`（総称の親） |
| `head` | 最初の区切りまでを鍵にする |

**厳格制限だけ `head`。**LOLI が1番（PFOS類）を13物質に割っている（`1-01`〜`1-13`）。

**重点管控新汚染物だけ番号の付け方が違う。**LOLI は `01`〜`15` の通し番号、
原文は `一`〜`十三` と「十四 已淘汰类」の下に10物質。
`01`〜`13` は漢数字に直せば当たる。**LOLI は已淘汰类を2物質しか持たない**ので、
`14` → `十四-9`（α-硫丹）、`15` → `十四-10`（多氯联苯）だけ `NEWPOL_EXTRA` に書く。

**1つの欄に序号が2つ入ることがある**（`0102, 1489`）。カンマで分けて両方に結ぶ。

#### `scripts/verify-loli-counts.ts` — 件数で読み方を確かめる

**一覧の欄を読み違えていないかを機械で見る網。**取り出しごとに3つを並べる。

```
LOLIの鍵   その取り出しにいくつの号があるか
こちら     その区分の法文物質名がいくつあるか
結び付き   実際にCASが付いた法文物質名の数
```

**鍵の数とこちらの件数が近いこと**が、欄の読み方が合っている裏づけになる。

| 印 | 意味 |
| --- | --- |
| `・` | 理由が `note` に書いてある（1つのTSVが表の一部だけ、など） |
| `??` | **理由が書かれていないずれ。その一覧の読み方を疑う**（第4章 4-1a） |

**`??` が出たまま先へ進まない。**理由が分かったら `note` に書く。
