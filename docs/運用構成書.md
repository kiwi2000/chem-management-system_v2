# 1. 標準構成

## 1.1 構成図
```
                         インターネット
                              │
                    （Tailscale VPN のみ許可）
                              │
┌─ VPS（Ubuntu 22.04+ / メモリ4GB / NVMe 100GB〜）────────────┐
│  ファイアウォール: 22(TCP,鍵認証のみ)・Tailscale以外は閉塞  │
│                                                             │
│  docker compose（compose.prod.yml）                         │
│  ┌─────────┐   ┌─────────────────────┐   ┌──────────────┐  │
│  │ caddy   │ → │ app                 │ → │ db           │  │
│  │ 80/443  │   │ Next.js + LibreOffice│  │ PostgreSQL16 │  │
│  │ (HTTPS) │   │ (PDF変換同梱)        │  │ ポート非公開  │  │
│  └─────────┘   └─────────────────────┘   └──────┬───────┘  │
│                                          volume: db-data   │
│  cron: scripts/backup-db.sh（毎日 pg_dump→gzip→世代管理）  │
└─────────────────────────────────────────────────────────────┘
        │ 外向きHTTPSのみ                    │
        ▼                                    ▼
   supabase.co（認証のみ）           オフサイト保管（rclone→B2等・推奨）
```

## 1.2 コスト目安（2026年時点の一般的な水準）

|---|---|
| VPS（4GB/NVMe 100GB級） | 約800〜2,000円 |
| Tailscale（VPN） | 無料（小規模枠） |
| Supabase（認証のみ） | 無料枠内 |
| オフサイトバックアップ（B2等・〜50GB） | 数十〜数百円 |
| **合計** | **約1,000〜2,500円** |

## 1.3 ファイル構成（リポジトリ側）
| ファイル | 役割 |
|---|---|
| `Dockerfile` | アプリ本番イメージ（Node 22 + LibreOffice + 日本語フォント。起動時に `prisma migrate deploy` を自動実行） |
| `compose.prod.yml` | 本番サービス定義（caddy/app/db。db・appはポート非公開） |
| `deploy/Caddyfile` | HTTPS設定（既定=VPN内運用の内部CA。公開ドメイン用の記載例あり） |
| `.env.prod.example` | 本番環境変数のテンプレート（`.env.prod` にコピーして使用・コミット禁止） |
| `scripts/backup-db.sh` | 日次バックアップ（cron用・復元例をコメント記載） |

# 2. 初回セットアップ手順（VPS）

```bash
# 1) OS初期設定（Ubuntuの例）
sudo apt update && sudo apt -y upgrade
sudo apt -y install unattended-upgrades          # セキュリティ自動更新
# SSH: 鍵認証のみ・パスワード認証無効化（/etc/ssh/sshd_config → PasswordAuthentication no）

# 2) Docker
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # 再ログイン

# 3) Tailscale（VPN）
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up               # 表示URLで自社アカウントに紐づけ

# 4) ファイアウォール（Tailscale外から80/443を閉じる）
sudo ufw allow in on tailscale0
sudo ufw allow 22/tcp
sudo ufw enable

# 5) アプリ配置
sudo mkdir -p /opt/chem && sudo chown $USER /opt/chem
git clone <リポジトリURL> /opt/chem && cd /opt/chem
cp .env.prod.example .env.prod
vi .env.prod                    # DB_PASSWORD を必ず強力な値に（openssl rand -base64 24）

# 6) 起動（マイグレーションは起動時に自動適用）
docker compose -f compose.prod.yml --env-file .env.prod up -d --build

# 7) 初期データ投入（初回のみ・冪等）
docker compose -f compose.prod.yml --env-file .env.prod exec app npx prisma db seed

# 8) 管理者アカウントの作成とパスワード発行（自前認証）
#    まずDBに管理者ユーザーを1件作る（最初の1人のみCLIで作成）
docker compose -f compose.prod.yml --env-file .env.prod exec db \
  psql -U chem -d chem -c "INSERT INTO users (id,email,role,can_edit,active_flag,created_at,updated_at) \
  VALUES (gen_random_uuid()::text,'admin@example.com','SYSTEM_ADMIN',true,true,now(),now());"
#    パスワードを発行（12文字以上）。以降のユーザー追加は管理画面から行える
docker compose -f compose.prod.yml --env-file .env.prod exec app \
  npx tsx scripts/set-password.ts admin@example.com 'ここに強いパスワード'

# 8) バックアップcron登録
chmod +x scripts/backup-db.sh
crontab -e   # → 0 3 * * * /opt/chem/scripts/backup-db.sh >> /var/log/chem-backup.log 2>&1
```

動作確認: 社員PCでTailscaleに接続し `https://<VPSのTailscale名またはIP>/` を開く→ログイン。
（内部CA証明書の警告を消すには deploy/Caddyfile 冒頭のコメント記載の手順でルート証明書を配布）

# 3. 更新手順（アプリのバージョンアップ）
```bash
cd /opt/chem
git pull
docker compose -f compose.prod.yml --env-file .env.prod up -d --build   # 1〜3分
# 問題があれば直前コミットに戻して再実行（git checkout <前のタグ> → up -d --build）
```

# 4. バックアップ／復元

- **取得**: cronで毎日 `scripts/backup-db.sh`（pg_dump→gzip、既定14世代保持、`BACKUP_DIR`=/var/backups/chem）
- **オフサイト**: スクリプト末尾のrclone行を有効化し、B2/R2等へ毎日コピー（強く推奨）
- **復元**:
```bash
gunzip -c /var/backups/chem/chem_YYYYMMDD_HHMMSS.sql.gz | \
  docker compose -f compose.prod.yml --env-file .env.prod exec -T db psql -U chem chem
```
- サーバー全損時: 新VPSで§2の手順→最後に上記復元（所要目安30分〜1時間）

# 5. セキュリティ対策一覧

| 脅威 | 対策 | 実装場所 |
|---|---|---|
| アカウント乗っ取り | VPN限定公開（ログイン画面に外部から到達不可） | Tailscale＋ufw |
| 〃 | パスワードは Argon2id ハッシュ（平文保存なし） | 自前認証（実装済み） |
| 〃 | ログイン失敗5回で15分ロックアウト | 自前認証（実装済み） |
| 〃 | セッションはhttpOnly Cookie＋DB側でハッシュ保管・12時間で失効 | 自前認証（実装済み） |
| 〃 | MFA（TOTP・認証アプリ対応） | 自前実装済み（設定UIは拡張予定） |
| 〃 | パスワード変更・権限変更・無効化で全セッション即失効 | 自前認証（実装済み） |
| **外部への情報流出** | **認証を含め外部サービスへの通信ゼロ（完全閉域）** | 2026-07-30 Supabase廃止 |
| データ抜き取り | DBポート非公開（アプリ経由のみ） | compose.prod.yml |
| 〃 | 全APIのサーバー側認可・組成マスキング・監査ログ | 実装済み |
| 〃 | HTTPS（VPN内でも暗号化） | Caddy |
| 〃 | バックアップの世代管理＋オフサイト | backup-db.sh |
| サーバー侵害 | SSH鍵認証のみ・自動セキュリティ更新・最小ポート | §2手順 |
| 秘密情報漏洩 | .env.prod はコミット禁止・イメージにも含めない | .gitignore/.dockerignore |

# 6. 制約・注意
- **完全閉域で動作する**（認証も自前実装のため、外部サービスへの通信は一切不要）。VPSからインターネットへの外向き通信は、OSのセキュリティ更新とバックアップ転送のみ
- 初回セットアップ時、管理者のパスワードは**サーバ上でCLIから発行**する（§2手順7）
- メモリ2GB以下のVPSではビルド時にスワップ追加を推奨（実行時は4GBで余裕）
